# VexusMemo-Lite：读、写、搜一体化的原生记忆数据库

> **SQLite 权威事实层 × TDB 2-bit 冲程检索 × AGS 统一背景场 × Spike 有界传播与请求级动态虫洞 × RiverMemo 共享预算双场投影与统一泛函**
>
> 更新日期：2026-10-29。本文说明当前数据库实现：原空间重正交化 AGS 统一几何、图内残差与尾残差路由、双场投影预算、请求级向量复用，以及完整四项基线评分、边缘稀疏场景的条件式排序修正和原生并发双排与事实存储、检索的协作方式。

Vexus-Lite 已不只是一个“由 JavaScript 调用的向量索引”。它是 VCPToolBox 的嵌入式原生知识与记忆数据引擎：从事实事务、向量路由、几何预计算、传播观测，到候选精排和结果回填，在同一个 Rust 原生模块中协作完成。

**但数据库的意义，不只是让 Agent 在需要时“查到一条资料”，而是让过去的经验在当下理解与回答形成之前，就成为可被唤起的背景。** LightMemo 提供主动回忆渠道；更核心的 RAGDiary 被动渠道，则把这个内核接入 Agent 的日常对话，使记忆成为持续随语境浮现的经验河流，参与直觉、联想与逻辑的构成。

**它快，不是因为把全部计算都近似掉了；它准，也不是因为对全库做昂贵的精确推理。它把近似用在寻找候选，把原始精度留给数学与裁决，把长期不变的结构预计算，把请求内重复的工作合并复用。**

### 先理解它服务于什么：主动回忆与被动记忆背景

| 渠道 | 触发方式 | 在 Agent 记忆中的角色 |
| :-- | :-- | :-- |
| **RAGDiary：被动渠道，核心背景入口** | 消息预处理阶段，根据已配置的记忆占位符、当前对话语义和门控条件唤起记忆，在模型生成回答前注入上下文 | 不必先决定“我要搜索”；让相关经历、关系与叙事连续性先进入理解过程 |
| **LightMemo：主动渠道，显式回忆入口** | Agent 显式调用工具，提供查询与检索范围 | 当 Agent 意识到信息缺口时，定向追查、核实或补充记忆 |

**主动渠道回答“我想起要去查什么”；被动渠道决定“在我开始回答时，哪些过去已经在场”。** 两者不是两套互不相干的记忆库，也不是数据库快慢路径的别名，而是同一记忆内核进入 Agent 认知上下文的两种方式。

这里所说的“所有 Agent 的记忆背景”是系统层的定位：不同 Agent 可以通过各自配置接入同一套记忆基础设施，形成个人经历与共享知识的背景；**不是默认让每个 Agent 无条件读取全库**。实际唤起受占位符声明、日记本作用域和门控约束；没有相关声明的普通请求会直接跳过记忆管线。“被动”指不依赖本轮显式工具调用，不指无条件召回或后台持续推理。

入口见 [RAGDiary 消息预处理](../Plugin/RAGDiaryPlugin/RAGDiaryPlugin.js:1382) 与 [LightMemo 主动工具声明](../Plugin/LightMemo/plugin-manifest.json:68)。被动渠道如何把数据库能力变成经验背景，详见第 8 节。

## 1. 一眼看懂：五个部分，一条数据链

| 部分 | 回答的问题 | 核心职责 |
| :-- | :-- | :-- |
| SQLite 权威事实层 | 现在真正存在哪些内容与向量？ | 保存正文、原始 FP32 向量、有序 Tag 事实、版本、操作回执与派生资产元数据 |
| TDB 2-bit 冲程检索 | 从大量向量中，先看哪些候选？ | 以紧凑位码进行图导航或全局扫描，再读取原始向量精排 |
| AGS 统一背景场 | 哪些语义是重复解释，哪些是独立方向？ | 同一锚定正交化框架生成局部残差/锚增益与全局星团主题面 |
| Spike 有界传播与动态虫洞 | 本次查询实际激活了哪些关系？ | 沿共享传输图传播，以更深层残差为已有历史边提供请求级动态席位，形成带节点势与实际边流的河网 |
| RiverMemo 双场与统一泛函 | 相似、关系、正文和直接事实如何共同排序？ | 求解局部场/迁移场，在共享选点预算下投影，结合有序 Tag 曲线与相对拓扑统一裁决 |

这五部分不是五个互相同步的独立服务，而是共享事实来源、版本约束和原生执行边界的协作层。

原生导出见 [`index.js`](index.js:313)；向量与 Memo 入口见 [`lib.rs`](src/lib.rs:90)；数据库运行时入口见 [`knowledge_runtime.rs`](src/knowledge_runtime.rs)。

### 必须分清的三种“图”

- **TDB 向量导航图**：为了快速定位近邻而建立的检索结构。
- **AGS 几何参与构建的 Tag 传输图**：来自有序共现事实、语义增益与锚增益的长期背景。
- **Spike 请求级河网**：某次查询在背景图上实际产生的节点响应与边流。

向量近邻边不自动等于知识关系；背景中存在关系，也不等于当前查询真的经过了它。

## 2. 完全一体：不是把数据库、向量库和重排器串起来

传统拼装方式常把事务放在应用层，把向量放在另一套索引，把图计算放在第三套运行时，然后反复传输候选、向量和中间图。

Vexus-Lite 选择另一条路径：

1. **写入以 SQLite 事务为事实提交点。**
2. **索引是可恢复的派生路由，不是第二份数学真值。**
3. **查询在原生读事务与范围门禁下读取原始向量。**
4. **AGS 与传输资产按依赖和代际发布。**
5. **Sense、双场和拓扑读出复用同代观测。**
6. **原生联合检索不把中间候选往返搬到 JavaScript。**

这里的“深耦合”是**执行、数据所有权与一致性协议的深度协同**，不是取消模块边界，更不是宣称 SQLite 与外部派生文件共享一个跨介质 ACID 事务。

### 2.1 写路径：事务先确立事实，路由再跟随事实

存储层采用一个专用写 Actor 和有界写队列，避免多个应用线程各自争夺 SQLite 写连接。事实变化时，数据库代际及相关待恢复状态随事务提交；异常则回滚。

读侧使用连接池与 WAL 快照，避免每次计算都重新建立连接。默认读池大小为 4，并约束在 2～8；写队列容量为 128。**有界意味着过载需要等待，而不是无限堆积请求。**

实现见 [`SqliteStorageEngine`](src/storage.rs:84)、[写 Actor 初始化](src/storage.rs:289)、[事务提交与代际推进](src/storage.rs:775)、[连接配置](src/storage.rs:638)。

### 2.2 读路径：同一快照内完成候选与原始向量读取

运行时的 SQL-owned 检索要求活动读事务。TDB 负责产生候选，但最终余弦分从该事务中的 SQLite 原始向量计算；不把旧快照文件或量化重建向量冒充现行事实。

这既降低双份原始向量常驻的压力，也避免“正文已更新、精排仍读取旧向量”的隐蔽错误。

实现见 [`search_sql()`](src/retrieval_index.rs:139)、[读事务封装](src/storage.rs:160)、[原始向量批量读取](src/storage.rs:984)。

### 2.3 发布路径：可重建，不盲信文件

检索快照使用双槽代际发布：写入非活动槽的暂存文件，完成校验与持久化，再由 SQLite 记录认可的资产身份和基线。

- 文件出现不等于资产已被数据库认可。
- 发布前后检查事实代际、基线与索引修订，防止陈旧计算覆盖新状态。
- 恢复时核对模型、维度、资产身份与文件标记。
- 快照缺失或不兼容时，可以从 SQLite 原始向量重建内存路由，不必重新请求 embedding。
- 查询同步内存路由与后台 checkpoint 分离，不让每次搜索都隐式写一份磁盘快照。

实现见 [`IndexCheckpointTask`](src/index_lifecycle.rs:146)、[恢复任务](src/index_lifecycle.rs:961)、[全局 Chunk 发布](src/global_chunks.rs:225)。

**数据库保存事实；索引加速访问事实。这个关系不能倒置。**

## 3. TDB2Bit 冲程向量图：把带宽用在值得看的向量上

本文用 **TDB2Bit / 2-bit 冲程检索**统称当前 TDB 紧凑位码导航与筛选机制；代码中的核心对象包括 [`Bq2Signature`](crates/vcp-tdb-index/src/index/bq.rs:86) 与 [`CorrectedSmIndex`](crates/vcp-tdb-index/src/index/quiver/corrected_sm/dynamic.rs:560)。

“冲程”描述紧凑编码驱动的分阶段推进，不意味着所有查询都执行同一种图遍历，也不表示已实现一个独立命名的全库块跳过算法。

### 3.1 每维两位：符号与强弱

对原始向量，BQ2 使用两个位平面：

- 符号位：该维为正还是非正。
- 强弱位：该维绝对值是否超过该向量平均绝对值。

这比只保存正负号多保留了一层幅值结构。位运算与人口计数可以快速比较大量维度，不必在导航每一步读取完整 FP32 行。

紧凑 BQ2 位码载荷为：

\[
B_{\mathrm{code}}=16\left\lceil\frac d{64}\right\rceil\ \text{字节/向量}
\]

例如 768 维的两个位平面共 192 字节，而原始 FP32 行为 3072 字节：**仅位码载荷约为原始行的 1/16。**

这不是“整个数据库压缩 16 倍”的承诺：图邻接、ID、幅值元数据、对齐、增量、SQL 缓存和正文都需要额外空间。

实现见 [BQ2 编码](crates/vcp-tdb-index/src/index/bq.rs:108) 与 [紧凑双数组存储](crates/vcp-tdb-index/src/index/bq.rs:907)。

### 3.2 不止 Hamming：保留强弱幅值的导航

当前 SM 路径还保留弱幅值、强弱幅值差、重建范数等元数据，用位计数近似恢复内积与重建距离。它不是把所有导航都简化为无权 Hamming 距离。

通用维度路径采用 64 字节对齐行与独立整数计数，避免维度增长引起打包计数串位；完整原始向量只在需要精排时读取。

实现见 [`DynamicSm`](crates/vcp-tdb-index/src/index/quiver/corrected_sm/dynamic.rs:18)、[幅值编码](crates/vcp-tdb-index/src/index/quiver/corrected_sm/dynamic.rs:63)、[导航评分](crates/vcp-tdb-index/src/index/quiver/corrected_sm/dynamic.rs:815)。

### 3.3 三种规模，三种合适的工作方式

| 路径 | 当前工作方式 | 取舍 |
| :-- | :-- | :-- |
| 小规模 Tag / 日记索引 | 无图时逐行读取原始向量，以有界 Top-K 堆保留结果 | 避免小库建图成本；不是 2-bit 全局预筛 |
| 达到建图条件的 Tag / 日记索引 | QuIVer 图导航与紧凑 SM 筛选，再以原始向量精排 | 减少大范围原始向量读取；召回属于近似检索 |
| LightMemo 全局 Chunk 表 | 无图紧凑 SM 扫描，范围过滤后保留有界候选池，再批量读 SQL 原始向量 | 避免为全局 Chunk 表维护导航图；扫描成本仍随行数增长 |

TDB 当前建图阈值为 2048 个节点；具体是否已有图也受增量与维护状态影响。见 [`TdbIndex`](crates/vcp-tdb-index/src/engine.rs:12)。

**全局 Chunk 表明确是 graph-free，不应把它宣传成全库图搜索。** 其过滤扫描返回的是近似重建负平方距离，不是最终余弦分；随后才在原始向量上计算候选余弦。

实现见 [`GlobalChunks.search()`](src/global_chunks.rs:151)、[`search_flat_filtered()`](crates/vcp-tdb-index/src/index/quiver/corrected_sm/dynamic.rs:575)、[LightMemo 候选精排](src/light_memo.rs:139)。

### 3.4 为什么这一层快

- **减少数据搬运**：路由先访问紧凑编码，不在每次导航时读取完整高维行。
- **匹配硬件**：BQ2 距离按平台选择 AVX-512、AVX2、NEON 或标量路径；不同 SM 热点有自己的分发与回退，不能理解为所有函数都支持相同 SIMD。
- **改善局部性**：紧凑数组、对齐行与预取减少热点中的缓存浪费。
- **限制中间结果**：扫描与精排使用有界候选池，不先构建全库排序结果。
- **控制增量成本**：更新、墓碑与维护分开处理，避免每条写入都重建全图。

实现见 [距离分发](crates/vcp-tdb-index/src/index/bq.rs:357)、[预取](crates/vcp-tdb-index/src/index/bq.rs:1002)、[增量维护阈值](src/retrieval_index.rs:87)。

**精排分数来自原始向量，不等于候选集合必然包含全库真实 Top-K。** 图导航和紧凑预筛的召回率仍须实测。

## 4. AGS 统一背景场：一次几何，局部与全局共同使用

AGS 即 Anchored Greedy Gram-Schmidt，锚定贪心 Gram-Schmidt。它把过去分散讨论的局部解释与全局语义背景，收敛到同一正交化框架。

### 4.1 局部 Explain：保留不能被邻居解释的方向

给定单位 Tag 向量 \(t\) 与选出的局部正交基 \(b_k\)，其未解释残差范数比为：

\[
r_t=\left\|t-\sum_k\langle t,b_k\rangle b_k\right\|_2
\]

目标在读取时已单位化，因此这里是**范数比**，不是能量比。实现直接逐轴扣除目标投影后计算残差范数，不再用两个接近的能量相减；在正交与舍入误差范围内，解释能量比为 \(1-r_t^2\)。

残差经有界映射变成锚增益，参与背景传输图的虫洞判定等传播条件。其意义不是“罕见就一定正确”，而是避免一个独立语义方向被高共现邻居完全淹没。

### 4.2 全局 Span：从星团而不是孤立词建立主题面

全局背景先减去全库有效单位 Tag 向量的均值，再混合目标与共现邻居，形成带真实 Tag 标签的星团方向；随后贪心选出互补主题轴，并记录前缀覆盖率。

EPA 据此测量查询的语义解释率、熵与跨域共振，再用**全库覆盖率和随机背景**校准强度，避免“少量主题轴捕获了一点能量，就认定查询高度域内”。

同一框架的两种用途：

| 局部几何 | 全局几何 |
| :-- | :-- |
| 邻居能解释目标多少？ | 一组主题面能覆盖知识库多少？ |
| 输出残差与锚增益 | 输出均值、主题面与覆盖率 |
| 参与传输背景构建 | 参与 EPA 请求级校准 |

实现见 [`anchored_gs()`](src/memo_geometry.rs:346)、[`star_direction()`](src/memo_geometry.rs:387)、[EPA 背景校准](src/memo_pipeline.rs:237)。

### 4.3 AGS：原空间缓存投影与选择性重正交化

AGS 在原始向量坐标中构造正交基，局部解释与全局张成共享同一选轴内核。几何版本由 [算法标识](src/memo_geometry.rs:377) 定义为 unified_geometry_ags_v4_cached_reorth，主题面缓存标识为 ags-global-star-v4-cached-reorth。

对候选 \(v_i\)，令 \(u_i=(I-BB^\top)v_i\)、\(h_i=\|u_i\|_2\)，先验为 \(p_i>0\)。局部选点分数为 \(|\langle t,u_i\rangle|p_i\)，全局选点分数为 \(h_i^2p_i\)；相同分数按 Tag ID 升序决胜。选中后复用首遍投影缓存构造残差，再执行四轴分块重正交化；严重相消或缓存不可用时执行两遍逐轴 Modified Gram-Schmidt。单位化后得到新轴，局部增益为 \(|\langle t,b_k\rangle|\)，全局增益为新轴单位化前的范数；小于配置最小增益时停止。

- **增量标量与投影缓存**：维护每个候选的投影平方和、目标相关项，以及按候选连续存放的历史投影。首遍消元直接读取缓存，投影行缓冲区复用；通常成本为 \(O(Knd+K^2d+Kn)\)，辅助缓存为 \(O(nK+n)\)，其中 n 为候选数、d 为维度、K 为基数；不构造完整 Gram 矩阵。
- **选择性重正交化**：选中候选的估计剩余能量不大于原能量的 1e-3，或首遍缓存不可用时，使用两遍逐轴修正。候选评分阶段的估计剩余能量不大于原能量的 1e-8 时，直接重算原空间残差。大量候选持续近秩亏会增加重算成本，上述通常复杂度不是此路径的最坏上界。
- **数值阈值**：非有限或不大于 1e-6 的候选正交范数不入基；目标残差能量低于原能量的 1e-14 时报告零。这些阈值定义数值有效秩与归零语义，不宣称精确保留任意微小方向。
- **统一坐标归约**：单路点积与四路分块点积均从正零开始按坐标顺序累加，四路版本复用轴向量读取，不改变单个点积的加法树；分块重正交化与逐轴修正的投影时机不同，不承诺两条正交化路径逐位相同。这是可移植分块，不保证特定 SIMD/FMA 指令。
- **邻接与局部复用**：构建期邻接表过滤缺失向量，按权重降序、同权 ID 升序预排序，保留局部与星团所需邻居数的最大值，并缓存向量槽号；支持度仍对完整共现邻居求和。工作区缓存单位向量范数，语义门控所得目标相关项直接供局部几何使用；局部输出不保留基向量，内部轴仍用于重正交化。
- **显式中心化覆盖率**：每个固定分块复用一个中心化向量缓冲区，直接计算中心化范数和轴投影，不使用大能量相减的方差展开式。
- **有界构建与确定性**：SQL 每批最多 128 个 ID，构建期映射工作区按槽借用向量；局部任务并行，覆盖率按固定分块收集后串行归约，不依赖 Rayon 归约顺序。
- **原子发布**：局部残差、全局主题缓存与几何元数据在同一写事务发布；缓存命中不重写资产。

实现见 [原空间两遍逐轴重正交化](src/memo_geometry.rs:73)、[缓存投影与选择性回退](src/memo_geometry.rs:92)、[增量选轴内核](src/memo_geometry.rs:163)、[构建期工作区](src/memo_geometry.rs:439)、[统一几何发布](src/memo_geometry.rs:894)。

### 4.4 能量分解与资产一致性

单位正交基将目标分解为已解释投影与未解释残差：

\[
t=\sum_k\langle t,b_k\rangle b_k+r,\qquad
\|t\|_2^2\approx\sum_k\langle t,b_k\rangle^2+\|r\|_2^2
\]

缓存首遍投影、分块重正交化与近退化两遍逐轴回退共同控制轴间正交误差，目标残差直接在原空间计算，避免小残差中的能量相减消去。全局覆盖率使用显式中心化向量在各轴上的投影平方和，除以全库中心化总能量；有效主题面按覆盖率与增量条件截取前缀。数值有效秩和残差归零仍受上述阈值约束，浮点近同分候选的选择受实际舍入结果影响。

**资产依赖链为“统一几何 → 传输 Artifact → 运行时发布”。** 几何算法版本、模型、维度、配置与内容共同确定几何签名；传输资产依赖统一几何代际与签名，主题面和传输背景必须按依赖链保持一致。几何算法属于背景资产层，Topology V3 的候选评分、Ω 与结果协议属于请求读出层，二者使用独立版本标识。

源码变更须构建匹配的原生模块后才会生效；几何算法身份变化时，须按依赖链重建派生背景，不涉及数据库表结构迁移。

AGS 是共享背景，不是每次搜索重新训练的召回器；也不能把它的“局部/全局”误写成 RiverMemo 的“局部/迁移”。

## 5. Spike 有界传播：扩展联想，不放任噪声扩散

请求先经过 AGS 背景校准的 EPA、图内残差金字塔及核心／字面／贡献／语言／层级门控，形成带权 Tag 种子。Spike 再沿长期 Tag 传输背景传播。

金字塔在既定 Top-K 标签池内，先按当前 CSR 节点索引过滤图外标签，再读取权威向量并正交投影；图内无出边节点仍有资格，过滤不扩大池、不补位。默认边际解释能量低于原查询能量的 0.03 时拒绝该层，不发布其标签或剥离结果。存在图内有效显式核心／字面焦点时，隐式种子统一等比例缩放，使最大隐式权重不超过显式最大权重的 0.35 倍；图外显式标签不参与该基准。

实现见 [`analyze_pyramid_with_pool()`](src/memo_pipeline.rs:651)、[`gate_tags_for_graph()`](src/memo_pipeline.rs:888) 与 [`scale_implicit_seeds()`](src/memo_pipeline.rs:874)。

背景传输图的有向关系来自文件有序 Tag 共现，并结合事实压缩、枢纽校正、内联原始向量语义增益与 AGS 锚增益；不是直接把正交基当作邻接矩阵。

实现见 [`memo_artifact_builder.rs`](src/memo_artifact_builder.rs) 与 [统一查询管线](src/memo_pipeline.rs:2140)。

### 5.1 “有界”不仅是少走几跳

Spike 同时约束：

- 最大安全跳数与动量；
- 每节点保留的邻居数量；
- 发放阈值与最小注入电流；
- 普通边与虫洞边的衰减；
- 前驱敏感的立即回流抑制；
- 每轮保留的传播状态数；
- 可选逐跳转移记录的硬上限；
- 动态虫洞在原邻居名额内的保留席位，以及请求内不同目标的评估预算。

Rust 默认配置包括最大 4 跳、每节点 20 个邻居、传播状态保留上限 2000；生产调用可以覆盖这些默认值。状态上限约束每轮保留集合，并非保证临时生成容器永远不超过该数；输出节点/边的默认值 0 表示不额外截断。

实现见 [`SenseConfig`](src/memo_sensing.rs:49)、[`sense_typed()`](src/memo_sensing.rs:226)。

### 5.2 软非回溯与有限时域

立即返回前驱的流量被衰减，而不是完全禁止。这样既抑制两点循环反复“自证”，也保留真实双向关系。

各跳使用归一化有限时域权重：

\[
a_h=\frac{\gamma^h}{\sum_{r=0}^{H}\gamma^r},
\qquad E_i=\sum_{h=0}^{H}a_h e_i^{(h)}
\]

虫洞降低动量消耗，但仍受跳数、传输预算及其他约束，不是无限跳跃许可。

### 5.3 一次传播，同时得到两份证据

- **节点势**：哪些 Tag 获得响应，响应有多强。
- **实际边流**：本次查询真正沿哪些方向传递了信息。

河网不是整张背景图的复制。后续拓扑读出关注的是本次实际流，而不只是静态共现。

这让传播既是召回增强过程，也是可诊断的观测过程：可查看到达节点、活跃边、回流抑制量、状态截断与耗时。传播截断或逐跳记录截断时，不能宣称拥有完整逻辑链。

### 5.4 请求级动态虫洞：让较弱历史边获得语境相关的通行机会

静态背景决定“历史上有哪些路”，动态虫洞决定“本次语境下，哪些已有路值得优先尝试”。它**不新增历史边，不写回图资产，也不要求重建图**。

动态虫洞开启时，金字塔只保留各**已接受层**投影前的残差；至少接受一层，且最后已接受层的尾残差能量有限、大于 1e-12、占原查询能量至少 0.02 时，追加该尾残差作为最后一个路由输入。接受 L 层时，路由输入因此为 L 或 L+1 个；关闭动态虫洞时不保存路由残差。后续层被拒绝时，不采用被拒层的剥离结果。

种子以首次出现层级为来源层，传播时继承它；只有索引比来源层更深的残差可以支持动态共鸣。因此，**单层分析和最后已接受层的种子也可能由追加尾残差获得动态支持资格**，但仍须通过真实边、共鸣、电流和预算门槛，不保证实际注入。尾残差不新增标签层、种子层或解释能量。合并状态保留最早来源层级，这是来源策略，不是完整多源血缘跟踪。实现见 [尾残差追加](src/memo_pipeline.rs:761) 与 [路由残差诊断](src/memo_pipeline.rs:1879)。

动态判定检查源节点的**完整 CSR 历史出边行**，不只看静态 Top-K；目标必须有正权重历史出边连接、达到共鸣阈值，并在考虑立即回流惩罚后达到最低注入电流。共鸣取可用后续残差与目标原始向量的最大正余弦，动态排名使用：

\[
\text{动态排名}=\text{历史导电率}\times\text{共鸣}^{4}
\]

默认最多保留 2 个动态席位，**包含在原有邻居名额内**，再按静态权重顺序补齐剩余名额；不是增加邻居总数，也不是将所有出边统一重排。静态虫洞仍沿用原有判定。

动态边不消耗动量，但电流仍按“源能量 × 历史导电率 × 虫洞衰减 × 回流惩罚”计算，没有电流保底、重新归一化或额外能量增益；源状态仍须满足发火阈值和非负动量，并受最大跳数、最低注入电流和状态保留上限约束。高共鸣不能把任意弱边变成强证据。

原生默认启用动态判定，共鸣阈值为 0.2，请求内不同目标评估预算为 4096。目标批量加载并复用请求级 FP32 向量池；各层共鸣、已有相似度和缺失向量结果在请求内复用。超出目标预算后仅跳过相应目标的动态判定，静态路径仍有效。**该预算独立于双场投影预算**：3072 维下，4096 个 FP32 向量载荷约 48 MiB，尚不含已有向量、容器和其他状态；不能用双场的 256 个选点上限估算整个请求内存。

CSR 普通传播热路径另有内存预处理：行内按权重降序、同权按目标 ID 升序排列，直接读取前 K 条正权重边；节点锚增益和显式虫洞标记使用紧凑数组，避免每个脉冲状态重复分配邻居列表和排序。数组由构建或冷加载派生，不改变持久化格式，也不将请求阈值固化进图资产；动态判定仍需检查完整历史行，不能把普通 Top-K 快路径的成本外推到动态阶段。

诊断区分动态候选、入选、成功注入和静态 Top-K 外提升，并记录目标评估、SQL 读取、点积、缓存复用及分项计时。这些是按传播状态和跳累计的事件，**不是唯一边数、语义正确率或每次查询的固定触发次数**；注入后仍可能被状态上限裁剪。

实现与配置边界见 [`memo_sensing.rs`](src/memo_sensing.rs)、[`memo_pipeline.rs`](src/memo_pipeline.rs)；完整契约、诊断及部署说明见 [`MEMO_DYNAMIC_WORMHOLES.md`](../docs/MEMO_DYNAMIC_WORMHOLES.md)。

## 6. RiverMemo：同一传输算子，双场响应，一个统一泛函

### 6.1 两个场不是两个互不相关的召回器

归一化查询源 \(S\) 与共享传输算子 \(T\) 产生：

\[
u_L=(1-\alpha_L)S+\alpha_LT(u_L)
\]

\[
u_T=(1-\alpha_T)S+\alpha_TT(u_T)
\]

- **局部场**强调源附近的稳定解释，默认 \(\alpha_L=0.15\)。
- **迁移场**允许可靠关系带来更远的响应，默认 \(\alpha_T=0.55\)。

在相应收敛条件下：

\[
u_\alpha=(1-\alpha)(I-\alpha T)^{-1}S
\]

实现并不显式求逆，而在同一个有最大迭代次数和残差判据的循环中求解双场；一个场已收敛后不继续重复更新它。

场的主解释权按累计质量保留有效支持域，默认局部 80%、迁移 90%，避免正值长尾到处产生微弱但貌似有效的路径。

实现见 [`memo_pipeline.rs`](src/memo_pipeline.rs)。

#### 双场投影：共享预算，不截断标量求解

**全图 CSR 标量迭代、有效域判定与高维向量投影是三个不同阶段。** 管线先求质量场与有效域，再选择用于高维投影的节点；默认预算 K = 256，约束的是**两场选点的去重并集，包含全部核心骨架**，不是每场各 256，更不是整个请求最多读取 256 个向量。

选点采用“种子流域内圈复用 + 共享预算动态扩展”：

1. 以本次 Spike 活跃河网为保留骨架，复用 hop-0 种子与代表来源，在真实正流量观测边上构造确定性的多源 BFS 森林；无法分配的骨架节点独立保留。不重新聚类，也不额外读取向量寻找质心。
2. 每个“流域 × 场”从自身内圈边界维护独立最短路前沿，以负对数传输率为边代价，只沿真实出边扩展。外圈节点必须有同场已选前驱，不跳过低质量桥接点直接摘取远处高峰；核心允许多个分量，不强行跨主题连通。
3. 每个“流域 × 场”通道先轮转获得最多 2 个不按收益竞争的外圈接纳机会，之后按流域重要性、近期新增归一化质量和已用机会动态分配预算，每批最多 4 个。这是受可达性、剩余预算、质量目标与工作限额约束的机会，不是每个流域保证得到 2 个不同新向量；遍历内圈不消耗外圈机会。常量与调度见 [投影限额](src/memo_projection.rs:8) 和 [通道选择](src/memo_projection.rs:216)。
4. 节点在全局只扣一次席位，但两场独立接纳、独立累计质量；另一场已读取该向量，不等于本场自动取得投影资格。核心节点两场均保留，缺失向量不做全图补位，因此路径保证针对选点支持集，不保证有效向量子集连通。

正预算小于核心骨架时显式返回预算冲突，不静默裁剪路径或突破上限。K = 0 **只取消节点数量上限**，不恢复全正支撑投影：质量目标与搜索限额仍有效，搜索最多处理 8192 个出队状态、发现 8192 个流域—场—节点状态、扫描 65536 条边；达到限额会保留已选支持集并报告截断。

各场以原有效域实际累计质量为扩展目标，允许域外桥接计入预算和投影质量，但**不改写原有效域**，候选路径解释仍消费原有效域。共享预算满后不再接纳新 ID，仍可在剩余工作限额内补全已有 ID 的独立场资格。选点交汇本身不放大质量，也不改写 Sense、Ω 或河网形态评分。

金字塔、融合、动态虫洞、双场投影及候选读出共享请求级原始 FP32 向量池。投影与候选阶段只按差集补查，SQL 每批最多 128 个 ID；候选先读取标签关系、位置和名称，不重复搬运已加载的向量 BLOB。观测持有共享池，候选读出克隆共享引用而不是复制高维载荷；跨事务读取校验数据库代际，事实变化时明确报过期观测错误。

标量保留不由 K 决定：仅过滤低于该场最大质量 1e-12 倍的数值尾流，并强制保留两场有效域并集及河网节点。这仍涉及标量裁剪语义，需要通过真实检索结果观察；**预算约束高维读取与投影，不意味着全图标量求解或整条查询变为 O(1)**。

选点实现见 [`memo_projection.rs`](src/memo_projection.rs)，读取与共享池见 [`storage.rs`](src/storage.rs)，完整预算、停止原因、质量覆盖与内存诊断见 [`MEMO_FIELD_PROJECTION_BUDGET.md`](../docs/MEMO_FIELD_PROJECTION_BUDGET.md)。

### 6.2 候选是穿过场的有序曲线

一个候选不只是“命中了哪些标签”，还拥有来自文件稳定序位的 Tag 链。RiverMemo 测量：

- 这条链是否连续经过局部场与迁移场；
- 相邻段的方向与语义是否连贯；
- 查询河网节点和边是否在候选链上获得相对对应；
- Tag 关系能否闭合回当前 chunk 正文；
- 关系是否过度依赖候选文件自身，形成循环自证。

候选路径在相邻标签与跨一个标签的 Span-1／Span-2 段中择优，跨段乘 0.7；相同端点对（含反向重复）共用一次证据容量，总机会数仍为标签数减一。路径支持要求两端同属至少一个场的有效域，且存在真实正权重全局边；有序标签来自文件序位，不自动证明正文叙事或因果顺序。

查询节点与候选标签按精确 ID 优先、语义质量其次进行双侧一对一绑定，重复标签不能多次响应；弱语义匹配按质量折算覆盖，而不是命中即记满票。图奖励采用由支流覆盖、正文闭合和节点对齐组成的支流置信度，原始全河网覆盖可靠性只作诊断及角色解释，不重复乘入奖励。

候选图读出由查询河网的 Atomic / Propositional / Narrative 连续形态权重混合，而不是凭查询文本关键词或候选内容硬切换整套图评分。实现见 [`evaluate_path()`](src/rivermemo_topology_v3.rs:1516)、[`evaluate_topology()`](src/rivermemo_topology_v3.rs:1737) 与 [`branch_confidence()`](src/rivermemo_topology_v3.rs:1710)。

这是相对拓扑匹配，不是严格图同构；当前候选 Motif 项复用边拓扑分数，不代表独立模体匹配已经完成。详见 [`RIVERMEMO_TOPOLOGY_V3.md`](../docs/RIVERMEMO_TOPOLOGY_V3.md)。

### 6.3 Ω：有结构，看起来像结构，还不够

Ω 只测量查询河网，不读取候选。它综合：

1. 是否真实激活了边；
2. 是否从源产生了新节点支持；
3. 正边流是否具有非退化分布；
4. 观测是否完整。

候选不能靠自身“看起来关系很多”来授予自己无限排序权限。在四项基线中，Ω 只门控图奖励，不门控路径或锚奖励；其几何平均采用 epsilon 底值，空图不代表 Ω 必然严格为零，没有候选结构证据时图奖励仍为零。高 Ω 表示传播可观测，不证明主题正确、实体同一或正文因果成立。条件式虫洞修正另使用 Ω 校准路线证据与权重，见第 6.5 节；这不改变基线预算。Ω 的稀疏／稠密工况不是主题资料密度，也不是该修正的直接开关。实现见 [`compute_omega()`](src/rivermemo_topology_v3.rs:2483)。

### 6.4 常规主干：完整四项基线评分

Topology V3 的常规排序主干由四项独立记账：

\[
\boxed{
S_0(c)=\operatorname{clip}_{[0,1]}
\left[B(c)+P(c)+G(c)+A(c)\right]
}
\]

| 项 | 含义 | 契约 |
| :-- | :-- | :-- |
| \(B(c)\) | 原始查询与正文余弦裁剪至 [0,1]，加有界非负场共振 | 不包含路径奖励；共振先封顶至 0.03，再乘候选标量场支持，无有效场时共振为零 |
| \(P(c)\) | 双场路径质量及标量支持形成的路径奖励 | 不乘 Ω，优先占用拓扑预算 |
| \(G(c)\) | 候选自身图分、支流置信度、方向与精度约束形成的图奖励 | 乘 Ω 的幂，并受剩余拓扑预算限制 |
| \(A(c)\) | 直接锚强度经绝对阈值平滑激活后的奖励 | 不乘 Ω，独立限额 |

路径与图共享默认上限 \(C_T=0.08\)，满足 \(P+G\le C_T\)；锚奖励默认独立上限 \(C_A=0.10\)。图奖励**不以同伴均值、条件期望或异常程度决定资格**，角色只解释证据，不分配倍率、独占上限或前沿压制。查询观测、候选身份和配置固定时，加入无关候选不改变既有候选的自身奖励；候选池截断和最终排名不受此不变性保证。

直接锚采用精确优先、双侧一对一接触，最多三个独立接触；隐式接触永久折减，纯隐式锚强度上限 0.035，低于默认激活阈值 0.05，因此默认不产生锚奖励。非原子候选被解释为直接答案，还须有真实显式精确接触及至少 0.55 的观测正文闭合；语义相似不等于显式身份。

原生结果保留基础分、场共振、路径奖励、图奖励、锚奖励及截断扣分，可按“四项合计减截断扣分”复算基线分。场共振已含在基础分中，拓扑奖励已是路径与图之和，均不可重复相加。启用条件式 RRF 时，最终融合分另行记账，截断扣分仍相对于基线计算，不能用四项之和复算融合分。见 [结果组装](src/rivermemo_topology_v3.rs:3108) 与 [RRF 明细](src/rivermemo_wormhole.rs:459)。公共接口不保证透出全部原生顶层字段或详细诊断。

原始查询分是基础分下限，不是启用 RRF 后的最终分下限，也不是名次下限；非负基线增益不保证真实排序收益。兼容配置中的条件同伴、创新系数与批级锚异常／前沿控制等不参与基线奖励，以 [已退役控制回执](src/rivermemo_topology_v3.rs:3158) 为准。

评分实现见 [`assign_v3_scores()`](src/rivermemo_topology_v3.rs:2549)、[场共振](src/rivermemo_topology_v3.rs:1716) 与 [路径奖励计算](src/rivermemo_topology_v3.rs:2929)，完整数学契约见 [`RIVERMEMO_TOPOLOGY_V3.md`](../docs/RIVERMEMO_TOPOLOGY_V3.md)。

### 6.5 边缘稀疏场景：严格门控的虫洞 RRF 回归修正

**虫洞 RRF 不是普遍情况，不是常驻全局评分因子，也不是 RiverMemo 的常规排序主干。** 它针对极端边缘稀疏知识场景：图构建已经发现了有事实支持的逻辑关联，查询传播也实际经过了这条关系，但候选正文与查询的表面语义距离较远，常规读出未能充分反映这条已发现的关联。此时才允许以严格验证的路线提供条件式排序修正，而不是要求所有查询都经过虫洞融合。

这里的“逻辑链”指图关系及其正文落地证据，不把共现直接当作形式逻辑或因果证明。“边缘稀疏”描述适用问题，**实现并不新增一个按 Ω 工况标签判定的稀疏开关**；局部河网即使显示稠密，也不代表该主题资料充分。实际触发必须通过以下约束：

1. **真实观测路线**：正电流、非自环、非即时回流的虫洞，且存在同方向正权 CSR 关系和有效目标向量；不是仅凭背景有边就参与排序。
2. **严格全局见证**：至少两个同时包含路线两端的不同文件，校验和非空且不同；两文件还须共享排除两端与全部显式焦点的第三标签，并在至少一个文件中包含另一个显式焦点。每路线最多检查 128 个文件、每文件 128 个标签，检测到超限则不放行。
3. **强度与来源**：完整请求观测、正 Ω、来源为零跳核心／字面焦点，且原始观测中的相对流量至少 0.5；过滤后不重新归一化。
4. **候选落地**：目标与候选正文正相关，且候选文件标签具有精确目标 ID 或超过默认 0.48 阈值的语义匹配，该标签与正文也必须正相关。精确 ID 在实现中按相似度 1 统一通过阈值检查。

**全局见证是图证据，不是全局排序因子。** 见证读取不受共同候选文件范围限制，但不扩大候选权限、不把见证文件补入结果，也不替代候选自身落地。不同校验和不证明见证相互独立。

每条合格路线按“相对流量 × 目标—正文正余弦 × Ω 的幂”排列具有落地资格的候选，得到从 1 开始的路线名次 \(r_e(c)\)；完整基线名次记为 \(r_0(c)\)。路线权重由原始电流相对于普通传播的解释力度确定：

\[
w_e=\frac{f_e}{f_{\mathrm{ref}}}\Omega^\gamma,\qquad
S(c)=\frac{1}{60+r_0(c)}
+\max_{e:\,c\text{ 具有落地资格}}\frac{w_e}{60+r_e(c)}
\]

参照电流是原始观测中非虫洞、非即时回流、非自环普通边的最大正电流；没有这种边时使用原始观测全部边的最大正电流。多路线取最大贡献，不叠加相关支路的票数；最终稳定排序，平分保留基线顺序。权重可以大于 1，融合分不是余弦或概率，也不占用或改写基线的拓扑、锚点预算。

**只有至少一个候选获得实际正路线贡献，才启用上述融合；否则基线分数逐位不变、排序不变。** 未触发不是功能缺失；常规、资料充分的查询由完整拓扑、直锚与 Ω 正常完成排序，不需要虫洞 RRF 来证明读出有效。

路线、门控及融合实现见 [`rivermemo_wormhole.rs`](src/rivermemo_wormhole.rs:33)，两阶段排序接入见 [基线与条件式融合](src/rivermemo_topology_v3.rs:3006)。该通道是 RiverMemo 内部的特殊修正，不是第 8 节外部 Rerank+ 与 RiverMemo 的排位融合。

## 7. 为什么可以又快、又高效、又准？

### 7.1 快：把不必要的工作从热路径拿掉

| 机制 | 省掉的工作 |
| :-- | :-- |
| 长期 AGS 几何与传输 Artifact | 每次请求重新建立语义背景和整张关系图 |
| 2-bit 路由与有界候选池 | 对所有向量执行完整高维精排 |
| 实例持有共享图快照 | 每个候选或每个阶段重新装载、复制 CSR |
| 原生观测句柄复用 | Sense、双场与拓扑阶段各自重复传播 |
| 请求级 FP32 向量池与差集补查 | 金字塔、动态共鸣、投影和候选重复读取相同向量 BLOB |
| 共享预算双场投影 | 对全部正支撑节点执行高维读取与投影；不省略全图标量求解 |
| CSR 邻接顺序与紧凑属性预处理 | 普通传播中每个脉冲状态重复分配邻居列表和排序 |
| Rust 联合候选处理 | 中间向量、候选和图反复跨越 N-API |
| Rayon 候选级并行 | 在 JavaScript 主线程逐候选执行数学计算 |
| 独立 checkpoint 调度 | 搜索时顺便序列化整库索引 |

完整观测保存在原生运行时，调用方只接收句柄、摘要和增强查询向量，见 [轻量观测返回](src/memo_pipeline.rs:1323)。

常规完整请求通常仍包含“前置观测任务 + 联合召回/排序任务”；不能将某个任务的一次跨界诊断说成整个请求永远只有一次调用。联合查询入口见 [`execute_river_query_hybrid()`](src/knowledge_runtime.rs:3945)。

### 7.2 高效：减少常驻复制，控制工作规模

- SQLite 保存权威 FP32；恢复后的生产路由释放快照原始向量与可变原始行缓存，见 [`release_originals()`](crates/vcp-tdb-index/src/engine.rs:99)。
- 几何工作区是构建期资源，不是第二套永久向量数据库。
- 小库不强制建图，大库不强制逐行 FP32 扫描，全局 Chunk 也不强制维护图。
- 批量差分减少跨界和锁获取次数；读者不会观察同一排他批次的半批状态。
- 写队列、候选池、传播保留状态、动态目标评估、投影选点和搜索工作限额各自承担资源约束；不同预算不能相互替代。
- 观测是跨原生调用的请求上下文，不是跨请求结果缓存。独立查询结束立即释放，共享作用域待内部消费者全部结束后释放；准备阶段产物校验失败也释放已创建句柄，不等待 TTL。
- 原始 ABI 直接调用者仍须显式释放；TTL 仅作漏释放兜底，并非新增的活跃请求硬过期或后台清扫器。释放观测不清除常驻 CSR，已取得共享引用的消费者仍有效，载荷在最后一份引用释放后回收。

**不是零内存、零复制或无锁。** 活动路由、元数据、CSR、查询观测、SQLite 缓存、临时向量和增量仍会占用内存；LightMemo 当前全局表还受互斥锁保护，同一表上的任务可能串行等待。

### 7.3 准：每层只拥有自己应有的解释权

准确性来自一条分工明确的证据链：

1. **事实准确**：SQL 原始向量与正文是权威，量化码不参与替代数学真值。
2. **查询更完整**：残差金字塔继续读取主方向之外的未解释部分。
3. **背景更有尺度感**：AGS 主题面以覆盖率和随机背景校准，而不是盲目提高域内置信度。
4. **联想不过度**：有界 Spike、回流抑制和动态席位共同控制扩散；动态虫洞必须依托历史边与更深层残差共鸣，不凭空造关系或增益。
5. **关系有来源**：排序读取本次实际河网，而不是把所有静态图边都算成查询证据。
6. **标签要落回正文**：路径与锚接触需要 chunk 闭合。
7. **结构奖励要有资格**：候选自身证据、支流置信度、方向与精度约束确定图请求，Ω 门控图奖励，路径与图共享有限预算；不靠同伴异常程度分配奖励。
8. **直接事实不受牵连**：弱河网不自动否定强直接锚。
9. **代际不混用**：观测句柄与 Artifact 签名、运行时代际绑定；跨事务向量差集读取也校验数据库代际，不混用旧池与新事实。
10. **投影不跳过桥梁**：河网骨架必保留，外圈沿同场前驱扩展；预算冲突和工作截断显式可见，而不是为满足上限静默破坏支持路径。

这是一套提升检索质量的机制，而不是“所有数据集准确率必然更高”的证明。Embedding 质量、Tag 事实、候选池大小与参数都会影响结果；未进入候选池的内容，后续重排通常无法挽回。

## 8. 两种记忆渠道：RAGDiary 让经验在场，LightMemo 让回忆可追问

### 8.1 RAGDiary 被动渠道：不是搜索附件，而是回答形成前的记忆背景

如果只有主动搜索，Agent 必须先意识到自己缺少哪段经历，再决定调用工具。但许多重要记忆的价值恰恰在于：**当下尚未明确提出的问题，需要由过去先提供背景，才能被看见。**

RAGDiary 将记忆唤起放在消息预处理阶段。它读取已声明的日记本入口，从最新真实用户发言、净化后的上一轮 AI 内容及可用历史上下文主题分段中组织查询；随后在指定作用域内检索、排序和整理记忆，将结果替换到消息中的占位符位置，再交给模型生成回答。Agent 不需要为这次背景唤起先输出一次工具请求。

这就是“经验河流”的工程含义：**长期经验保存在数据库中，每次对话只让与此刻有关的一部分流入上下文；语境改变，浮现的记忆也随之改变。** 不是把整本日记永久塞进提示词，也不是让一份静态摘要代替全部过去。

主链路可以概括为：

占位符声明与门控 → 当前用户 / AI 意图融合、历史主题补充 → 显式日记本作用域与候选计划 → RiverMemo 召回和结构读出 → 可选时间处理、外部精排、联想与全文展开 → 去重、格式化 → 回填消息 → 模型生成回答。

实现见 [占位符识别与无声明快速返回](../Plugin/RAGDiaryPlugin/RAGDiaryPlugin.js:1418)、[当前意图融合](../Plugin/RAGDiaryPlugin/RAGDiaryPlugin.js:1553)、[历史分段](../Plugin/RAGDiaryPlugin/RAGDiaryPlugin.js:1608) 与 [消息回填](../Plugin/RAGDiaryPlugin/RAGDiaryPlugin.js:1665)。

### 8.2 直觉、联想与逻辑：经验背景的三种作用

这些词描述记忆对 Agent 的作用，不是宣称数据库具有意识，也不是把向量分数当作逻辑证明。

| 作用 | 对 Agent 意味着什么 | 对应的工程机制 |
| :-- | :-- | :-- |
| **直觉背景** | 尚未显式搜索，相关经历与熟悉的主题已进入当前理解，使判断不必每次从零开始 | 对话语义驱动的被动唤起、AGS 长期语义背景、局部场与直接锚证据 |
| **联想展开** | 不只想起措辞最相似的一段，也能沿可靠关系接近其他经历，发现不同记忆的交会 | Spike 有界传播、迁移场、历史多向量候选；可选的跨种子联想共现发现 |
| **逻辑与叙事支撑** | 让人物、事件、前提与后续经验保持关联，给模型提供可核对的关系材料，而不是零散相似句 | 有序 Tag 曲线、查询实际边流、相对拓扑、正文闭合、时间条件与父文档展开 |

**直觉不是脱离事实的猜测，联想不是无限扩散，逻辑也不是“图上有边所以结论成立”。** 数据库负责让有来源、受范围约束的经验及关系进入上下文；最终解释与推理仍由模型完成，并应回到记忆正文核对。拓扑证据不自动构成因果证明，检索也不保证恢复完整推理链。

对所有接入的 Agent 而言，这套机制提供的是共同的记忆基础设施，而不是相同的记忆内容：各自声明的日记本和联合范围，决定各自有哪些经验在场。个人经历与共享经验可以在配置范围内共同参与回答，不必为每个 Agent 复制一套数据库。

### 8.3 被动入口的范围与可选能力

RAGDiary 的被动渠道有明确的控制面，而不是每轮无差别地执行所有能力：

- **声明决定入口**：检索式、相似度门控式与纯文本直接引入式入口承担不同职责；纯文本直接引入可走不依赖向量库和 embedding 的快速路径。
- **语境决定唤起方向**：主查询融合当前用户与 AI 意图，历史主题分段提供补充方向；这些是可配置的工程权重，不是对用户真实意图的绝对判定。
- **日记本决定候选作用域**：多个日记本可作为请求期虚拟联合索引，共享全局结果预算和后处理；联合不等于取消范围约束。
- **RiverMemo 是当前标准 RAG 管线的核心引擎**：不是只有显式添加后缀才使用；原生联合路径受运行时开关及接口可用性约束，未走联合路径时仍可将候选交给 RiverMemo 重排。
- **时间、联想、全文与总结按需启用**：时间补充维护近期连续性，联想寻找跨种子共现，全文展开恢复事件语境，AIMemo 可进一步整理记忆；它们不应被描述成每轮默认全部执行。
- **没有声明就不启动主记忆管线**：被动背景以实际配置为前提，不对未接入的 Agent 或普通无占位符请求承诺自动记忆。

实现见 [纯文本快速路径](../Plugin/RAGDiaryPlugin/RAGDiaryPlugin.js:1384)、[虚拟联合索引](../Plugin/RAGDiaryPlugin/RAGDiaryPlugin.js:2682)、[标准管线启用 RiverMemo](../Plugin/RAGDiaryPlugin/RAGDiaryPlugin.js:2936)、[原生联合路径门控](../Plugin/RAGDiaryPlugin/RAGDiaryPlugin.js:3031)、[时间连续性补充](../Plugin/RAGDiaryPlugin/RAGDiaryPlugin.js:3524) 与 [联想共现发现](../Plugin/RAGDiaryPlugin/RAGDiaryPlugin.js:3980)。

### 8.4 RAGDiary 原生多索引 / RiverMemo 联合路径

显式日记权限与候选计划 → 原生 ANN → 合并、展开、去重与投影 → 同代观测读出 → 候选级并行路径、拓扑与锚接触计算 → 查询形态、Ω、候选自身奖励及共享预算 → 完整基线排序 → 仅在严格路线与候选落地条件满足时执行虫洞 RRF 修正 → 最终结果。

权限过滤先于候选归一化和统计，显式空权限集合表示无权限。拓扑读出只处理共同候选边界内的内容，内部候选超集默认上限 300，不从全库补回池外漏召回项；该边界不等于各入口的原始 ANN 数量。实现见 [权限过滤](src/rivermemo_topology_v3.rs:2773) 与 [`select_superset()`](src/rivermemo_topology_v3.rs:1362)。

在这条被动生产链中，JavaScript 主要组织占位符、时间表达式、BM25 文件级证据及历史主题计划；启用原生联合路径后，Chunk 候选展开、向量融合、去重与拓扑排序交给 Rust，而不是逐候选搬回 JavaScript 计算。这里的候选展开也不等于后置的完整父文档读取。

实现见 [RAGDiary 原生查询计划](../Plugin/RAGDiaryPlugin/RAGDiaryPlugin.js:3031) 与 [联合查询调用](../Plugin/RAGDiaryPlugin/RAGDiaryPlugin.js:3199)。

### 原生 Rerank+：Sense 与候选召回并行，HTTP 与拓扑读出并行

新增 [原生并发入口](src/knowledge_runtime.rs:2452) 与 [HTTP / RRF 单元](src/native_rerank.rs:1)。调用方只提交查询、作用域与计划；Rust 同时启动 Sense 和 TDB 候选召回。候选就绪后，外部精排立即开始，不必等待 Sense；RiverMemo 等待 Sense 后读取同一候选域，最后在 Rust 内融合排位，仅返回有界结果。中间候选正文不再为外部精排往返 JavaScript；HTTP 等待期间不持有 SQL 事务或索引读锁。

- **适用范围**：RAGDiary 常规 Rerank+，支持联合日记本与历史霰弹枪查询。要求原生联合查询已启用且新 ABI 可用。普通 Rerank，以及 Time、BM25、TimeDecay 和共享元思考观测组合继续走既有兼容路径。LightMemo 不受此次改动影响。
- **两种外部后端**：传统 Rerank 使用既有 URL、API、Model 配置；Jev 使用既有启用标志、Provider、API URL、API KEY、Model、代理和 Choice 配置，支持 Typesafe 与 OpenRouter。实现直接读取 [插件配置位置及调用代理](../KnowledgeBaseManager.js)，不修改配置文件；进程环境优先于插件文件，修改已加载的环境配置后需重启。
- **有界网络**：传统请求每批最多25篇，按 Token 估算限制拆批，单查询并发沿用配置，全进程最多10个 HTTP 请求；连接复用，禁止重定向，响应上限4 MiB。Jev 原生路径不复用 JS 客户端的重试器，失败直接保留 RiverMemo 排名。
- **失败语义**：未配置、网络错误、无效响应、批次失败或超时，不伪造外部排位，保留 RiverMemo 排序并返回诊断。候选、Sense 与拓扑事实代际不一致时明确报错，不混用新旧数据。任一外部批次失败将放弃本次全部外部排名。
- **融合语义**：外部精排消费 TDB 小窗口，RiverMemo 消费更大的有界候选域；按 Chunk ID 对齐，缺失外部排位贡献零，平滑常数60，权重沿用 Rerank+ 参数。融合在 RiverMemo 返回域内进行，不额外引入被拓扑候选收缩排除的项目。这不是原先“RiverMemo 缩窗后再外排”的逐项等价替换。
- **配置新增项**：插件环境模板中的 NativeRerankTimeoutMs 默认30000，约束外部 HTTP 排队及全部批次总等待，不是整个数据库查询时限。RAG_SHOTGUN_HISTORY_ENABLED 默认 true；设为 false 后停止历史上下文分段多向量召回，当前查询仍正常检索。见 [配置模板](../Plugin/RAGDiaryPlugin/config.env.example)。
- **后处理边界**：最终格式化、联想、全文展开和输出去重仍沿用上层管线；输出去重可能按需读取最终少量结果的向量，并非整个请求完全没有向量跨界。

协议与融合正确性覆盖见 [原生单元测试](src/native_rerank.rs:286) 和 [代理及排序回归](../tests/nativeParallelRerank.test.js)。这些测试不构成延迟或召回质量承诺；部署前须构建匹配的 release 产物。

### 8.5 LightMemo 主动渠道：对浮现的记忆继续追问

LightMemo 让 Agent 在意识到信息缺口后，显式提出查询，指定日记本等范围及可选条件，主动核实事实、追查细节或补充被动背景没有带入的经验。**它补充被动渠道，而不是代替被动渠道成为全部记忆。**

其全局 Chunk 路径为：

原生读事务 → 同步全局紧凑表 → 日记/署名/时间等范围过滤 → 无图 SM 预筛 → SQL 原始向量余弦精排 → 有界正文回填 → 可选 RiverMemo → 最终结果。

该路径不把 Chunk 向量传给 JavaScript，也不在查询时发布快照。其可选词项证据目前是候选池内的子串词频评分，**不是独立的全局 BM25 倒排召回通道**；不要与 RAGDiary 的文件级 BM25 候选计划混为一谈。

实现见 [LightMemo 工具入口](../Plugin/LightMemo/plugin-manifest.json:68) 与 [`LightMemoTask`](src/light_memo.rs:104)。

两条渠道共享数据库事实和数学内核，不意味着候选来源、触发时机和输出组织完全相同；LightMemo 也不能越出自身预筛池凭空补回全库漏召回项。**被动渠道让经验先在场，主动渠道让 Agent 有机会继续追问；两者共同构成可唤起、可追查的长期记忆。**

嵌入模型和向量生成仍由上游提供。本模块不等于一个自带 embedding 模型、网络鉴权与多租户服务的独立数据库服务器。

### 配置与部署边界

- **双场投影预算**：持久配置位于 KnowledgeBaseManager → riverMemo → effectiveSupport → [maxProjectionNodes](../modules/knowledgeBase/memoConfig.js)，默认 256。查询顶层 [maxFieldProjectionNodes](../KnowledgeBaseManager.js) 或查询有效支持配置中的同名预算可覆盖；显式 0 不回退默认值。仅接受非负整数，不要求为 128 的倍数，拒绝负数、小数、非有限数和字符串。
- **动态虫洞配置**：原生输入路径为 config → spikeRouting，字段为 [dynamicWormholes](src/memo_sensing.rs)、[dynamicWormholeThreshold](src/memo_sensing.rs)、[dynamicWormholeSlots](src/memo_sensing.rs)、[dynamicWormholeMaxTargets](src/memo_sensing.rs)，默认依次为 true、0.2、2、4096。关闭开关、席位为 0 或目标预算为 0 均退回静态选边，阈值校验仍执行。
- **不要假设上层自动透传**：动态虫洞技术节点未修改上层配置构造或调参文件；原生支持字段不代表管理器会透传任意新增字段。通过上层覆盖前须核对 [`KnowledgeBaseManager.js`](../KnowledgeBaseManager.js)，缺省调用使用 Rust 默认值。
- 两个节点不要求数据库表结构迁移；动态虫洞不写持久化图，CSR 预处理可从旧资产冷加载派生。但源码更新不等于部署生效，必须重新构建匹配的原生产物并验证加载。Windows 部署需停止占用模块的进程、备份旧产物、核对新产物校验值后再启动；未透传动态开关时，不应把修改上层配置当成可靠的紧急关闭方式。
- **版本验证**：Topology V3 是架构名称；当前 [原生读出标识](src/rivermemo_topology_v3.rs:22) 为 rivermemo.conservative-topology-v2.5-confidence-rrf，[统一管线标识](src/memo_pipeline.rs:23) 为 memo.conservative-topology-v2.2，两者分别标识读出与观测管线，不要求编号相同。原生结果协议为 rivermemo-topology-v3-native-result-v1。停止占用模块的服务、替换对应平台产物并重启后，应核对真实查询返回的原生标识；空候选快捷返回、日志标题或公共门面的兼容常量不能证明原生模块已加载。单纯同步本文不触发编译、背景重建或数据库修改。
- 专项回归测试验证工程契约，不替代生产 release 验证、并发内存测量和真实检索质量验收；没有固定新增延迟或无损召回承诺。比较效果时须固定查询、资产、配置、权限和候选身份，并记录实际加载版本与耗时。详细步骤见 [`MEMO_DYNAMIC_WORMHOLES.md`](../docs/MEMO_DYNAMIC_WORMHOLES.md) 与 [`RIVERMEMO_TOPOLOGY_V3.md`](../docs/RIVERMEMO_TOPOLOGY_V3.md)。

## 总结

**Vexus-Lite 的核心不是某一个孤立算法，而是让每一份数据、每一次计算和每一种证据各就其位。**

SQLite 维护事实，TDB2Bit 快速寻找值得精读的位置；AGS 提供统一背景，Spike 把查询变成有界且可观测的河网，动态虫洞用更深层残差在已有历史边中争取通行机会；RiverMemo 从同一传输过程生成双场，以保留河网骨架的共享预算约束高维投影，跨阶段复用请求级 FP32 向量池，再用正文闭合、相对拓扑、Ω 与直接锚共同完成排序。标量求解、动态评估与向量投影各有边界，任何一个预算都不代表整个请求的成本上限。

在 Agent 侧，**RAGDiary 是更核心的被动记忆背景渠道**：让过往经验在回答形成前随语境浮现，参与直觉、联想与逻辑的构成；**LightMemo 是主动回忆渠道**：让 Agent 能够对信息缺口和已浮现的经验继续追问。这条经验河流不来自无限上下文，而来自事实持久化、背景结构与每次有边界的唤起。

**速度来自少搬运、少重复、少做无效精算；性能来自紧凑布局、有界工作集和原生协作；准确性来自原始精度、背景校准与受约束的证据融合。读、写、搜因此不是三个拼接功能，而是同一个记忆数据库的完整工作过程；其目的也不只是返回搜索结果，而是让接入的 Agent 拥有可持续唤起的经验背景。**
