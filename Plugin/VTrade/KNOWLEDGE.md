# VTrade 组件知识卡

## 产品流程

VTrade 是带模拟账户的本机看盘工作台。普通用户先浏览或搜索当前行情源覆盖的证券，再看图、制定计划和模拟下单。自选与自建板块只整理视图，不限制可交易范围。一次模拟账户保存虚拟资金、持仓、意图、成交、事件及按日推进的时钟。

训练是独立的历史实验流程。`CreateTrainingPair` 从固定数据集抽取同一起点，分别创建人工和 Agent 账本；盲测、种子、成绩单由训练流程管理。训练不能通过普通全市场目录读取未来行情。

对决（`core/duel*.cjs`、`frontend/duel/`）是另一条流程：一局一道历史行情题，座位每天交目标仓位，交齐后一起推进；每局一个自己的小账本，成交价、费用和涨跌停仍走 execution 插槽。成绩与 1000 个随机操作者比较百分位，经验和成就只看百分位与好的决定。

## 对决的约束

- 题目窗口只在服务端；视图只给到当前日，盲测把日期换成“前N”“第N天”，基本面不给报告期，严格盲测连基本面也不给。结束后才能揭晓。
- Agent 交决定必须带当回合的决策票据；票据只从登录后的页面接口取得，回合推进即作废。工具调用列不出票据，也不能替玩家座位决定；页面只能替玩家座位决定，超时后维持原仓位只能用于 Agent 座位。
- 随机操作者的种子由题目和设置决定，同一道题同样的决定成绩不变；战绩按局号只记一次，重复记账返回原奖励。
- 资金挑战同一时间只允许一局，资金在建局时预留；重置后进行中的那一局不再写回。

## 数据与安全约束

- 普通全市场账户用 `CreateSession` 的 `marketMode: directory`。管理员先在设置页配置本机通达信 `vipdoc` 目录。Agent 只能传模式标识，不能传路径。
- 账户创建时不固化证券名单。`GetSessionSecurities` 只列出模拟日已有日线的证券；`GetSessionQuotes`、`GetChart`、`GetAnalysis` 按模拟日截断。首次计划或下单才把证券记入账本。
- 目录账户自动读取已完成的新日线；`AdvanceDay` 才结算。目录路径指纹、历史日历或已记账证券的既往日线变化会使账户停止操作，以免静默改写交易依据。
- 固定数据集和版本化来源继续支持训练与复现实验。单份导入上限仍是 100 只证券；这个限制不适用于普通目录账户。
- 当前按日线作决策与撮合，不处理公司行动、真实委托或逐笔成交。独立的最新看盘命令没有 Agent 身份隔离，不能作为严格盲测的防作弊边界。

## 端到端验证

1. 用合成通达信目录创建普通账户，确认空账本可列出模拟日已有证券，新上市证券在该日不可见。
2. 搜索未预选的股票，读取模拟日报价与图表，预览并提交买入意图；推进一天后核对成交、持仓和现金。
3. 改写已经记账的历史日线，确认后续读写报 `SOURCE_CHANGED`，原账本文件保留。
4. 在工作台创建账户，确认表单不要求证券池，列表可显示并搜索当前行情源的证券；检查页面脚本错误。
5. 运行插件 Node 与 Python 测试；部署到 VCP 后检查独立工作台及模拟入口。
6. 对决：在本机通达信目录上单练一局到结算，核对盲测期间页面与局面文本里没有日期和名称，揭晓后复盘的买卖点与每日决定一致；用真实模型按 `invites` → `turn` → `SubmitDuelDecision` 打完一局，确认每个决定都有理由、过期票据被拒。
