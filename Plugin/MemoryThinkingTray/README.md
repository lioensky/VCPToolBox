# 记忆思维托盘（实验性）

只搬运，不检索、不解析占位符。插件启停就是唯一开关，不设内部启用配置。不修改现有日记、元思考、时间线及酒馆插件。

## 使用

将下列完整标记区放在系统提示词内（起始单词为 Start）：

```text
固定的人格、规则、工具使用原则……

<---VCP记忆思维区Start--->
[[VCP元思考:RyanThink::Group]]
这里是[小吉]的TimeLine系统：[[VCPTimeLine::小吉]]
这里是[小吉]的日记本：[[小吉日记本::Group::Time::RiverMemo]]
工具记忆：{{toolbox:MemoToolBox}}
<---VCP记忆思维区End--->

其余固定提示词……
```

工具箱名称须替换为已配置的真实别名。同一工具箱全上下文只展开一次，避免在托盘外更早重复引用。

运行顺序：

1. 酒馆注入预设，主变量管线展开 Agent、工具箱等内容。
2. 记忆思维托盘将系统消息中的标记区移除，区内正文合并为一条以 `[系统提示:]` 开头的 user 消息，插入指定深度。
3. RAG 解析日记、元思考等占位符。
4. 时间线处理器解析时间线占位符。

顺序已在根目录 [预处理器顺序配置](../../preprocessor_order.json) 中设置为托盘 → RAG → 时间线。自定义顺序时必须保留此相对顺序。工具箱在搬运前已经展开，其动态文本也会随托盘后移，不会重新执行工具箱展开或绕过去重。

## 深度配置

可将 [配置模板](config.env.example) 复制为本插件目录的私有配置文件。未配置时默认深度为 1；修改后重启服务。

| 深度 | 注入位置 |
|---|---|
| 0 | 上下文末尾 |
| 1 | 最后一条消息之前（推荐，保留真实用户问题在最后） |
| 2 | 倒数第二条消息之前 |
| 大于消息数 | 开头连续系统消息之后 |

深度按**本插件执行时的消息条数**计数，不是对话轮数。后续插件仍可能插入消息。无效/负数配置回退 1。为避免破坏原生工具调用协议，落点为工具结果时向前避让完整工具结果序列。

## 边界和回退

- 只从协议角色为 system 的消息搬运，不从普通用户、助手、工具结果或伪系统用户消息中提取标记区。
- 多个完整标记区按原消息顺序合并为一个托盘；仅搬运正文，不保留区标记。
- 任一系统消息内标记缺失、顺序错误或嵌套时，本轮全部不搬运并输出警告，避免内容丢失。
- 支持字符串、多模态文本数组及文本对象；文本数组中的标记可跨文本部分，不移动图片等非文本部分。
- 输入消息不原地修改；无标记时直接返回原数组。搬运后再次执行不会重复注入。
- 只有空白的托盘区只移除标记区，不生成空伪系统消息。
- 禁用或移除插件后，标记区内容仍留在系统消息，原有记忆解析流程照常工作。
- 工具循环内现有 RAG 刷新仅接受真实系统消息；本插件不放宽该安全边界，托盘内记忆在下一次正常请求重新解析。

## 缓存收益

目标是让托盘之前的固定提示词和历史上下文保持稳定，不保证服务商缓存命中，也不缓存模型思维内容。托盘本身及其后的前缀仍可能因刷新而失效。深度越大，动态内容出现越早，可复用前缀通常越短。

系统提示词其他位置的时间、动态工具列表、折叠内容以及后续插件改写，仍可能独立影响缓存。工具箱动态折叠计算依旧执行，本插件只改变输出位置。

### 可选的显式缓存断点

在[插件私有配置](config.env)中设置 [`MEMORY_THINKING_TRAY_CACHE_BREAKPOINT=true`](config.env.example:14)，重启服务后开启；默认关闭，设为 false 可恢复原行为。

仅在实际插入非空托盘时，向插入位置之前寻找最近一条有非空文本的用户或助手消息，在最后一个非空文本块上添加 [`cache_control`](MemoryThinkingTray.js:74) ephemeral 标记。字符串内容转换为单个文本块数组；多模态部分及已有缓存策略保留；没有合适的前置文本时跳过，不标记系统消息或托盘本身，也不原地修改输入。

这是实验性上游提示，不是本地缓存。上游必须支持并透传该字段；不支持时可能忽略或报错。已有断点数量、缓存写入费用、最低缓存长度、有效期及前缀稳定性仍需自行核对。多模态消息中的断点只覆盖到选中文本块，后续非文本块不在此断点覆盖范围内。调试日志中的 cacheIndex 为标记消息索引，-1 表示未设置。
