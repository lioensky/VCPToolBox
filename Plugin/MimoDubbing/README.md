# MiMo 字幕时间轴配音异步插件

将 AI 输入的字幕时间轴逐句合成、按原始时间放置，输出可播放和下载的 24kHz PCM16LE 单声道 WAV。没有网页或额外监听端口，不修改主服务。

## 配置与启用

1. 将 [config.env.example](config.env.example) 复制为插件同目录的 config.env，填入真实密钥。VCP 插件加载器读取配置并注入子进程；入口不自行加载之前网页项目的 .env。
2. DMXAPI 默认端点为 https://www.dmxapi.cn/v1/chat/completions。小米官方密钥需同时改端点为 https://api.xiaomimimo.com/v1/chat/completions；也支持以 /v1 结尾的基础地址。
3. 基础模型默认 mimo-v2.5-tts。按模式自动派生后缀，误填模式后缀也会先去除。
4. 必须启用 ImageServer 并配置 File_Key。主服务会注入文件访问密钥；音频写入项目文件资源目录，再返回受控 URL。
5. 在 Agent 工具提示词中加入 `{{VCPMimoDubbing}}`。已提供启用态 [plugin-manifest.json](plugin-manifest.json)，重启或等待清单热加载后可调用。
6. 需要超时语音自动加速时安装 FFmpeg，并配置可执行文件路径（不要附带命令参数）。只使用默认报错或明确截断策略不需要 FFmpeg。

要求 Node.js 20+，使用原生网络请求和内置模块，不需安装插件 npm 依赖。

公开 URL 默认按 VCP 的主机地址与端口生成；反向代理或分布式部署请配置完整公开基础地址。回调默认本机主服务端口，分布式部署需要填写可达主服务回调地址。

## 多段配音合成一条音轨（1.1）

每段独立设置音色与导演指令，整串只有一个异步任务和一个最终 WAV，不需要角色注册：

```text
<<<[TOOL_REQUEST]>>>
tool_name:「始」MimoDubbing「末」,
command:「始」submit「末」,
text1:「始」你终于来了，我等你好久了。「末」,
voice1:「始」冰糖「末」,
instruction1:「始」角色：活泼的年轻女性。场景：车站重逢。指导：欣喜轻快，不要尖叫。「末」,
pause_after1:「始」0.3「末」,
text2:「始」抱歉，让你久等了。我们出发吧。「末」,
voice2:「始」Dean「末」,
instruction2:「始」角色：沉稳温柔的男性。指导：先略带歉意，再轻松坚定。「末」,
pause_after2:「始」0.2「末」,
text3:「始」[轻笑]好，这次你带路。「末」,
voice3:「始」冰糖「末」,
instruction3:「始」角色：活泼的年轻女性。指导：俏皮自然，像接话，不要播音腔。「末」
<<<[END_TOOL_REQUEST]>>>
```

编号从 1 连续递增，最多 200 段。每段可选 commandN=speak，不填也可以。不是多个 submit 任务的批量调用，禁止在段内混入查询等命令。

段参数为 textN、voiceN、instructionN、modeN、styleN、reference_audioN、optimize_text_previewN、pause_afterN。音色和表演字段继承同名全局参数；正文每段必填。

- 不填起止时间：按实际生成时长依次拼接，不加速、不截断；每段后的静音由 pause_afterN 指定，单位秒，默认 0，最多 60 秒。全局 pause_after 可设置默认值，末段停顿也保留。
- 全部段填写 startN/endN：按固定时间轴生成，可使用原有超窗策略，不允许 pause_after。
- 不允许编号断档、未知编号字段、混合有时间/无时间的段、同时提供 timeline 与编号分段；连续模式不接受 overflow。
- 最终报告含 arrangement（sequence/timeline）、每段实际 start/end 和 pauseAfter。连续模式总长度包含停顿，最多 30 分钟。
- 所有段在回执前完成参数校验；任何一段合成失败都不会发布不完整音轨，但已经请求上游的段仍可能计费。

音轨是各段独立合成后的顺序拼接，并非上游共享上下文的连续对话生成；不支持重叠抢话或混音。每段可使用不同预置、设计或克隆模式，文件名仍为任务 UUID 加 WAV 扩展名。

## 基本调用

```text
<<<[TOOL_REQUEST]>>>
maid:「始」Nova「末」,
tool_name:「始」MimoDubbing「末」,
command:「始」submit「末」,
mode:「始」preset「末」,
voice:「始」冰糖「末」,
instruction:「始」自然明亮，咬字清晰，轻快但不要过度夸张。「末」,
timeline:「始」1
00:00:01,000 --> 00:00:05,000
(开心)欢迎来到这座城市。

2
00:00:06,000 --> 00:00:10,000
[轻笑]我们一起出发吧。「末」,
overflow:「始」error「末」
<<<[END_TOOL_REQUEST]>>>
```

立即返回任务 UUID 和动态结果占位符。AI 必须原文返回占位符，不能把“已提交”当作生成成功，也不能自行拼接音频地址。后台完成后回调主服务，由其保存结果、广播通知并替换后续上下文占位符。

回调有三次有界重试，仍失败时最终音频和任务状态保留，可查询：

```text
<<<[TOOL_REQUEST]>>>
tool_name:「始」MimoDubbing「末」,
command:「始」query「末」,
request_id:「始」提交返回的UUID「末」
<<<[END_TOOL_REQUEST]>>>
```

状态为 Running、Succeed 或 Failed。成功结果含音频 URL、总时长、每句原始/放置时长和对齐操作。主服务重启、进程被强制终止可能留下 Running 旧记录；超过配置总超时的 Running 不代表仍在运行。本版本没有自动恢复、自动重提或取消命令，避免重复计费。

## 时间轴

支持完整 SRT、WebVTT 或 JSON 数组/数组字符串。秒数从最终音频起点 0 开始，数字和 `HH:MM:SS.mmm` 时间戳均可。

```json
[
  {
    "start": 0,
    "end": 4,
    "text": "(开心)你好，欢迎回来。",
    "voice": "Mia"
  },
  {
    "start": 5,
    "end": 10,
    "text": "这段使用自然语言设计音色。",
    "mode": "voicedesign",
    "instruction": "温暖低沉的青年男性，语速适中，带一点沙哑。"
  }
]
```

每句可覆盖模式、预置音色、自然语言指令、独立风格、克隆参考音频和预览优化开关，未覆盖则继承全局参数。JSON 不是角色名字映射，不支持隐藏角色注册。

限制：1–200 句、总时间最多 30 分钟、单句最多 4000 字符、总正文最多 40000 字符。必须按时间顺序、不重叠、不倒序。单句窗口至少一个采样点。多行字幕原样保留，不自动删除 HTML 标签或改写正文。

## 三种模式与导演控制

- preset：预置音色模型。支持 mimo_default、冰糖、茉莉、苏打、白桦、Mia、Chloe、Milo、Dean。
- voicedesign：音色设计模型。自然语言指令必填，可设置布尔预览优化参数。
- voiceclone：音色克隆模型。参考音频必填，仅支持 WAV/MP3 Data URI；Base64 内容上限 10 MB，并检查 MIME 与音频文件头。参考音频不落盘，不在结果和对齐报告中回显。

参考音频通过用户消息的音频输入结构发送，正文始终放在助手消息。克隆消息结构由本插件实现，真实 DMXAPI/官方接口兼容性仍需用用户密钥验证。

主服务可透明转换 file:// 参数，插件自身不读取任意本地文件或下载任意 HTTP URL。参考音频 Data URI 是推荐输入形式；如果主服务转换成其他类型地址，需在调用端先转换为 Data URI。

自然语言指令不会朗读。导演结构只是指令写法，不是第四个模型：

```text
角色：
温暖成熟的旅行讲解员，声音有磁性但不压迫。

场景：
黄昏的车站，向刚抵达的朋友介绍这座城市。

指导：
语速适中，咬字清晰，句尾轻收。
- 语速与顿挫：重要地名稍作停顿。
- 气声与实声：以实声为主。
- 咬字与重音：突出欢迎与陪伴。
```

支持半角/全角圆括号及方括号开头风格，独立风格参数不带括号，多个风格用空格分隔。支持行内吸气、深呼吸、叹气、紧张、激动、疲惫、颤抖、气声、笑、轻笑、抽泣、哽咽标签。开头的已知行内标签不会被错误转换成风格括号。

唱歌风格为唱歌、sing 或 singing，必须独立使用，禁止与其他开头风格混用。自然语言指令没有语义级唱歌冲突检测，调用者也应避免在指令中写入相互矛盾的表演要求。

## 对齐策略

逐句合成，然后按字幕起点放置。首句前、句间和句尾空缺补静音。最终 WAV 长度为最后一句的结束时间，不附加额外尾音。

- error（默认）：语音超过字幕窗口立即失败，不截断，不让后续字幕漂移。
- fit：只对超过窗口的语音用 FFmpeg 保音高加速，默认最大 2 倍，可配置 1–4 倍。短句仍补静音，不慢放。超过倍率上限或加速后仍超窗会失败，不静默丢词。
- truncate：明确截断超出窗口的音频，可能丢词，不推荐正常配音使用。

时间轴约束的是整句起点与窗口，不是词级强制对齐。自然语言提示词无法保证模型精确生成指定秒数。逐句上游调用可能带来音色/语气轻微变化，尤其自然语言设计；参考音频克隆更适合要求较高的一致性场景。唱歌也会逐句生成，本插件不是连续整曲生成器。

## 安全、计费与运行数据

密钥只从后端环境获取；上游地址、输出目录和 FFmpeg 可执行文件由管理员配置，AI 不能覆盖。FFmpeg 不经 shell 执行。禁止网络重定向，避免认证信息跨端点转发。上游响应体错误不回显，避免供应商回显密钥或参考输入。

后台总超时会取消尚未完成的上游请求和 FFmpeg。异步任务已接受后，聊天连接断开不会取消任务，这是 VCP 异步插件语义，与之前的网页 SSE 测试台不同。

逐句请求会产生多次计费；中途失败时，之前已生成的句子仍可能收费，本版本不会自动重试收费的合成请求。语音仅在全部成功后发布。

只保存生成 WAV 和脱敏任务结果，不保存输入字幕、自然语言指令或参考音频。VCP 主服务自身的工具调用审计/调试日志可能记录入参，敏感参考音频应同时遵循主服务日志策略。

任务状态与音频文件不自动清理，维护者需按保留策略清理。资源文件与状态均加入版本控制忽略规则。带密钥下载链接不是公开匿名地址，请勿随意公开。

## 离线验证

根目录运行：

```text
node --test tests/mimoDubbing.test.js
```

测试包括时间轴解析、模型派生、风格/唱歌校验、参考音频校验、分块 SSE、异常/提前断流、静音与 WAV 编码，以及本地模拟上游的异步回执/回调/查询闭环。不调用真实 API、不使用真实密钥，也不启动完整 VCP 服务。

真实音色、上游克隆输入兼容性、最终听感和 FFmpeg 保音高质量须在真实环境另行验证。

### FFmpeg 回归验证

已安装 FFmpeg 时，Windows 命令提示符可运行：

```text
set "MIMO_TEST_FFMPEG=true" && node --test tests/mimoDubbing.test.js
```

本次开发验证结果：11 项测试全部通过，包括真实 FFmpeg 对离线测试波形的保音高加速。加速采用最多四次本地倍率微调，解决算法输出时长的近似误差；不重新请求收费 API，仍不允许超过配置倍率或静默截断。真实 MiMo API 尚未调用。
