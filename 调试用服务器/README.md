# VCP 调试用服务器

独立的本机 HTTP 反向代理，用于看到 VCP 每次实际发给上游网关的请求体。不需要安装依赖，不修改 VCP 源码。

## 启动与回滚

需要 Node.js 22 或更高版本。示例链路：**VCP → 本地调试代理 6305 → 原上游网关 3106**。原上游无需改端口。

1. 编辑代理目录自己的 [`config.env`](config.env)。新部署若没有此文件，从 [`config.env.example`](config.env.example) 复制一份。

   ```dotenv
   VCP_DEBUG_PROXY_UPSTREAM=http://127.0.0.1:3106
   VCP_DEBUG_PROXY_PORT=6305
   ```

   上游基址沿用 VCP 原先的地址，支持 HTTP、HTTPS 和网关路径前缀。若上游不在本机，把示例中的 `127.0.0.1` 换成原网关地址。不要把调试代理自己的地址填成上游。

2. 从 VCP 服务器根目录启动代理。代理会自动读取自身目录的配置，改配置后重启代理生效。

   ```cmd
   node "调试用服务器/server.js"
   ```

3. 将 VCP 根目录的 [`config.env`](../config.env) 中的 `API_URL` 改为：

   ```dotenv
   API_URL=http://127.0.0.1:6305
   ```

   不要在代理地址后加 `/v1`，原 API 密钥保持不变，然后重启 VCP。代理只监听 `127.0.0.1`，VCP 与代理需要共享同一回环网络，例如在同一主机环境或同一容器内运行。

回滚时把 VCP 的 `API_URL` 改回原上游基址，重启 VCP，再停止代理。
## 会记录什么

- 只记录 POST：`/v1/chat/completions`、`/v1/responses`，以及 `/v1/chat`、`/v1/resp` 两个短路径。查询参数不影响匹配，不写入日志；短路径不会被改写。VCP 若已将 Responses 请求转换成 Chat Completions，这里看到的是实际出站的 Chat Completions 请求。
- 向量化、rerank、生图、模型列表等其他路径直接转发，不读取并缓存完整请求体，不写日志。
- 每次匹配的请求（包括重试）各有一对文件，位置为 [`logs/`](logs)/UTC 日期/时间戳与 UUID/：
  - [`request.json`](server.js:126)：完整请求体，不重组消息、不删字段。压缩 JSON 仅为日志解压，仍按原字节发送上游。无法解码成 JSON 时以 Base64 保存原始字节。
  - [`request.md`](server.js:127)：按数组下标和角色展示消息，展开正文换行；Responses 的输入项也按顺序列出。
- 不记录任何请求头、查询串或上游响应。日志内容仍可能含系统提示词、用户对话、附件和工具结果。只在调试期间运行，调试结束后按需清理日志。
- 两个文件成功写入之后才会转发被记录的请求。写盘失败或对话请求体（含解压后）超过 128 MiB 时，这次请求不转发。日志代表已捕获的转发尝试，不代表上游已成功接收。
- HTTP API 的方法、路径、查询、正文和鉴权头不改写，上游状态码及响应体流式返回，不跟随重定向。每一跳会重新建立 HTTP 连接和传输分帧；这不是通用 TCP 或 WebSocket 代理。

这些日志展示的是 VCP 发给网关的 JSON，不是网关改写后或模型聊天模板渲染后的提示词。
