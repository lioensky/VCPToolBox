# 路由文件路径安全审计

## 范围

本次检索了路由目录中的直接文件写入、追加、创建目录、移动、复制和删除操作，并检查了相关路径来源。审计重点为请求参数或外部元数据影响落盘路径的接口，不等同于整个插件生态、插件内部 HTTP 路由或所有间接工具调用的完整安全审计。

## 直接风险与修复

| 模块 | 接口/操作 | 原问题 | 修复 |
| --- | --- | --- | --- |
| [TVS](../routes/admin/tvs.js) | TVS 读取、保存、删除 | 只检查扩展名，用户文件名直接拼接根目录 | 强制单文件名，检查目录边界与链接 |
| [Agent](../routes/admin/agents.js) | 新建、读取、保存 | 文件名和目录未限制，重复 URL 解码 | 文件名与相对目录分别校验，保留合法子目录，移除二次解码 |

| [插件商店](../routes/admin/pluginStore.js) | 文件夹上传、GitHub 子路径 | 原安全拼接允许同前缀兄弟目录，且清洗而非拒绝部分遍历输入 | 严格相对路径解析；检查上传目标；下载文件名不再包含外部仓库元数据 |

## 未发现请求路径直接参与拼接的写入

配置、图像缓存、AgentAssistant 配置与分数、日程、最终上下文配置、语义路由配置、JEV 策略及服务日志清空等接口，目标由服务端固定路径或可信配置决定，未发现与 TVS 同类的直接请求参数路径遍历。没有为了统一形式而改动全部固定配置写入逻辑。

通过服务模块或插件代理的接口，例如邮件、任务派发、人格管理、SAR 提示词及多模态配置，不应据此宣称插件内部所有写入均已审计。Bridge Profile 的间接存储因涉及名称生成文件路径，本次额外检查并加固了路由入口。

## 统一规则与兼容性

共享实现：[路径安全模块](../modules/safeFilePath.js)。

- 拒绝父目录段、绝对路径、盘符、UNC、控制字符及 Windows 备用数据流语法。
- 同时把正斜杠与反斜杠当作路径分隔符。
- 拒绝 Windows 设备保留名以及尾随点或空格的路径段，避免跨平台别名差异。
- 使用带路径边界的相对路径检查，不采用不带分隔符的简单前缀比较。
- 检查目标以及根目录以内的各级父目录，拒绝符号链接、悬空链接和 Windows junction。
- 不重复 URL 解码。百分号编码文本可以作为普通文件名保存，但不会被再次解释成路径。
- 保留中文文件名、合法相对子目录；已有链接目录及 Windows 非法名称会被拒绝。

## 安全边界

这些校验阻止请求级路径遍历和操作前已存在的链接逃逸，但不是对恶意本地进程的原子文件系统隔离。能在校验与使用之间替换目录的本地进程仍可能制造 TOCTOU 竞态；需配合操作系统目录权限，禁止非可信进程修改受管根目录及其上级目录。硬链接攻击、插件执行权限、任意工具调用权限、压缩包解析器的完整安全审计不在本次修复保证范围内。
