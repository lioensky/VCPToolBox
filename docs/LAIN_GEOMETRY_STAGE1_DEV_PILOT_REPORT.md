# 莱恩几何 Stage 1 开发集报告：赢家相邻，导航在哪里漏掉了它们？
2026-11-23｜Kerr｜状态：开发集首轮完成，暂停评审。未开启留出集评分。

**结论。** 固定同一批赢家，真实邻接使赢家片对的直连率从保度重连图的 25.89% 提高到 75.05%。这部分信号可以用于搜索：同样探 64 片、验 128 点，真图按 U 导航的平均 Recall@10 为 10.00%，重连图为 7.27%。但知道赢家彼此相邻，不等于从冷入口能找到它们。真图 U 的 2,530 个赢家名额中，1,843 个从未进池，另有 428 个在固定轨迹、时序和预算下本可选到却没被精验。当前工作点最大的损失在发现，其次在选片；没有证据支持把对称 XOR 设为默认。

## 共同口径

沿用 `LAIN_GEOMETRY_P0_PREREG.md` 的主曝光配置：原始 FP32，FP64 闭窗，逐维半径 IQR/8，k=10，得分降序、稳定 ID 升序。6,849 点、429 片；253 条开发查询，另有 141 条留出查询未评分。指标均指曝光真值，不指语义相关性。历史输入的精确重合检查不等于严格库外证明。Stage 0 结果见 `LAIN_GEOMETRY_P0_DEV_EXPERIMENT_RECORD.md`。

## 一、赢家图：真正有区分力的是一跳，不是两跳

将点级 CSR 投影成简单无向片图，去自环、合并重复边。真图有 24,337 条边，平均度约 113，全图连通。对照为五张固定种子的重连图；每张接受 243,370 次双边交换，保持每片度数和原连通分量成员。每条查询固定同一组 Top-10 赢家，映射后平均占 8.285 个不同片。先在查询内对不同赢家片的无序对统计，再对查询等权平均。

| 指标 | 真图 | 保度重连均值 |
|---|---:|---:|
| 赢家片对直接相邻 | 75.05% | 25.89% |
| 平均最短路（允许经过非赢家片） | 1.250 跳 | 1.741 跳 |
| 两跳内可达 | 99.989% | 100.000% |
| 只保留赢家片时的平均连通分量数 | 1.119 | 2.307 |
| 允许经过非赢家片时的平均连通分量数 | 1.000 | 1.000 |

保度后，一跳直连率相差 49.16 个百分点；两跳可达率却都已饱和。这支持真实边的位置携带赢家聚集信号，不证明入口好找，也不证明相邻赢家的查询响应位流相似。

## 二、四宫格：真实边贡献平均收益，XOR 未提高总召回

使用 8 桶摘要；按冻结入口、方向地标、壳地标顺序映射去重，取前四个片 `88,76,72,240`。每条边的枚举次序由固定哈希确定，不预看邻居摘要。每轮从已探片中选一个尚有邻居可枚举的扩展源，最多新探 8 片，再从已付费候选中精验一片。扩展与精验分开，首次计算某片响应扣一次探查。基础优先级为 U；折痕组对已枚举边使用 `U_j−0.5·popcount(h_i XOR h_j)`，同一候选保留已见最高优先级。原始载荷按整片实长计费。真值不参与调度。

| 条件 | 实探片 / 实验点 | Recall@10 | 至少首中一次 | 原型耗时 P50 / P95 / P99（ms） |
|---|---:|---:|---:|---:|
| 真图 · U | 64 / 128 | 10.00% | 52.57% | 1.147 / 1.689 / 2.383 |
| 真图 · XOR | 64 / 128 | 9.57% | 45.06% | 1.117 / 1.513 / 1.811 |
| 重连 · U | 64 / 128 | 7.27% | 44.19% | 1.083 / 1.457 / 2.105 |
| 重连 · XOR | 64 / 128 | 6.53% | 41.34% | 1.078 / 1.472 / 2.234 |
| 无图，全扫摘要 · U | **429** / 128 | **22.29%** | 73.52% | 2.612 / 3.249 / 5.232 |

实耗预算在各自条件内逐条相同。真图每格 253 条；重连每格 5×253 条；全扫 253 条，合计 3,289 条。重连种子不当成额外独立查询。真图 U 对同查询五张重连图均值，配对差均值 +2.74 个百分点，中位数 0，胜/平/负为 116/29/108。是平均收益，不是普遍逐查询胜出。全扫行固定精验预算、放宽摘要预算，不是四宫格的同预算优胜者。延迟描述当前 Python 原型（U 路径也生成 h），不作生产加速结论。

**首中与后续。** “首中”是实际精验到至少一个 Top-10 点，按整片验证完成时计费。真图 U 首中 133/253，XOR 首中 114/253；仅在各自首中样本内，首中时平均已探 35.31 / 35.89 片、已验 63.16 / 64.28 点。在两者都首中且都还能再花 32 点的 63 条共同查询上，随后 32 点平均新增赢家为 U 的 0.444、XOR 的 0.603。这符合“延续亮区可能有益”的假设，但两条轨迹并非从同一个前沿起步，不是折痕首中后有效的因果证明，更不能以离线首中标签切换在线策略。

## 三、真图 U 重放：十个名额逐项对账

保持入口、盲探顺序、U 优先级和预算不变。253 条重放逐查询复现原记录的探查数、精验数、召回、首中及首中后指标。记录八次精验动作发生前各自可见的片，再用真值做两次离线选择：
- **最终池上限**：假设最后探到的 64 片从一开始都可选，按片实长，128 点内最多收回多少赢家。
- **时序上限**：保留原轨迹八次动作机会；每次至多选一个当时已经可见的片，机会可以放弃但不能攒到下一轮。允许事后最优选择，仍不得超 128 点。

| Top-10 名额归属 | 总数 / 2,530 | 比例 | 如何理解 |
|---|---:|---:|---|
| 候选池外 | 1,843 | 72.85% | 最终 64 片里没有该赢家所在片 |
| 最终池容量损失 | 0 | 0.00% | 即使知道答案，也因 128 点整片成本放不下的名额 |
| 到达时序损失 | 6 | 0.24% | 最终能放下，但原动作轮次来不及选全 |
| 选片损失 | 428 | 16.92% | 时序上限可拿到、实际 U 调度没拿到的名额差 |
| 实际命中 | 253 | 10.00% | 已精验、进入近似 Top-10 的真实赢家 |

每查询平均：**进池 2.715 → 最终池上限 2.715 → 时序上限 2.692 → 实收 1.000**。零命中的 120 条查询中，49 条全程没探到赢家片，71 条候选池里已有赢家却未验到。要提高固定轨迹的召回上限，首先得改变发现轨迹；要减少零命中，选片也有明确的改进空间。“容量损失为零”只对这个已发现池的事后最优选择成立，不表示提高精验预算对实际策略无益。时序上限也不是可部署的召回率。

## 评审停点

- **已测：** 真图相对保度重连的赢家聚集与同预算平均召回收益；当前 XOR 工作点的首中与总召回代价；当前真图 U 轨迹上的发现、时序、选择损失。
- **未测：** 强边优先能否改善发现；胖片偏置是否解释选片损失；不同预算、入口或 β 的泛化表现。上述结果没有证明“剩下只需工程优化”。
- **下一项候选，不启动：** 同一真图、相同入口和 `64/128` 预算、相同 U 精验规则，只把哈希盲枚举替换为跨片点边重数降序。用 **2.715 个入池赢家**检验发现，用 **1.000 个实收赢家**检验收益是否兑现。若前者提高而后者不动，再固定前沿研究选片，不同时改变两个机制。
