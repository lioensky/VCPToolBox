# VCP Tool Call Manual Approval API

Here is the documentation for the Phase 1 backend implementation to facilitate frontend integration.

## Backend to Frontend (WebSocket Notification)

When a tool call requires manual approval, the backend broadcasts a `tool_approval_request` to all connected [AdminPanel](file:///h:/VCP/VCPToolBox/WebSocketServer.js#541-555) clients.

**Message Type:** `tool_approval_request`

**Payload Format:**
```json
{
  "type": "tool_approval_request",
  "data": {
    "requestId": "approve-1710348740345-6n2d9sk0p",
    "toolName": "LinuxShellExecutor",
    "maid": "VCPMaid",
    "args": {
      "command": "rm -rf /"
    },
    "timestamp": "2024-03-14T00:52:20.345+08:00"
  }
}
```

- `requestId`: Unique identifier for this approval request.
- `toolName`: The name of the tool being called.
- `maid`: The identity (maid) initiating the call.
- `args`: The arguments passed to the tool.
- `timestamp`: Specific local time of the request.

---

## Frontend to Backend (Approval Decision)

The frontend should send back a `tool_approval_response` once the user clicks "Allow" or "Reject".

**Message Type:** `tool_approval_response`

**Payload Format:**
```json
{
  "type": "tool_approval_response",
  "data": {
    "requestId": "approve-1710348740345-6n2d9sk0p",
    "approved": true
  }
}
```

- `requestId`: Must match the `requestId` received in the request.
- `approved`: `true` to allow execution, `false` to reject.

## Configuration Settings

The logic is controlled by [toolApprovalConfig.json](file:///h:/VCP/VCPToolBox/toolApprovalConfig.json) in the project root:

```json
{
  "enabled": false,
  "timeoutMinutes": 5,
  "approveAll": false,
  "approvalList": [
    "TestTool1",
    "PowerShellExecutor:Get-ChildItem",
    "ChromeBridge:open_url",
    "PowerShellExecutor::SilentReject",
    "PowerShellExecutor:Remove-Item::SilentReject"
  ]
}
```

- `enabled`: Global switch for the feature.
- `timeoutMinutes`: Automatic rejection if no response is received within this time.
- `approveAll`: If `true`, all tool calls will require manual approval (ignoring `approvalList`).
- `approvalList`: when `approveAll` is `false`, each entry supports four exact-match formats:
  - `ToolName`: require approval for all calls of that tool; notify AI on rejection.
  - `ToolName:Command`: require approval only when `command` matches exactly; notify AI on rejection.
  - `ToolName::SilentReject`: require approval for all calls of that tool; do not notify AI on rejection.
  - `ToolName:Command::SilentReject`: require approval only when `command` matches exactly; do not notify AI on rejection.
- If a tool call carries `command1`, `command2`, ... then matching any one of them will trigger approval.
- If both tool-level and command-level rules match, command-level rule wins.
- If a same-scope rule exists with and without `::SilentReject`, the `::SilentReject` rule takes precedence.
- If a tool call has no `command` / `commandN`, then only tool-level rules can match.
- 工具名匹配不区分大小写。

### 参数级规则（细粒度）

语法：`ToolName:参数名:[匹配值]`，可追加 `::SilentReject`。

| 匹配值写法 | 含义 |
|------------|------|
| `[C:]` / `[C]` | 前缀匹配（默认），不区分大小写；单字母自动视为盘符 |
| `[=DeleteFile]` | 精确匹配 |
| `[*.env]` | 含 `*` 为通配匹配（`*` 匹配任意字符） |

特殊参数名：

- `Path`：匹配所有路径类参数（键名以 `path` / `dir` / `directory` / `folder` 结尾，或 `cwd`，含编号变体），如 `filePath`、`sourcePath`、`destinationPath`、`directoryPath`、`searchPath`、`downloadDir`。
- `*`：匹配除 `maid` 外的全部参数。
- 普通参数名同时匹配其编号变体（`command` 匹配 `command1`、`command2`…）。

路径处理：统一 `\` → `/`、剥离引号、解析 `file:///`、折叠 `..`（`H:\safe\..\Windows` 视为 `H:/Windows`）；前缀匹配遵守路径边界（`[H:\work]` 不匹配 `H:\work-old`）。命令等非路径值前缀匹配遵守单词边界（`[node]` 不匹配 `nodemon`、`node-gyp`）。

优先级：参数级(3) > 命令级(2) > 工具级(1) > approveAll(0)。

示例：
```json
"approvalList": [
  "FileOperator:DeleteFile",
  "FileOperator:Path:[C:]",
  "FileOperator:filePath:[*.env]::SilentReject"
]
```

### 免审核白名单 `whitelist`

```json
"whitelist": [
  "PowerShellExecutor:command:[node]",
  "FileOperator:Path:[H:\\VCP\\workspace]"
]
```

- 语法与 `approvalList` 相同（`::SilentReject` 无意义）。
- 仅当白名单的具体程度 **≥** 命中审核规则时才豁免（同级白名单优先）。即工具级白名单无法豁免参数级审核；`approveAll` 下任意白名单都可豁免。
- 参数/命令级白名单要求该参数的**全部值**（含 `command1`、`command2`… 或多个路径参数）都命中白名单，否则不生效。
- 命令类参数（`command`/`cmd`/`script`/`shell`/`code` 及编号变体）中出现 `; & | \` $ ( ) { } < >` 或换行时，白名单自动失效，防止 `node a.js; Remove-Item ...` 这类串联绕过。
- 命中白名单时后端日志输出 `✅ 命中xx白名单 [...]，豁免审核规则 [...]`。
