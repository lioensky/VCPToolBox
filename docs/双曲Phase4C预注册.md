# Phase 4C 开发消融与第三版终验预注册

注册时间：2026-11-17，北京时间。现场提交69db6d59，工作区初始干净。
本协议在Phase 4C开发结果及第三版终验读出前固定；不修改Phase 4B历史协议。

## 边界与假设

- 原始SQLite向量只读，索引流式构建，无全库原始FP32驻留；生产默认不变。
- 每尝试层精排唯一冷读最多64，宽度128，最多三层，原空间NNLS解释接受门槛0.03。
- 访问预算饥饿、径向罗盘尺度、查询端量化误差是待验证因素，不预先声称唯一根因已证明。
- 升降梯步长用于排序而不是硬资格阈值；大于跨度不意味着完全没有升降梯边。
- 现役余弦没有同样的访问硬上限；1024访问不自动等同其实际热工作量。
- L0精确解释差约2.07个百分点；不同闭环L1查询不同，不直接宣传为同查询因果提升。
- 历史冻结场代次和非EPA回放限制不变，ID互斥不等于文档或主题独立。

## 实现与计数

- 增加实例级径向罗盘缩放开关，旧默认保留常数。
- 启用时跨度为最大值（半径上限减0.35，0.10），三个尺度分别为跨度乘0.35、0.12、0.42。
- 增加请求级非对称导航与16种子选项，旧入口仍保持对称导航和原种子配额。
- 紧凑入口保留最多8个内壳节点，再从不重复方向候选中按同一热距离选择至总数16；仍服从小访问预算及宽度限制。
- 记录首次发现预算被拒绝时的展开数、拒绝发现尝试数、预算耗尽后展开次数。
- 拒绝发现尝试按实际尝试计，不冒称不同节点数量；另记录选种评分、导航评分与非对称精筛工作量。

## 开发矩阵

只允许原12开发加旧32留出44查询，不读取fresh_holdout或holdout_v3向量或评价。

1. 代表A：上限0.65、喉部1.5、软化0.15、剥离1、角尺度2。
2. A上执行罗盘缩放／非对称导航／紧凑种子的全部八种组合。
3. 每种组合执行访问／展开三档：256／128、512／192、1024／256。
4. 定点参数矩阵：上限0.65／0.90，喉部0.8／1.5，软化0.15／0.35，剥离0.7／1，角尺度1／2，共32组。
5. 参数矩阵统一三项启用、1024／256；与A全启用大预算项去重。
6. 加现役余弦和旧设置首轮中心参考。预计57条路线，若只做流程检查须显式标记smoke而非完整开发。

## 门禁与锁定

- 三项门禁沿用Phase 4B定义：44查询L0返回平均入度分位数严格小于0.85；
  精确候选与ANN候选解释能量各不少于同次现役余弦对应均值的98%。
- 只从32组全修复且1024／256预算的参数配置中选型。
- 达标者按44查询终局已接受解释能量降序，平局按上限、喉部、软化、剥离、角尺度升序。
- 锁定前2至3组；不足2组不降低门槛，不以失败组冒充达标进入成功终验。
- 锁文件沿用phase4b-lock-v1，但新增phase4c协议身份、三个修复开关、固定热预算、
  开发来源与SHA-256、基线结果及实际门槛。验证入口必须检查这些附加字段。
- 同一几何若有不同软化参数而结果近似或相同仍按既定规则，不根据终验临时替换配置。

## 第三版终验

- 仅在成功锁定后，使用源冻结副本独占新建4096和8192导出。
- 原12、旧32、新32历史ID均排除；新种子20261118抽32条holdout_v3。
- 两规模验证查询ID必须相同，互斥性需独立核对；不改变采样种子。
- 一次性评测现役余弦、首轮中心旧设置参考及锁定配置。
- 锁定配置统一全修复、宽度128、访问1024、展开256、唯一冷读64；
  首轮中心参考保持旧罗盘、对称导航、旧种子、256／128，明确不是等热工作量。
- 不按第三版结果再调参或选择默认值。报告L0/L1召回、覆盖、解释能量、
  同查询精确对照、误停数、热访问及评分、冷读、构图和统计内存。
- 无论成败保留完整结果，不将开发最高解释0.604643预设为必达结果。
