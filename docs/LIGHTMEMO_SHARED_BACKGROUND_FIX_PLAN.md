# LightMemo 词元契约与共享背景修复
工程：p299n。2026-11-12。状态：施工中，未部署。

## 不变量
- 背景只读共享；各请求独立激活、Spike、双场、候选及读出。
- 不合并不同查询的动态场，不新增时间窗口聚合器。
- 保留 queryTokens <= 256、单词 UTF-8 字节长度 <= 1024 的原生安全边界。
- 已接收的活动请求不得因后续请求到来被 FIFO 淘汰。
- 不修改生产配置、数据库或部署产物。

## 已核实
- nativeQuery.js 无预算合并基础词与语义组扩展，生产大组可突破 Rust 校验。
- 普通 knn 虽不评分，仍生成并传递扩展词。
- MemoRuntime 已有 Arc 背景与 cold_load single-flight；已有 concurrent_cold_loads_share_one_decode 测试。复用，不另建缓存。
- withMemoObservationScope 按完整 ABI 输入共享相同观测，不合并不同输入。
- observation 注册表仍存在 256 FIFO 与五分钟 TTL，资产切代清空；需要修复生命周期。
- TaskLifecycle 的 admission 仅跟踪关闭/排空，并不是容量限流。

## 施工
1. 独立关键词构造器：统一启用条件、归一化去重、原词优先、激活组轮转填充，256 总预算；超长词过滤并诊断。
2. nativeQuery 接入；诊断传回日志；Rust 字段级校验；Error 显式记录 message/code。
3. 核对各消费者后修复活动观测所有权、背景快照绑定与有界准入，不牺牲现有数据库代际/依赖校验。
4. JS 夹具验证大组、多组、边界、关闭路径；Rust 验证输入边界、共享背景、并发隔离与生命周期。
5. 记录测试真实结果、剩余限制及部署要求。

## 禁止的捷径
- 不将 256 改成 1024。
- 不无限移除资源边界。
- 不通过旧背景快照绕过 SQL 事实变化校验。
- 不以生产随机查询非空作为测试判据。

## 实现结果
- queryTokens.js：原始词优先、多组轮转、归一化去重；最多256词、单词最多1024 UTF-8字节；裁剪及无效词显式诊断。
- nativeQuery 按实际 useBm25 决定是否生成词元；普通knn跳过，实验室AB保留既有规则。
- Rust保留输入安全上限，字段级错误提供actual/expected/max；JS错误日志显式记录message/code。
- 复用既有Arc背景与cold_load；observation持有实际管线使用的背景Arc。发布不同资产不再清空活动句柄。
- 活动句柄不因FIFO/TTL被淘汰；满256个注册观测时明确拒绝新注册。五分钟仅为超龄诊断阈值，正常路径显式释放。
- LightMemoTask提交时持有observation Arc，普通及AB读出直接复用，避免任务执行后段查找句柄。
- 读出仍检查SQL资产依赖及数据库generation；不以旧背景绕过事实一致性。
- KBM LightMemo入口提供异步准入：每owner最多8个运行、256个排队，排队30秒超时，支持排队AbortSignal；许可覆盖准备、读出及finally释放。不占用原生线程等待许可。
