# Tag 双曲场训练换代施工图：降低建场成本，保持图不变

状态：G1 已实现并通过索引内核回归；G0 已测独立建表，真库整场分项基线待测。适用于手动全量训练或变动阈值触发后的 Tag 场构建，不改变训练触发条件。跨代整表复用、图边构建优化各有独立启动条件；在线精排不排期。

## 1. “不变”指什么

对**同一事实快照、同一训练输入、同一原生构建和平台**，优化路径必须生成与参考路径相同的方向编码、节点半径、导航表字节、CSR 邻接次序、入口和地标。不能只比较连通性、召回率或几个查询的 Top-K。不同训练代的图允许不同；复用某个中间量不代表承认旧图为新图。

[Tag 场构建入口](../rust-vexus-lite/src/warped_tag_field.rs:152)先确定均值轴来源、入流分位、有效成员和半径，再从 SQL 取原向量。[索引构建](../rust-vexus-lite/crates/vcp-tdb-index/src/index/quiver/hyperbolic/warped.rs:211)依次转换并编码方向、生成几何导航表、构建图、生成方向地标；宿主随后检查连通性并补壳层地标。**生成导航表不是生成图边**：前者是固定规模数值工作，后者使用当前库的节点、位码和半径，成本会随数据变化。

## 2. G0：先测一次完整换代，确定瓶颈

- 在隔离工作目录使用一致的 SQLite 副本；有 WAL 时通过 SQLite 备份接口或停写后的完整副本取样，不单独复制活动主文件。不给原库写快照，不让上游统一几何或传输资产在对照期间换代。
- 用同一发布构建、线程数、模型、预设、资产签名及输入顺序，分别走旧、新两条完整构建路径。记录来源是新建、快照恢复还是内存命中；后三者不可混算。旧路径先重复两次检查载荷是否确定；若图本身有非确定性，先定位，不能放宽验收口径。
- 分项记录墙钟时间：SQL 元数据及半径、原件读取与方向编码、几何建表、图边构建、连通性与两类地标、序列化与落盘。另记节点数、维度、边数、总耗时、峰值内存；固定冷／热文件缓存口径，计时和详细计数分轮进行。
- 至少三组交替对照，列出各次耗时与中位数。若单次全量成本过高，先用小固定集调通，真实规模的未测项留空。若建表仅占整场时间的比例为 f，即便完全消除建表，整场节时比例也不超过 f。不要把建表倍速写成建场倍速。

## 3. G1：代内消除重复求积（本期实施候选）

[建表循环](../rust-vexus-lite/crates/vcp-tdb-index/src/index/quiver/hyperbolic/warped_geometry.rs:469)在 64 个半径上取 2,080 个无序半径对，每对算 65 个角度，共 135,200 个距离。只为生产正喉部预设增加专用建表路径；[原距离实现](../rust-vexus-lite/crates/vcp-tdb-index/src/index/quiver/hyperbolic/warped_geometry.rs:301)保留作参考，其他几何和在线求距不动。

| 计算项 | 依赖 | 施工方式 |
|---|---|---|
| 喉部切线转角 T(R)、长度 L(R) | 有效几何及单个网格半径 | 各用 64 个双精度槽，调用原积分器一次填好；共 1 KiB，建表结束释放 |
| 单调路径临界角 C(a,b) | 有效几何及排序后的两个半径 | 在半径对的任务内算一次，供 65 个角度使用，无需全局缓存 |
| 路径分支、内部折返或单调求根 | 还依赖当前角度 | 保留原比较顺序、端点特例、容差、求根器和求积顺序 |

边界分支仍按 **(L(a) + L(b)) + φ(0) × (θ − (T(a) + T(b)))** 求值；不要重排加减、提前判边界、改精度或引入近似。网格半径、角余弦、距离平方减径差平方、单精度舍入和对称写表均保留原表达式。建表使用的是真实网格双精度半径，不得借用 Tag 节点舍入后的半径。

已做可行性探针：零软化时 64 个端点与独立闭式对照，角度／长度最大绝对误差分别为 3.33×10⁻¹⁶、6.66×10⁻¹⁶。生产参数网格中，2,080 项同方向、906 项单调、123,504 项边界、8,710 项内部折返；抽测 1,220 项边界值无位差。这是 Python 数值实验，**不是 Rust 验收，也不是建图加速实测**。

## 4. G2：同参数跨代复用整表（条件立项）

仅当 G0 记录到多次真正新建、其建表键完全相同，且 G1 后建表成本仍值得消除，才排此项。真实副本含两代就绪传输资产，这不等于已观测到两次同参数建表。

- **允许共享**：仅不可变导航表。键由最终有效几何类型及其浮点参数位模式、最大半径、两个网格规格、网格生成与数值算法版本构成。表生成不读取 Tag、均值轴或数据库代际，不要用资产签名代替几何键。
- **不共享**：成员、入流分位、局部残差、节点半径、均值轴、方向位码、图边、地标及发布票据。入流排序和均值轴都可能随换代改变，不能据“只改 1% Tag”推断只需更新 1% 图边。
- 优先做进程内、有界、同键单次构建的只读表复用，不引入独立持久化文件。键不匹配、版本变化、无缓存时就本地建表；构建失败不缓存半成品。强制训练仍重新构建和校验当前代的图；保留独立的绕过表缓存测量路径。
- [整场快照](../rust-vexus-lite/crates/vcp-tdb-index/src/index/quiver/hyperbolic/warped_snapshot.rs:106)已保存表，正常恢复不重新积分；不改现有快照格式、CRC、资产校验和[发布门禁](../rust-vexus-lite/src/warped_field_snapshot.rs:118)。不能为取旧表而把旧图作为新代发布。

## 5. 若 G0 显示图边构建占主导

转向[图构建入口](../rust-vexus-lite/crates/vcp-tdb-index/src/index/quiver/hyperbolic/warped_graph.rs:72)及[四向剪枝](../rust-vexus-lite/crates/vcp-tdb-index/src/index/quiver/hyperbolic/warped_graph.rs:333)，而不是继续投入建表。先在诊断构建中按阶段统计距离／角损调用数、同一有序节点对重复率、剪枝耗时及临时分配。确认重复计算显著后，再试单次剪枝调用内复用相同输入的精确评分；保持候选访问、同分决胜、回边处理和写边顺序。不设全库节点对缓存，不降低度数或构建宽度，不把旧代边混入当前代。没有热点证据就不立优化工单。

## 6. 放行、停止与回退

1. 在同一原生二进制中逐位比较 135,200 个双精度距离及展开后的 266,240 个单精度表项；覆盖零半径、相等半径、相反与同向、两个分支临界角两侧可表示的输入。遇到差异，报告首个半径对、角度、分支和位模式，不放宽容差。
2. 对同一事实输入比对完整[训练索引载荷](../rust-vexus-lite/crates/vcp-tdb-index/src/index/quiver/hyperbolic/warped_snapshot.rs:84)、宿主入流分位及快照恢复结果；另做固定查询距离位模式与 ID 次序回归。时间戳、耗时等诊断不属于数学载荷。
3. G2 若立项，补测相同键跨事实代命中、单参数变化未命中、并发请求、失败重试、强制重建、失效发布票据及重启后旧快照恢复。两代各自和**本代独立全量参考**比较，不要求不同训练代的图相等。
4. 仅在零位差、整场无可重复性能回退且目标阶段节时超过重复运行波动时放行。若收益只存在于建表，按建表收益报告。若图边占主导，执行第 5 节；若发现位差或失效问题，切回原建表路径，不发布未验收产物，无需改库或迁移快照。

**本期交付边界：分项基线、建表等价实现及逐位对照报告。** 在线每 Tag 常驻 16 字节、实际精排分支统计、增量图和跨进程缓存均不在本期验收内。

## 7. G1 实装与实测

- 同向输入先按原表达式返回绝对径差；不会因为提前准备半径对临界角而进入单调、折返或边界分支。排序后的网格半径直接用于准备积分，非生产规格不启用该建表快路。
- Release 索引内核回归 129 项通过、0 失败、4 项默认跳过。生产网格 135,200 个距离及展开后的 266,240 个表项逐位一致；固定合成输入的完整索引载荷、快照恢复查询的 ID 次序与距离位模式也一致。
- 独立建表（Release，4 个 Rayon 线程，3 组交替）：参考路径 74.81／66.15／68.32 ms，优化路径 20.38／15.24／13.70 ms。中位数 68.32 → 15.24 ms，约 4.48 倍，单表节省约 53 ms。这不是完整建图耗时。
- 既有约 4 万节点的历史实验建场记录约 6.7–8.2 秒，只是量级参考，不是同平台同输入的 G0 对照。本轮未重训真库，也未更改剪枝、图边生成、跨代缓存或在线评分策略。若继续压低整场耗时，先在同一真库副本上补测 G0 的图边、编码和 SQL 各阶段。

## 8. 纯追加文件时的局部残差

1% 阈值触发训练后，原生几何任务在同一个 SQLite 读事务中核对上一代发布身份、读取旧局部行并求解本次目标。目标是新增文件里出现过的全部 Tag，包括被新文件再次引用的旧 Tag。每个目标使用自己当前参与的所有文件，仍按文件 ID、位置、Tag ID 累计，每个文件限 2–100 项。邻居的局部残差不参与目标求解。

首版只加速纯追加窗口。手动一键全量重训练沿用原有几何签名缓存，签名未命中时执行整库局部求解。首次训练、旧文件成员或位置改变、文件删除、已有 Tag 原件版本或有效性改变，以及模型、维度、算法或配置改变时，阈值训练也走整库局部求解。旧文件跨过 100 项边界也属于成员变化。缺少完整的已发布工件、局部行或诊断，或读事务中的事实不能通过核对时，同样回退。

`kv_store` 的 `memo_local_inputs_v1` 键保存一条 JSON 记录，随几何发布事务替换。字段 `signature` 是几何签名，`files` 是含空文件的升序 ID 数组，`file_events` 是文件变动计数，`diagnostics_hash` 是诊断 JSON 的 SHA-256，`derived_revision` 是 SQLite 记录的几何发布版本。缺少文件计数时该记录无法用于复用。现有几何签名已经覆盖 Tag 身份、原件版本及有序成员关系。训练器用当前读视图中的旧 Tag、旧文件重建这个签名。文件变动计数的增量必须等于新文件数，Tag 事实计数的增量必须等于新 Tag 数与新文件成员数之和。它还核对上代 Memo 工件记录的几何版本，只有成功发布的工件才能成为复用来源。

复用时，残差和锚增益取自 SQLite 发布行，选列顺序与 NNLS 诊断取自同代诊断记录。训练器按本代 Tag ID 顺序合并结果，照常计算全库支持度、EPA、覆盖率、共现和入流分位，并用本代均值轴、方向码和半径构建图边及地标。`phaseSummary.localReused` 是本代沿用的局部行数。

部署时需重新构建与当前源码匹配的 `rust-vexus-lite` 原生模块。升级后的首次阈值训练若缺少发布记录，会完成整库训练并写入记录。
