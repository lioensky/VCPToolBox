# RiverMemo 增量刷新与旧图持续服务修复

## 问题与根因

普通日记摄取会改变 Tag 或日记标签关联。此前查询和冷启动清单要求训练依赖版本与实时版本完全相等，导致任何相关写入都能使上一代图被拒用。另一方面，自动训练只累计新增 Tag，阈值硬编码为 50；已有 Tag 的关联变化可能导致图被拒用但没有重算任务。

另有冷启动算法版本判断落后于当前原生构建格式的问题。

## 修复后的策略

- 已发布图是不可变训练快照，不要求追随每次事实提交。
- 普通事实版本和派生几何版本向前增长，不撤销上一代图的在线服务资格。
- 新图成功构建并发布后切换；训练失败保留上一代图和累计变动。
- 在线查询及冷恢复仍检查支持的资产格式、依赖键集合、依赖存在性和版本不得倒退；冷恢复还按模型签名和配置哈希筛选。
- 冷加载仍验证压缩载荷校验和、CSR 结构、节点与边权合法性。
- 构建提交仍保留严格数据库代际和依赖快照检查，不允许过期计算覆盖已发布资产。
- 权限过滤与实时候选检索逻辑不变，新日记无需等待图重算即可进入向量候选。

## 自动训练计数口径

阈值为上次成功训练时 Tag 总数的 1%，向上取整，至少 1 个。

累计量是训练后发生变化的**唯一 Tag ID 数**，不是写入次数，也不是事实版本差值。覆盖：

- Tag 新增、删除、名称或向量修改；
- 日记标签关联新增、删除、位置或归属变化；
- 日记路径、日记本归属变化所涉及的 Tag。

同一个 Tag 重复修改只计一个。删除的 Tag 仍保留在待刷新集合中，因此该集合不对 Tag 表建立外键。

待刷新集合和训练基线由 Rust 所持数据库持久化，重启不清空。成功图发布的事务更新训练基线并清空已纳入图的累计变化；提交严格快照检查确保训练期间有新事实时旧计算不会错误清空新变化。

首次升级没有历史唯一变更日志时，无法准确追溯修复前已发生的全部变化；计数从新触发器安装后开始，缺少训练基线时暂用当前 Tag 总数。上一代格式兼容图可继续使用；需要立即纳入修复前所有变动时，可显式执行一次管理员全量训练，无需删除旧图或索引。

## 调度

- 日记摄取、删除及 Tag 一致性维护提交后检查阈值。
- 每分钟补查一次，覆盖重启与其他写入入口。
- 达到阈值后使用固定延迟期限，默认 5 分钟，不因后续写入或轮询不断延期。
- 既有训练进行时不重复排队；其后的轮询会检查是否仍有未处理变化。
- 训练重试保留退避时间，不再被队列收尾逻辑覆盖成每秒重试。
- 管理员显式全量训练接口保留。

## 验证

- 完整 Rust 原生单测通过。
- 28 项针对性 Node 回归通过。
- 原生清单、TypedArray/观测句柄、联合检索、并发冷恢复集成测试通过。
- 验证新增 Tag 后热查询和冷恢复均可继续使用旧图。
- 验证几何资产更新和训练失败不会撤销旧图。
- 验证成功图重建清空累计量并更新训练基线。
- 验证关联变化按唯一 Tag 计数，版本倒退及依赖缺失仍拒绝加载。
- 差异空白检查通过；构建工具存在换行规范提示。

## 部署

本次包含 Rust 逻辑和数据库附加表、触发器的自动初始化变更，不能只更新 JS。

部署时更新源码及目标平台对应的原生构建产物，并重启服务加载新模块。其他平台必须重新构建对应原生模块。已有兼容图不需要因这次修复强制重新训练。

未对生产数据库或日记运行批量修复，测试使用临时数据库；本轮没有重启生产服务。
