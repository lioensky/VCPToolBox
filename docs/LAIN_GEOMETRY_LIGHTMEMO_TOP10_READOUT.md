## 怎么测

1. **先认人。** 用相对路径在冻结 SQLite 联结 `files → chunks`，再用 LightMemo 回执正文核对具体块；仅统一换行等展示差异。记 `chunks.id`、`chunk_index`，确认 ID 存在于 `plate-a` 的稳定 ID 数组。特别留意月度 timeline 可能对应多个块。若多个块都匹配、返回的是跨块聚合、版本不同或未入盘，写清状态；不挑得分最高的块冒充原片段，不把缺失记为末名。
2. **主读数：精确曝光。** 对原始 FP32 全盘，沿用 IQR/8、FP64 闭窗端点，计算每点命中维数 `S`，按 `(S 降序, 稳定 ID 升序)` 排名，从 1 起计。报 `S`、精确名次、`S−S₁₀`（负数表示少几票）。上一轮 `S₁₀=281`，阈值处有同分；差零票不保证进入前十，必须报实际名次。
3. **副读数：3-bit 粗排。** 对同一 ID 报桶内 ECDF 估分 `Ŝ`、全盘粗排名、是否进前 128。先复核本查询既有精确前十 ID 及候选精排与其重合 8/10。精确名次靠前但粗排掉出 128，是候选选择问题；精确名次本来就靠后，单靠更忠实的量化不能使它成为曝光赢家。
4. **距离的边界。** 若希望用“越小越近”的数，可附 `D窗=1−S/3072`，明确它仅为**未命中维度比例**，与曝光分携带相同信息，不是已证明的度量。当前查询没有冻结的 Plate II 二维坐标；不报虚构的盘面欧氏距离、双曲距离或图跳数。若要测这些量，另定不使用答案标签的查询落点规则。
