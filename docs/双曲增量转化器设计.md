# 双曲增量转化器设计与验证

日期：2026-11-18。适用范围：全局 Chunk 双曲场（`.vcpwc`）。Tag 双曲场（`.vcpwf`）不在本次范围内。

## 1. 目标与现状

《双曲 Vexus 合龙交付说明》第 13 节规定：训练代内均值轴、对齐度分位点、节点半径、量化编码、导航图与方向目录冻结；新增或向量版本变化的 Chunk 不进入索引，每次查询逐条读取 SQL 原件，在冻结坐标下计算端点半径与精确双曲距离，再与图候选合并。该工作量随范围内累计增量数增长，没有固定上限。实测（3072 维）每条增量每次查询约 30 微秒且另需读取原件：增量 1102 条时单次查询约 35 毫秒，4096 条时约 127 毫秒，而无增量的图查询约 1.3–1.7 毫秒。

本设计在训练代几何保持冻结的前提下，把增量逐批转化为双曲资产：增量转化完成后，单次查询逐条精确评分的增量不超过 32 条，读取的原件数不超过精排预算加 32；积压超过单次转化上限或尾部文件已满时，超出部分在转化之前仍逐条精确评分，不丢结果。不变数据的查询结果与训练快照字节逐位不变；不新增自动训练触发器，不改变训练调度、训练快照格式与 N-API 签名。

## 2. 总体设计

| 层次 | 触发条件 | 行为 |
| --- | --- | --- |
| 待转化缓冲 | 范围内增量数不超过 32 | 与现有实现相同：逐条读取原件并精确评分 |
| 增量转化 | 图导航路径上范围内增量数超过 32 | 把增量转化为冻结坐标下的节点，追加到索引尾部；此后用热编码评分，不再逐条读取 |
| 全量训练 | 既有 1% Tag 阈值任务或手动全量训练 | 与现有实现相同；重建后尾部清空 |

“转化”对单个原件所做的事与全量构建相同：均值轴减除与归一化、量化为极坐标元数据与位平面、按冻结分位点取半径。区别只在于转化后的节点不连入导航图，而是组成一段平铺尾部。缓冲上限 32 的取法：使 32 条增量的精确评分耗时与一次无增量图查询相当（实测比值约 41，取最近的 2 的幂）。小范围（不超过 128 条）精确路径不变，也不触发转化。

## 3. 索引内核

`WarpedFieldIndex` 的节点分为两段：`[0, trained_len())` 为训练图节点，由 CSR 偏移数组界定；其后为转化尾部。

- `convert_batch`：输入一批（标识、冷读槽位、原件读取回调，回调同时返回该原件的冻结半径）。整批先编码后提交，任一条失败则索引不变。不读取、不修改导航图、入口、方向目录与距离表。
- 退役：某个未退役节点的标识再次被转化时（向量已变化），旧节点被标记为退役，不进入任何结果；位于图内时仍作为量化导航桥，与现有“已删除成员仅作导航桥”一致。任一标识始终只由一个未退役节点代表。
- 查询：导航仍只在训练图上进行，预算不变。束搜索结束后，尾部中未被排除的节点用阶段 0.5 的同一非对称代理距离评分并入候选池，再与图候选一起取前“精排预算”条读取原件计算精确距离。因此尾部节点的最终距离与现有增量端点评分逐位相同；不依赖导航可达性，不占用访问与展开预算；图候选与尾部节点合计读取的原件数不超过精排预算。入围精排仍由代理距离决定，与图候选相同。
- 存储：转化在既有数组上按精确容量原地追加，不把训练部分的热编码拷贝到第二个缓冲区；冷读槽位延续节点序号时不建立槽位表。
- 快照：`snapshot_bytes` 只写出训练图部分，训练代的索引载荷逐字节不变。尾部由 `converted_bytes` 单独导出，由 `restore_converted` 在训练快照之上按转化顺序重放，重放同时重现退役集合，并校验计数、长度、标识、槽位、半径范围、有限值与强位计数。

## 4. Chunk 场接线

- 版本：训练时的版本基线表不变；转化节点的版本记入独立的转化表。判断增量时先查转化表，再查训练基线。
- 触发：图导航路径上范围内增量数超过 32 时，取其中标识最小的至多 1024 条转化；超出部分本次仍逐条精确评分，由后续查询继续转化。转化前先按尾部文件的剩余容量（与训练快照相同的 512 MiB 上限）缩小批量，装不下的增量继续逐条精确评分，不因文件已满而失败。半径与现有增量端点半径为同一函数。
- 失败：原件损坏、非有限或零向量时与现有增量评分一样显式失败，场保持不变。尾部文件发布失败时丢弃内存中的场并返回错误，下一次查询从磁盘重新加载，内存状态不超前于已发布文件。
- 旧格式快照缺少版本基线时不转化，保持“全部实时成员保守评分”，直到下一次训练。
- 诊断新增转化节点数（尾部节点总数，含已被再次转化取代的）、退役节点数、本次转化条数与耗时、本次参与代理评分的尾部节点数。`nodes` 仍表示训练图节点数，`deltaChunks` 表示本次仍逐条精确评分的增量数，`coldReads` 计入本次转化读取的原件。

## 5. 快照与兼容

- 训练快照 `.vcpwc`：格式、内容与生命周期不变，转化不改写该文件。
- 尾部文件：与训练快照同目录、同前缀，扩展名 `.vcpwi`，内容为魔数 `VCPWI001`、头部（所依据训练快照的摘要、转化节点版本表）、尾部载荷与 SHA-256。每次转化后经既有的暂存、同步与替换流程发布，大小与累计转化量成正比（3072 维每条约 0.8 KB）。
- 加载：先按现有流程加载训练快照，再读取尾部文件。文件自身的 SHA-256 校验通过后，其记录的训练快照摘要与当前一致时重放，不一致视为过期并忽略；校验不通过、尾部内容非法或冷读槽位不等于节点序号时显式拒绝，由强制训练修复。训练发布新快照后删除尾部文件；删除失败不影响训练结果，遗留文件因摘要不一致被忽略。
- 发布只在进程内串行化，与训练快照相同。多个实例各自转化时后写覆盖先写，丢失的只是已转化状态，下次加载后重新转化，不影响结果；持有旧训练代的实例写出的尾部因摘要不一致被忽略。
- 降级：旧版本模块不读取 `.vcpwi`，继续使用 `.vcpwc` 并对全部累计增量逐条精确评分，结果语义正确；再次升级后，若其间未训练，尾部文件仍可使用。

## 6. 仍须全量训练的情形

转化不改变冻结坐标，新旧节点的距离在同一坐标系内，不引入新的几何偏差；冻结几何相对于“以当前全库重新训练”的偏差在现有实现中同样存在。

- 必须训练（现有规则）：模型、维度、径向规则或索引配置变化；旧格式快照缺少版本基线；快照损坏。
- 建议训练（据诊断字段判断，不自动触发）：转化节点数达到训练节点数（实测增量与训练量相等且分布有偏移时，与重新训练的 Top-10 重合度为 0.974，更高占比未测）；尾部代理评分的耗时超过一次图查询（每个尾部节点约 0.2 微秒，对应约 6000–8000 个）；退役节点占比较高（退役的训练节点仍占用访问与展开预算）。

## 7. 验证结果

测评方案在看到结果之前写定。独立真值为全部实时成员在冻结坐标下逐条计算的精确双曲距离。数据为真实 3072 维文本向量：语料甲 2204 条，语料乙 8038 条（另含短词向量），200 条未进入语料的真实查询向量；按时间顺序以前一部分训练、其余作为增量（增量与训练集分布不同的不利情形）。查询参数与 `search_warped` 的图导航路径相同。耗时为单线程、内存中的原件，不含 SQLite 读取，禁用 AVX-512。

召回率（K=10 / K=30）与单次查询中位耗时：

| 语料与增量 | 现有实现 | 增量转化 | 冻结几何全量重建 |
| --- | --- | --- | --- |
| 甲，增量 220（10%） | 1.000 / 1.000，7.9 ms | 1.000 / 0.997，1.4 ms | 1.000 / 0.996，1.3 ms |
| 甲，增量 441（20%） | 1.000 / 1.000，14.9 ms | 1.000 / 0.997，1.4 ms | 1.000 / 0.996，1.3 ms |
| 甲，增量 1102（50%） | 1.000 / 1.000，34.7 ms | 1.000 / 0.998，1.5 ms | 1.000 / 0.997，1.3 ms |
| 甲，随机顺序，增量 441 | 1.000 / 1.000，14.8 ms | 1.000 / 0.998，1.4 ms | 1.000 / 0.997，1.3 ms |
| 乙，增量 1608（20%） | 1.000 / 1.000，51.7 ms | 1.000 / 0.999，1.7 ms | 1.000 / 0.997，1.3 ms |

- 增量成员自身的召回率为 0.999–1.000。K=30 时与现有实现相差 0.001–0.003，来自转化节点与图候选共用同一精排预算（现有实现对增量不设预算）。
- 把访问与展开预算压到 128 / 32 作压力诊断时，增量转化与现有实现持平（甲 20%：0.998 / 0.990 对 0.998 / 0.993），高于全量重建（0.987 / 0.933），因为尾部不依赖导航。
- 规模趋势（合成数据，仅用于耗时与内存：真实向量两两插值加噪，训练 2 万条）：增量 64 / 256 / 1024 / 4096 条时，现有实现为 3.8 / 9.6 / 33.2 / 127.0 ms，增量转化为 1.6 / 1.6 / 1.7 / 2.4 ms（无增量 1.7 ms）。
- 转化 0.03–0.09 毫秒每条（不含读取原件）。转化不拷贝训练部分的热编码，批内瞬时堆增量与本批大小成正比：训练 2 万节点时，转化 64 条约 0.1 MB，转化 3072 条约 2.7 MB；同规模全量重建 6.4 秒、瞬时堆峰值 35.8 MB。数组原地增长时分配器内部是否搬移由平台决定，未计入。尾部每节点常驻约 0.82 KB。
- 冻结几何的偏差（冻结坐标真值与重新训练真值的 Top-10 重合度）：甲 10% / 20% / 50% 增量分别为 0.986 / 0.979 / 0.974，随机顺序 0.9995，乙 0.981。
- 向量更新：甲训练 1763 条后其中 441 条换为新向量，旧节点全部退役。默认预算下三组召回相同（1.000 / 0.997）；压到 128 / 32 时未更新成员的召回低于全量重建（K=10：0.905 对 0.964），与现有实现相同。
- 全量构建的快照在三组真实数据（407、2204、5834 个节点）上与改动前逐字节一致，构建耗时无可测差异。
- 测不出的：检索相关性（这里只有对精确双曲距离的召回）、服务器规模的真实语料、Linux 下的内存行为。

## 8. 曾评估但未采用：把增量连入导航图

先实现并测评了按构图终轮规则把新节点连入训练图的方案（束搜索取候选、四向罗盘剪枝、反向边超度数时重新剪枝、批末受保护连通性修复）：

- 默认预算下整体召回与全量重建相差不到 0.01，但 2 万条规模下新并入成员自身的召回只有 0.91–0.94（全量重建为 1.00），漏掉的全部是束搜索未访问到的节点。
- 原因是入边不对称：新节点只能把自己推荐给它选中的邻居，而全量构建里其他半径层的节点会按自己的前向选择指向它。新节点入边数的 10 分位只有 1（训练节点为 11），约 9% 在修复前入边为零。多做一遍细化、推荐给 32–256 个最近候选、强制最近邻保留入边，最多到 0.94。
- 每条 1.9–6.5 毫秒，是平铺尾部的 40–130 倍，并且要改写训练图与索引载荷格式。

它的优势只在尾部很大时的次线性查询，首批不采用。

## 9. 不在本次范围
