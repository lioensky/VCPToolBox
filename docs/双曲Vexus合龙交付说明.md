## 2. 生产配置

配置定义见 [PipelineConfig](../rust-vexus-lite/src/memo_pipeline.rs:108)。

全局默认仍为余弦。只有显式指定双曲路由才会加载或构建双曲场。

最简双曲配置为：
[{"config":{"tagRoutingMode":"warped_ags"}}](../rust-vexus-lite/src/memo_pipeline.rs:108)。

显式生产配置为：
[{"config":{"tagRoutingMode":"warped_ags","warpedPreset":"locked_2","warpedRadiusStrategy":"epa_guided"}}](../rust-vexus-lite/src/memo_pipeline.rs:108)。

| 配置字段 | 可用值与默认值 |
| --- | --- |
| [tagRoutingMode](../rust-vexus-lite/src/memo_pipeline.rs:138) | cosine（全局默认）、warped_ags |
| [warpedPreset](../rust-vexus-lite/src/memo_pipeline.rs:139) | locked_2（双曲默认）、locked_0 |
| [warpedRadiusStrategy](../rust-vexus-lite/src/memo_pipeline.rs:140) | epa_guided / EpaGuided（默认）；layer_schedule / LayerSchedule |

[生产预设](../rust-vexus-lite/src/warped_tag_field.rs:25)统一为：软化系数 0.15、喉部 1.5、角尺度 2.0、节点半径 0.35–0.65、自适应罗盘开启。默认预设的均值减除系数为 0.7；另一个 AB 预设为 1.0。

默认导航策略：

- 规模预算：不超过 4096 节点为 1024/256，不超过 16384 节点为 1536/384，更大为 2048/512；分别表示访问与展开上限。
- 非对称导航、束分数复用、兼容精排变换和解析包络均开启。
- 全局 64 方向目录与最多 512 个跨壳目录并集，4 个内壳入口加 12 个方向种子，最多 16 种子。
- [rerank_limit](../rust-vexus-lite/src/warped_tag_field.rs:251)固定为 64；金字塔单层结果数限制为 1–64。
- EPA 分析不可用但场仍可用时，半径计算沿用层级调度保底。

旧实验开关仍保留供受控诊断使用，但不建议作为生产接口使用。若主动关闭跨壳目录，应同时选择兼容的种子策略，避免非法组合。

## 3. 资产生命周期与增量窗口

[WarpedTagField::current()](../rust-vexus-lite/src/warped_tag_field.rs:203)只检查同一数据库身份、同一原生资产签名，以及[原生资产合法性校验](../rust-vexus-lite/src/rivermemo_topology_v3.rs:1116)。

沿用原生资产的现役规则：就绪状态、算法/格式匹配、完整依赖集合，以及当前依赖版本不得落后于发布基线。没有新增独立的训练阈值。

因此，在现有 1% 累积变动窗口内：

- 数据库代际和 Tag 事实计数前移不会单独使双曲场失效。
- 热请求不再额外校验 EPA 缓存摘要相等。
- 构建使用同模型最新就绪几何，不要求其事实计数等于实时计数；EPA 均值与所选几何签名必须一致。
- 增量任务清空内存后，下一次合法双曲请求会自动恢复快照。
- 精排遇到已删除 Tag 时仅跳过单个候选；损坏、非有限或零向量仍显式拒绝。
- 新原生资产发布后，新请求加载绑定新签名的场；已经持有旧场引用的请求保持其快照，不覆盖新活动资产。

现有训练调度及 1% 记账不变；本轮没有添加后台重训调度器。

## 4. 快照与冷启动

格式见[场级快照实现](../rust-vexus-lite/src/warped_field_snapshot.rs:8)及[索引编解码](../rust-vexus-lite/crates/vcp-tdb-index/src/index/quiver/hyperbolic/warped_snapshot.rs)。

格式包含：VCPWF001 魔数、两个 64 位小端长度、身份头、节点分位数组、索引载荷及整包 CRC32。索引载荷保存几何配置、位平面、极坐标元数据、均值轴、插值表、CSR、入口和方向目录，不保存原始向量矩阵。

加载校验包括：

- 魔数、长度上限、整包 CRC、维度、签名、预设和完整生产配置；
- 节点 ID、分位数与计数关系、有限浮点数、位平面尾位和强位计数；
- CSR 边界、度数、目标范围、目录范围及图连通性。

[旁路命名](../rust-vexus-lite/src/warped_field_snapshot.rs:27)以数据库文件名为前缀、资产签名的 SHA-256 为身份，并带预设后缀，扩展名为 .vcpwf，存放于数据库同目录。

原子发布复用[CheckpointStaging](../rust-vexus-lite/src/lib.rs:110)、文件同步和原子替换。快照是可重建派生文件，不修改数据库事实。

[冷加载流程](../rust-vexus-lite/src/warped_field_snapshot.rs:112)：先内存命中，再快照恢复，最后在当前读事务中流式构建并持久化。每个索引实例使用独立冷加载锁；同进程的临时文件发布也做串行保护。

仅基础就绪几何或 EPA 缓存尚未初始化时平滑回退余弦；坏向量、非法资产、数据库或持久化错误不会静默伪装成正常回退。

[原生资产清理任务](../rust-vexus-lite/src/knowledge_runtime.rs:2244)会回收不再对应就绪原生资产的受控快照，并清理受控命名的遗留临时文件。不匹配命名规则的邻接文件不会删除。

部署进程需要数据库同目录的旁路文件写权限。本轮单飞与发布锁是进程内机制，未宣称提供跨进程共享目录的分布式构建锁。

## 5. 预热接口

新增 [warmupWarpedTagField()](../rust-vexus-lite/src/warped_tag_field.rs:526)，不改变既有方法签名。

AB 脚本调用方式：
[await index.warmupWarpedTagField(dbPath, artifactSig, "locked_2")](../rust-vexus-lite/src/warped_tag_field.rs:526)。

省略第三个参数使用默认生产预设；传 locked_0 切换另一个 AB 预设。前两个参数分别为已由原生存储运行时注册的数据库路径和合法就绪资产签名。不要将预热接口当成数据库初始化或修复接口。

返回值为 JSON 文本，脚本解析后包含：

| 字段 | 含义 |
| --- | --- |
| [artifactSig / preset](../rust-vexus-lite/src/warped_tag_field.rs:512) | 实际绑定的原生资产及预设 |
| [source](../rust-vexus-lite/src/warped_tag_field.rs:512) | memory、snapshot 或 built |
| [nodes / hotBytes](../rust-vexus-lite/src/warped_tag_field.rs:513) | 节点数、受管载荷容量估算，不等于 RSS |
| [elapsedMs / buildMs](../rust-vexus-lite/src/warped_tag_field.rs:514) | 本次预热总耗时、驻留场记录的构建或恢复耗时 |

建议在服务器 AB 实验前显式预热两个预设，避免把首次构建成本混入热检索延迟。

## 8. 性能测量及边界

本机 Windows Release、合成夹具的测量：

- 40,452,064 字节、48,000 节点、3072 维索引载荷：内存解码中位数约 23.0 ms。
- 40,644,347 字节完整场级包：隔离运行时，文件读取、CRC、结构校验和资产验证总计中位数约 25.8 ms。
- 同一完整场级探针在全量并行测试竞争下约 51.6 ms，说明 50 ms 不是高争用下的硬实时上界。
- 真实增量夹具的热态路由检查：128 次，中位数 0.0090 ms，P95 0.0126 ms。

大快照探针使用合成连通环及合法重复编码，仅验证恢复成本与工程边界，不代表真实检索质量。文件读取测量使用操作系统已有页缓存，不代表断电后物理冷盘性能。上述场级恢复耗时不包含首次原生图解压与完整查询后续计算。

真实数据的首次无快照构建成本、服务器冷盘延迟和检索质量仍须在服务器 AB 实验室验收，不以这些合成测量替代。

## 10. 服务器验收顺序

1. 在目标平台构建并加载本轮原生模块，确认两个辅助接口存在。
2. 使用现有原生存储初始化流程注册测试数据库，取得合法就绪资产签名。
3. 显式预热生产预设及另一个 AB 预设，记录来源和内存统计。
4. 以默认余弦作为对照，以显式双曲配置作为实验组。
5. 在日常写入和个别删除后确认仍命中双曲路由；重启后确认从快照恢复。
6. 达到既有训练阈值后，核对新签名切换及旧旁路资产清理。
7. 用用户自有服务器测试集评估真实检索质量，不将本轮工程测试结果当作质量结论。

## 11. 追加交付：全局 Chunk 双曲与六轨 AB

### 11.1 范围与四条原生链路

本次按试验阶段要求新增全局 Chunk 双曲资产，并接入 LightMemo AB；同时保留外部 Rerank、Jev 两条对照，形成六轨展示。普通搜索默认行为不变。

| 原生轨道 | Chunk 候选来源 | Tag 观测 | 最终排序 |
| --- | --- | --- | --- |
| 原生 TDB ANN（兼容名称） | 现有 2-bit SM 无图扫描 | 不参与基线排序 | 候选原始向量余弦 |
| 双曲 Chunk ANN | 全局 Chunk 双曲资产的范围视图 | 不参与纯双曲排序 | 原件精确双曲距离升序；展示负距离 |
| 原生 RiverMemo V3/4 | 原 TDB 候选池 | 现有余弦 Tag 路由与原生 NNLS/统一观测 | 现有原生 RiverMemo 读出器重新评分 |
| 双曲 RiverMemo V5 实验轨 | 双曲 Chunk 候选池 | 生产预设的双曲 Tag 路由 | 同一个原生 RiverMemo 读出器重新评分 |

“V3/4”“V5”是此次实验链路标签，不是伪造新的读出算法版本。实际底层读出版本仍在[原生诊断展示](../Plugin/LightMemo/abDiagnostics.js:22)中独立列出。V5 不直接沿用双曲 ANN 排名，也没有将 RiverMemo 全部数学运算改写为双曲距离。

接线见[原生双候选池与双读出](../rust-vexus-lite/src/light_memo.rs:193)、[KBM 双观测准备与释放](../KnowledgeBaseManager.js:1783)和[六轨实验室](../Plugin/LightMemo/nativeQuery.js:119)。

### 11.2 全局几何与分库范围视图

[全局 Chunk 双曲封装](../rust-vexus-lite/src/warped_chunks.rs)从同数据库、同模型与维度的全局 Chunk 数据构建共享均值轴、节点半径、量化编码、导航图与方向目录。分库查询复用这些坐标，不重新计算一套分库几何。

本轮只在 LightMemo AB 原生数据面接通共享范围视图；未全局替换所有既有分库索引代理，也未将普通搜索切到双曲后端。

初始半径规则为[独立版本化实验规则](../rust-vexus-lite/src/warped_chunks.rs:10)：先求单位 Chunk 向量的全局均值，节点和查询的半径均为 0.35 加 0.30 倍的均值轴正交残差长度，范围 0.35–0.65。均值轴为零时取外壳半径。它不使用 Tag 入流质量，不能直接宣称具有 Tag 半径相同的语义或质量。

几何参数暂沿用软化 0.15、均值减除 0.7、喉部 1.5、角尺度 2.0、自适应罗盘；这些是本轮实验初值，不是经过真实 Chunk 盲测选择出的最优参数。

范围内不超过 128 条时，直接在共享几何上计算原件精确双曲距离；更大范围使用全局图导航。目录、女仆、时间、排除目录等结果边界沿用 LightMemo 范围判定。结果过滤不切断范围外节点的量化导航桥，但范围外正文不进入返回结果；全局构建本身仍会读取全库向量。因此这不是跨租户的严格物理隔离方案。

本轮未增加独立分库导航图或分库专用入口。强过滤下的召回和预算效率需要真实 AB 验证；不足 K 条时不使用 TDB 候选暗中补齐。

[Chunk 专用查询入口](../rust-vexus-lite/crates/vcp-tdb-index/src/index/quiver/hyperbolic/warped.rs:420)允许最多 2000 条有界候选；既有 Tag 入口的 64 条精排上限不变。LightMemo AB 每套召回仍默认 30、最多 100 条，最终 K 最多 100。

### 11.3 候选池、观测与 AB 含义

- 两套 Chunk 召回、正文读取和两次 RiverMemo 读出在同一 SQL 读事务中执行。
- 两条 Tag 观测分别准备并检查同一资产签名；它们不保证与 Chunk 阶段处于同一 SQL 快照，也不保证在日常写入期间形成跨阶段原子快照。资产签名变化会明确拒绝本次对照。
- 两条原生读出各使用自己的候选池，不让双曲独有候选污染旧轨；外部 Rerank、Jev 使用两池去重并集，最多 200 条，仍受各自配置限制。
- 这是端到端链路比较，不是固定共同池上的排序消融。候选 ID 交集不是召回率；未接入全库精确真值或人工相关性标注。
- 两套候选都保留原始查询余弦作为现有读出器的语义输入；负双曲距离只作为双曲 ANN 轨展示分数，不伪装成余弦或概率。
- 两个观测在原生任务入队时固定引用，完成或失败后由 KBM 释放；不把双曲观测当作旧观测使用。
- 初始化条件不足而回退余弦时，V5 明确显示不可用，不拿旧轨或余弦结果冒充。非法资产、覆盖不足、坏向量与 I/O 错误保持显式失败，可能使整次 AB 失败。

### 11.4 增量、快照与资源边界

本节首轮追加交付曾采用严格 Chunk 事实版本一致策略：事实前移后失效，下一次显式双曲 AB 重建。**该日常失效策略已被第 13 节替代**：[双曲资产生命周期](../rust-vexus-lite/src/warped_chunks.rs:134)现在保留训练代几何，Chunk 实时变动不再使其失效；达到既有 1% Tag 阈值后统一重建。

旁路文件使用数据库文件名前缀和模型摘要，扩展名为 .vcpwc；每模型使用固定目标文件，重建后原子替换，不按每个事实版本无限产生新文件。文件包含身份头、均值、索引载荷与 SHA-256 完整性摘要；校验尺寸、节点 ID、维度与完整配置，并复用底层图结构校验。

首次没有可用场快照的双曲 AB 仍可同步初始化并发布派生旁路文件，需要数据库同目录写权限；这与原 TDB 通过独立 checkpoint 发布快照的策略不同。首次构建及快照恢复成本会进入 Chunk 双曲诊断；第 13 节修订后，日常事实变化不再触发查询中的全量重建。比较热查询前应先执行一次相同范围的 AB 并观察下一次是否内存命中。

发布锁只覆盖同进程，不提供跨进程分布式构建锁。模型切换留下的其他模型旁路文件本轮不自动批量删除。损坏文件明确拒绝，不静默伪装成正常双曲命中。

## 12. 追加修订：一键全量训练与空候选诊断

### 12.1 手动训练现在确实包含双曲重建

此前面板“RiverAGS 全量重训练”只完成基础几何、原生图构建与发布；Tag 和 Chunk 双曲资产依靠之后的双曲请求懒加载。本轮将[手动全量训练](../TagMemoEngine.js:276)扩展为以下顺序：

1. 重算统一 AGS 几何。
2. 构建并发布原生 Memo 资产，完成既有伴随发布。
3. 强制重建绑定新资产签名的生产预设 Tag 双曲场。
4. 从当前数据库事实同步全局 Chunk 表，强制重建全局 Chunk 双曲资产。
5. 两个双曲阶段都成功后，才报告手动全量任务完成。

本节交付时，只有手动入口传递强制双曲准备选项。第 13 节已进一步将既有 1% Tag 自动阈值任务接入相同的两个双曲阶段；启动训练保持原策略。重复的手动任务仍按现有队列规则复用。

本轮手动重建只覆盖生产预设 locked_2，不额外重建另一个 AB 预设。Chunk 模型身份使用 KBM 配置中的检索模型标识，不误用 Tag 几何内部派生的模型签名。没有重新请求 Embedding，也没有借此重写 Chunk 或 Tag 数据库事实。

[管理面板](../AdminPanel-Vue/src/views/RagTuning.vue)增加两个双曲阶段的显示、节点数与来源；[任务状态类型](../AdminPanel-Vue/src/api/rag.ts)增加失败阶段及双曲结果。基础资产一旦发布，后续双曲失败不会回滚它：任务明确标记失败阶段及“基础资产已发布”，不会把部分成功显示为全部完成。

### 12.2 原生维护接口与强制语义

- [Tag 预热接口](../rust-vexus-lite/index.d.ts:386)增加可选第四个强制参数；既有三参数调用保持兼容。手动训练指定生产预设并传入强制参数，跳过内存与磁盘快照复用，重新构建并发布场。
- 新增[全局 Chunk 双曲维护接口](../rust-vexus-lite/index.d.ts:182)，接收模型标识及可选强制参数。它不需要查询向量或目录范围；强制模式从数据库同步新全局表，绕过旧 TDB 快照，再构建双曲资产，成功后替换驻留表。
- 维护操作仍受已注册存储、读事务、生命周期任务跟踪及发布门禁约束。没有绕过原生资产合法性检查，也没有把维护接口当作数据库初始化接口。
- 强制操作允许从数据库事实重建并原子替换损坏的受控派生快照；普通查询仍对损坏快照显式报错，不静默修复或伪装命中。
- Tag 强制发布遇到代际失效会报告失败，不能只返回一个未成为活动资产的构建结果。已持有旧场引用的请求仍可完成，不强制破坏其引用。
- 手动任务在基础计算前检查所需原生能力，并检查双曲返回结果是否确实强制构建。部署时须同时更新 JS、原生模块和面板资源，不能只替换面板文字。

## 13. 追加修订：实时 Chunk 索引与训练代几何解耦

### 13.1 更新边界

本轮明确拆开三种生命周期：

| 对象 | 当前策略 |
| --- | --- |
| Chunk 运行期索引、成员与范围元数据 | 继续从 SQL 实时同步新增、修改、删除，不等待训练 |
| 普通 Chunk 磁盘索引 | 保留既有 A/B 槽、SQL 背书与累计差异门禁，不因双曲训练额外发布 |
| 全局双曲数学几何 | 保留当前训练代的均值轴、节点半径、量化图及方向目录；达到既有 1% Tag 变动阈值后统一重建 |

[实时同步](../rust-vexus-lite/src/global_chunks.rs:96)不再因为全局 Chunk 事实计数变化而清空双曲场；[内存压缩](../rust-vexus-lite/src/global_chunks.rs:84)也保留该训练代。日常写入后，下一次双曲 AB 不会再因事实版本前移而全量重建及重写场快照。这不是将全量重建搬到后台，也没有另设 Chunk 的 1% 阈值。

[既有 Tag 阈值任务](../TagMemoEngine.js:455)现在按“统一几何 → 原生资产及伴随发布 → Tag 双曲场 → Chunk 双曲场”的顺序执行，等待两个双曲阶段完成。仍使用原生持久化的不同变动 Tag 计数、原训练基线及既有固定延迟；10 万 Tag 基线的阈值为 1000 个变动 Tag。手动全量训练继续显式重建；启动训练未新增强制双曲阶段。基础资产已发布但双曲阶段失败时，继续明确报告部分发布及失败阶段，不宣称整轮原子成功。

### 13.2 代际窗口内的新内容与删除

[双曲查询](../rust-vexus-lite/src/warped_chunks.rs:217)以实时 Chunk 成员及最新范围元数据为准：

- 不变向量继续使用当前代全局图，已删除或范围外成员不进入结果，旧图节点仅可保留为量化导航桥。
- 新增或向量版本变化的 Chunk 不使用旧图端点评分；读取其当前 SQL 原件，在冻结均值轴下计算端点半径和精确双曲距离，再与旧图候选合并、统一截断。
- 小范围仍直接精确评分，但遍历的是当前有效成员，因此也能立即包含新日记。
- 仅正文、时间或目录元数据变化时更新范围判断，不重算整场几何。
- 新端点计算复用[当前代距离接口](../rust-vexus-lite/crates/vcp-tdb-index/src/index/quiver/hyperbolic/warped.rs:308)，不插图、不重建方向目录、不常驻全库原始浮点向量。

增量原件逐条读取、候选结果有界；**增量评分工作量随范围内累计向量增量数增长，并非固定冷读取上限**。如果大量 Chunk 写入长期不触发 Tag 阈值，双曲查询的增量开销会增加；本轮不因此暗中增加第二个全量重训触发器，也不拿余弦候选冒充双曲结果。

### 14.2 数学与防滥用边界

- 残差半径采用审查提出的闭式推进：原位置加上剩余径向空间乘以“1 减残差能量比的 0.35 次方”，再乘 0.75。残差比取当前层输入能量除以原查询能量；非有限值保守按 1 处理。诊断增加每次尝试的输入残差能量比。
- 数值纠正：原半径 0.450、残差能量比 0.149 时，该公式给出约 **0.499**，不是 0.545；不能承诺该公式必然进入 0.55–0.62 外壳。
- 软场匹配使用余弦阈值 0.82，超过阈值的折现为 0.75 乘归一化阈上相似度；阈值处折现为零。选择最高相似活跃河网节点，势能及域接触均按折现继承。精确 ID 势能优先，不能被语义替代覆盖。
- 意图覆盖使用原始 Hop-0 节点能量，按种子 ID 去重；强语义阈值为 0.72。精确接触优先，每个候选 Tag 与种子最多各认领一次，防止一个泛义词重复解释多个种子。覆盖因子为命中能量与“0.55 倍总能量、最大种子能量两者最大值”之比的平方根，限制到 0.35–1；无有效种子时不凭空惩罚。
- 观测输出增加意图覆盖因子、命中种子能量、总种子能量及软场接触数量，供 AB 回执核验。既有 0.03 场奖励上限、图奖励预算、权限和观测代际检查不变。
- Chunk 常规精排预算为请求数的两倍，限制到 64–256；再确保预算不小于请求数，以兼容既有最高 2000 条的原生接口。请求 30 条时预算为 64，不宣称额外冷读耗时必然小于 0.5 ms。
- Chunk 新规则为训练单位向量与全库均值轴的绝对对齐度，保存 64 个经验分位点，半径为 0.35 加 0.30 乘“1 减对齐度分位数”的 1.10 次方。构图、查询、小范围精排及实时增量端点统一复用训练代映射。重复对齐度取分位中点，零均值/单节点等退化数据不按 ID 人工制造径向差异。64 点插值及非线性指数不意味着真实语料一定严格均匀铺满各壳。

## 17. 内存一期：旧 Tag 路由休眠与 Chunk 范围缓存冷热切换

### 17.1 原因与本轮范围

V5 的双曲 Tag 场不会自动替代并释放旧余弦 Tag 路由。旧流程在启动恢复、摄取差分维护和快照发布后仍可能持有旧载荷；与此同时，生产请求还会激活双曲 Tag 场、全局 Chunk 双曲图及实时范围元数据。因此“采用量化双曲索引”不能直接推导整个进程 RSS 一定低于 V4。

本轮定位到上述重复驻留机制，但未在生产进程中分解用户观察到的 100–200 MB 增量，也未证明检索卡顿的根因。受管载荷、线程工作区、SQL 页缓存和分配器保留量不能混同为 RSS。

### 17.2 Tag 行为

- 生产启动显式选择旧路由懒加载，校验 SQL 有效向量并保留逻辑计数，不创建完整旧检索载荷。
- 显式余弦搜索、旧轨观测以及既有双曲初始化余弦回退，在需要时从当前 SQL 读事务恢复旧路由。
- 生产双曲 Tag 命中时释放旧路由，不清空共享数学资产和在途观测。旧轨最后一次使用后若没有后续双曲请求，本轮没有新增独立定时回收器。
- 冷态摄取不保留旧路由增量向量；现阶段通过流式扫描 SQL 有效向量刷新逻辑计数，会产生随 Tag 总数增长的读取成本，不宣称该步骤恒定耗时。
- 快照发布保留原冷热状态；后台压缩发布前检查驻留状态，避免把已休眠载荷重新放回。
- SQL 原始向量、向量版本、累计差异、A/B 基线及既有发布门禁保留。双曲场不是事实数据库，也不能替代这些持久化信息。
- 兼容恢复接口新增可选懒加载参数；省略时仍使用既有热恢复行为。

Tag 双曲仍遵循原训练代际，没有加入新 Tag 实时感应，没有修改 1% 自动训练门槛。十万级 Tag 双曲预计算降本及提高训练频率属于二期。

### 17.3 Chunk 行为与限制

当前实现是范围元数据缓存优化，不是新增或卸载一套分区向量索引：

- 全局有效成员头、向量版本、文件身份及目录名仍保留；全局双曲图和冻结训练代不因目录切换重建。
- 首行文本及日期按当前请求涉及的目录集合加载；切换范围时释放不再使用的目录文本缓存。多目录请求同时保留所需目录，全库请求可能加载全部范围文本。
- LightMemo 与原生联合检索均在现有 SQL 快照和全局表锁内完成激活及检索；不会在请求使用中卸载缓存。
- 新增和变更 Chunk 仍在冻结几何下精确评分并合并；删除与权限、时间、女仆首行条件不放宽。
- 旧 AB 全局量化载荷仍按需启用；返回生产查询后释放。原闲置全局表淘汰机制保留。
- 运行时统计新增分区数量和首行文本容量；此容量不含全局成员头、图载荷、分配器或 RSS。
- 当前没有独立分区 LRU、容量预算或分区 TTL；采用当前请求工作集切换策略。频繁交替目录存在重新读取文本的成本，尚未进行真实规模性能验收。
