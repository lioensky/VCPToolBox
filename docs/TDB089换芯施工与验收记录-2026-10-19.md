# TDB 0.8.9 换芯施工与验收记录

日期：2026-10-19（北京时间）

## 当前交付边界

Rust 热检索后端已改为移植的 TDB QuIVer，USearch 依赖已移除。主 crate 与检索子 crate 静态链接到同一个 N-API 原生模块。

当前完成的是源码实现、隔离回归以及正式 Windows x64 产物编译，**不是试验服务器切换完成，也不是完整生产质量验收通过**。按主人追加要求，先封存旧产物，再替换本工作区默认 Windows 原生模块；没有启动服务或迁移真实数据库，没有请求新的 embedding。LightMemo 尚未施工，冷库入口不改。

施工基线见[原施工图](TDB089换芯与LightMemo原生化施工图.md)。

## 已实现

- 独立 edition 2024 检索子 crate；主 crate 保持 edition 2021。
- Rust 工具链固定为 1.89.0：上游使用的 AVX-512 intrinsics 在本机 1.88 上不能稳定编译。未使用本机专属 CPU 编译选项，未全局启用 AVX-512。
- 小作用域精确扫描；达到 2048 条后构建 QuIVer，默认搜索预算 128、精排预算 64，均随请求数量提高下限。
- 原件精排使用 mmap 或尚未压实的增量 f32；不把量化重建向量送入数学管线。
- SQL 冻结读事务流式构建派生资产，不收集全库 f32 矩阵到堆。
- 增删改整批预校验、单写锁发布，维护内容代际。
- 摄取、删除与 Tag 一致性修复后的私有索引维护；单飞执行，复用受跟踪任务，不创建游离线程。
- 冷恢复重放后若达到维护条件，在发布前从 SQL 流式压实为私有 mmap 资产，不依赖下一次摄取；已覆盖从单条基线增长到 2048 条的恢复回归。
- 恢复预计原件差分达到 16 MiB 时，不先逐条积累到增量堆区，直接从 SQL 流式重建；3072D 从单条基线增长到 1400 条的专项回归通过。
- 私有维护达到建图、脏比例或 16 MiB 增量条件后重建；不受公开 checkpoint 持久化策略限制。
- 大量删除使活跃数量降至建图阈值以下时，已有脏图仍触发维护，压实后退回平扫；对应回归通过。
- 双槽发布仍按临时文件、同步、文件发布、SQL 背书顺序执行。
- SQL 背书增加格式版本、文件长度、CRC 与内容摘要；低变化量跳过前也验证资产。
- 旧格式不解析，隔离为退休资产后从 SQL 原件恢复；损坏资产隔离后重建。
- Tag 金字塔、融合、AGS 与双场取数接回 SQL；删除无调用方的旧索引取数导出。
- 对外检索分数为原件余弦；零余弦不再作为缺省分数哨兵。
- JS 生产索引路径改为新派生格式，并通过能力标识拒绝旧原生模块。
- 内存诊断区分热堆估计、映射文件长度和墓碑；映射长度不等于 RSS。

## 实际文件格式与施工图差异

当前版本的头部是 **192 字节**，不是原草图中的 128 字节；草图字段无法装入 128 字节。

资产包含身份头、紧凑 ID 表、64 字节对齐的小端 f32 原件镜像、图块、默认 SM 状态块及 CRC 尾部。头魔数为 VCPVEC01，实际尾魔数为 VCPVCEND。默认 SM 冷加载不重新扫描全部 f32。

SQL 是真源；公开双槽资产和私有 mmap 维护资产均可从 SQL 重建。私有资产不写公开 SQL 背书，随拥有者释放映射后清理。

## 连通性防护及适用范围

未修改的上游构图主体在大量量化签名碰撞下会出现入口不可达节点。独立诊断直接调用原始构图，绕过 SQL、mmap、冷源包装和 SM 准备。

2048 条数据，每组重复三次：

| 维度与分布 | 独立签名 | 入口可达 |
|---|---:|---|
| 3D 随机 | 48 | 797 / 1015 / 825 |
| 3D 密集模式 | 12 | 614 / 487 / 611 |
| 65D 随机 | 2048 | 三次均 2048 |
| 768D 随机 | 2048 | 三次均 2048 |
| 3072D 随机 | 2048 | 三次均 2048 |
| 3072D 重复三维模式 | 12 | 513 / 492 / 458 |

不能由低维反例推断正常 3072D embedding 普遍严重断连。具体剪枝触发点仍未定位。

当前防护仅在检测到断连时保留原邻边，并利用空余邻接容量追加确定性有向环，随后再次检查可达性；全连通图不追加环边。可达性不等于有限预算召回保证。

### 固定合成召回实验

2304 条单位随机向量、32 个查询、Top-10，以暴力余弦为真值。旧后端来自未覆盖的默认原生模块；新后端来自隔离 release。

| 维度 | 旧 Recall@10 | 新 Recall@10 | 构建 ms | 查询 P50 ms | 样本最大延迟 ms |
|---|---:|---:|---:|---:|---:|
| 65 | 0.971875 | 0.975 | 34.0122 | 0.1089 | 0.2269 |
| 3072 | 0.63125 | 0.89375 | 180.9824 | 0.6430 | 1.0669 |

这里只是单机合成样本，32 个延迟样本不足以可靠估计生产 P99。并行构图可能带来小幅召回波动；此前同配置 3072D 单次为 0.896875，上表记录最新隔离产物复测。不是日记、Tag、金字塔真实语料的分层验收。

质量入口现检查旧、新模块的后端能力，禁止拿 TDB 与自身冒充新旧比较；生产切换后须通过 TDB_BASELINE_BINDING 指定保留的旧模块，TDB_NATIVE_BINDING 可指定新模块路径。

一次验证命令误用环境变量，导致两次均运行 65D；该输出未算作 3072D 证据，随后用正确配置补跑。

最新回退实验统一设置 TRIVIUM_NO_AVX512=1，含 SM 计数和点积的分发开关修复后，3072D Recall@10 为 0.9（旧后端 0.63125），构建 207.8809 ms，查询 P50 为 0.6536 ms，样本最大延迟 0.8444 ms。此前仅 BQ/余弦遵循开关的那轮不作为完整回退验证证据。测试未模拟操作系统、缓存层次或后端机器实际频率。

### 服务器操作顺序

1. 停止服务并确认没有其他进程持有知识库。完整备份真实 SQL 数据库、可能存在的 WAL/SHM、旧索引、旧模块与对应代码；复制运行中的 SQLite 单文件不构成可靠备份。
2. 同步本轮源码、配置模板与匹配的 Windows 新模块，不只拷贝模块。不要解除旧离线脚本裸写门禁。
3. 对照上述新模块哈希；进程重新启动后确认能力列表含 index.tdb-vec.v1 与 index.cosine-score.v1。
4. 首次恢复应从 SQL 原件构建新格式。观察退休旧资产、恢复条数、无重新 embedding 请求、scope ready、checkpoint 双槽发布及背书。
5. 固定真实查询集分别验证全局 Tag、日记 Chunk、金字塔及 RiverMemo 最终输出；记录旧新结果、冷启动时间、RSS 与查询延迟。
6. 验证新增、更新、删除、Tag 一致性修复、正常关闭及再次启动。人为损坏实验只针对另存的试验库，不在唯一真实库上操作。
7. 真实验收完成前保持 LightMemo 和冷库入口不变；本轮不声称既有 LightMemo 热检索问题已解决。

质量实验在默认模块换新后会拒绝默认基线，需显式指定 TDB_BASELINE_BINDING 为封存旧模块，TDB_NATIVE_BINDING 为正式新模块。隔离验收默认仍指向隔离目录；服务器验证正式产物时同样显式设置 TDB_NATIVE_BINDING。

## 运维限制

旧离线脚本保留禁止裸写的门禁，不能解除后继续操作旧格式。生产重建必须通过 Rust Runtime 的恢复与 checkpoint 链路；不得重新引入 JS SQLite 写连接。

回退不能只覆盖旧原生模块：旧模块不认识新格式。需停服并使用备份代码、模块及匹配的资产恢复策略；SQL 原件必须保留。
