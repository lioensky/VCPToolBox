## 2. 冻结输入与键映射

| 输入 | 读取路径和契约 |
|---|---|
| Chunk 场与布局 | 显式指定只读 `.vcpwc`，通过 `Plugin/WarpedFieldAtlas/lib/snapshot.js` 的 `parseChunkField` 验签；清单记录完整 SHA-256，不用运行时的“按修改时间选最新”或短校验标识。保存 `index.ids`、`radius`、点级 CSR、入口与地标。由 `lib/layout.js` 的 `computeLayout` 直接重算并冻结 FP32 角度，不经过舍入的布局缓存、UI 数据或展开动画。 |
| 被检索向量 | 按快照下标 `i → index.ids[i] → chunks.id`，从 `knowledge_base.sqlite` 一致副本用 `lib/library.js` 的 `vectorReader('chunks')` 取原始 FP32。数据库行号、CSR 下标和稳定 ID 是三种不同的键。 |
| 真实探针 | 从 `Plugin/RAGDiaryPlugin/folding_store.db` 的 `folding_entries.vector` 取逐 content 净化后的向量。直接遍历合格记录，不截取 UI 的最近消息列表，不重新 embedding。记录来源、`content_hash`、时间、向量哈希及模型身份依据；正文不进入报告。 |

**导出验收：** SQLite 使用一致性备份或已封存副本，不单独拷贝仍有活动 WAL 的主文件。核对模型来源，不能以维数相同代替模型相同。校验 ID 唯一、每个快照 ID 恰有一份原向量、维数为 3072、所有坐标和向量值有限；校验 CSR 偏移单调、首尾正确、边和地标下标均在范围内。遇到缺行、坏维数或坏边即报错，不补零、不静默删点。点数、片数取自导出，不硬编码历史盘面规模。

**查询拆分：** 对 content 与向量去重，排查与构图库重合；按时间先后划分 `Q_dev` 和封存的 `Q_eval`，不得让重复项跨集合。优先采用能证明未参与构图的真实查询；来源不明的探针单列，不计入严格库外结果。清单记录各步保留与剔除数量、快照与数组哈希、布局版本、稳定 ID 顺序及划分规则。相同输入重跑应复现片成员和两个查询集合。

## 3. 分片、色窗与独立真值

1. **真盘。** 从布局固定接缝按 `(θ, id)` 排序，每 64 点切一楔；楔内按 `(r, id)` 排序，每 16 点一片，尾片按实。切分只看坐标，ID 只决平局，不看高维向量或图社区标签。记录每片按盘面接缝定义的角跨度 `Δθ_T`，用于定位可能跨空白间隔的片，不据此事后删片。
2. **乱序盘。** 至少五张独立全局置换盘（首轮种子 1–5）；记录 PRNG、置换算法和片成员哈希。所有盘共用真盘的片容量序列、原向量、查询和逐维分位切点，分别连续打包，避免给乱序组额外制造随机回表。
3. **曝光真值。** 对每维闭区间 `W[d]=[lo[d],hi[d]]`，标量参考实现直接计 `S(q,x)=Σ_d 1[lo[d] ≤ x[d] ≤ hi[d]]`。按分数降序、稳定 ID 升序取前 k，要求 `1 ≤ k ≤ N`。每个查询的两端点只生成一次，所有路径共享。不调用摘要计票函数生成参考答案。
4. **预注册。** 在开发集确定色窗规则、端点数值精度、k、主配置、比较方法与计时条件；在打开留出集前写入清单。8 桶切点只用建库样本，桶左闭右开、覆盖全部有限输入，重复切点形成空桶。位图查询掩码标记与闭色窗相交的所有非空区间桶。亮桶率是测量值，不是调到指定范围才准报告的指标。
5. **最小回归集。** 覆盖原值等于切点且等于窗端点、重复切点、同分不同 ID、同一维跨多桶仍只计一票、尾片、`k=1` 和 `k=N`。另造两点各中不同维的例子，防止把多点拼出的上界当成单点真值。

## 4. P0：在写 SIMD 前裁决载荷账

每种分片各建两套摘要：FP32 Exact AABB（每维最小/最大值），以及逐维 8 桶占用位图（每维一字节）。二者都须外包片内全部原值。对每个查询和非空片计算：

- `U_T`：摘要与色窗相交的维数；`E_T`：片内至少存在一个原值落窗的维数；`M_T`：片内最高的单点精确分。逐项断言 `U_T ≥ E_T ≥ M_T`。
- `Δenv = U_T − E_T`，`Δchimera = E_T − M_T`。两项之和必须等于 `U_T − M_T`。相同片与查询换摘要时，`Δchimera` 不变。
- 取平扫最终门槛 `K*=(S_k,−id_k)`，乐观键 `B_T=(U_T,−min_id(T))`。两者均按字典序比较；实现直接用 ID 升序比较，避免无符号取负。离线可排除集合为 `B_T < K*`。
- 计算 `可省原始字节 = Σ_{可排除片} |T| × D × 4`，再减去全体已扫摘要字节得到净节省。尾片按实，不以片数百分比替代载荷百分比。D=3072 时 AABB 为 24 KiB/片，位图为 3 KiB/片；容量 16 的满片原始载荷为 192 KiB。

**输出：** 保留逐查询记录和各置换结果；汇总虚高两项的均值与分位数、亮桶率、角跨度、跳读原始字节、摘要字节和净节省。真盘对乱序做同查询配对比较；不把同一查询下的几百个片当成几百个独立查询。

**决策：** 若某配置在最终门槛下仍不能净省逻辑字节，则当前“全扫摘要、整片验证”方案在该口径下不能靠调整开片顺序回本。先定位包络或分片问题，不优先写该配置的 AVX2 路径。过线仅取得计时资格，不代表已加速；不过线也不否定不必全扫摘要的 Stage 1。

## 5. Stage 0：用在线门槛交付精确结果

堆未满 k 个已验证点时不得剪枝；堆满后仅凭 `B_T < K_current` 排除该片。所有未排除片都必须验证。比较连续内存平扫、存储序扫描、全摘要按完整 `B_T` 降序开片三条路径。仅对**无种子、整片验证、完整键降序**的路径逐查询断言：

```
online_opened_tile_ids == { T | B_T >= K* }
indexed_topk_pairs     == scalar_reference_topk_pairs
```

`K*` 与 Slack 真值只用于独立诊断和验算，不提供给在线算法。平扫与片内验证共用同一个优化精确计票核；若启用逐点剩余维数早停，两侧同口径。位图按“每维交集非零”计票，不对交集直接做位级 popcount。

在同一机器、相同线程与预先说明的冷/热缓存条件下交错运行各组。完整计入端点/掩码准备、摘要扫描、排序、堆维护、载荷验证和最终输出；报告样本数、P50/P95/P99 与逻辑字节。逻辑字节不是实测 DRAM 流量。真盘优于随机分组不单独证明二维布局独有；净字节节省不替代挂钟结果。

## 6. Stage 1：同预算测导航，不拿折痕当排除证明

固定点、片成员、摘要及曝光真值。将点级边映射为无向片边，去自环、合并重复边，另记跨片边数；报告度数、连通分量和入口覆盖率。入口由冻结入口/地标映射去重，选择规则与必要的截断在开发集冻结。对照重连保持每片度数和连通分量条件，记录种子与实际换边数量。

令 `h_T[d]` 为当前查询在该片的逐维摘要相交指示。3072 位占 384 B。折痕 `Ξij = popcount(h_i XOR h_j)`；若已求交集亮维数 `Γij`，则 `Ξij = U_i + U_j − 2Γij`，不用重复归约。临时位流的生成、读取和缓存照实计时。

| 邻接图 | 仅目标片 `U_j` | `U_j − β·Ξij` |
|---|---|---|
| 真实片图 | 基础导航 | 测折痕增量 |
| 保度重连图 | 重连基础导航 | 测折痕与边位置的关系 |

四组使用相同种子片、摘要探查预算、原始点精验预算与平局规则。种子同价：首次读取某片的 `U` 或 `h` 就扣一次不同片探查数；原始点精验另扣。未探查邻居按预定、与查询无关的次序枚举，不允许先免费看遍邻居再选。`β`、预算、前沿重复更新及预算不足一整片时的处理均在开发集冻结。

`expand_neighbors(T)` 与 `verify_payload(T)` 分离：桥片本身可以不精验，不代表不能经它发现另一座亮岛。用暗桥双岛合成例验证两种动作的独立性，记录第二岛首中时的探查步数，未找到亦计入。真实查询报告配对 Recall@k、实际探查数、精验点数与端到端延迟。预算耗尽只报告近似结果；精确模式须验证剩余候选或提供覆盖全部未验证片的安全上界证书。

## 7. 交付顺序与停止条件

1. **冻结包与探针清单**：提交导出程序和清单格式；真实输入保留在 Git 外。对齐、来源或可重放校验失败，停止进入盲测。
2. **标量真值与回归**：先通过小型可手算用例，再处理真实探针。任何 Top-k 不一致先修正确性，不发布该轮性能结论。
3. **P0 报告**：用同一批查询交付真盘与五张乱序盘、两种摘要的逐查询载荷与虚高分解。这是首轮评审点。
4. **后续分别判决**：按 P0 报告决定 Stage 0 优化投入；Stage 1 独立做双预算消融。留出集揭盲后若修改参数，后续结果标为探索性或另设新留出集。任何阶段不以语义替代 AGS 或生产上线作为本轮结论。
