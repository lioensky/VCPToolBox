# JEV 语义工具调用实验：开发说明与研究声明

> **状态：前沿实验 / Experimental**
>
> **稳定性：不保证**
>
> **兼容性：不保证**
>
> **生产可用性：不保证**
>
> **未来架构：可能发生完全、激进且不兼容的重构**

---

## 1. 项目声明

JEV 语义工具调用器是 VCPToolBox 中的一项前沿实验。

它不是现有工具栈的稳定替代品，也不是已经完成设计定型的公共协议。目前实现的主要目的，是验证以下假设：

> 大模型不必阅读、记忆并生成每个插件的完整参数协议，也可以通过简短、连续的自然语言表达工具意图；系统再通过确定性模板与 Jev 有限决策，将其编译成安全、合法的真实插件调用。

本功能目前：

- 不保证稳定可用；
- 不保证覆盖所有输入表达；
- 不保证所有已配置插件均可正常执行；
- 不保证当前自然语言协议长期保持兼容；
- 不保证当前 JSON 配置结构长期保持兼容；
- 不保证当前模块接口长期保持兼容；
- 不保证后续不会进行完全、激进、不兼容的重构；
- 不建议作为关键生产流程的唯一工具调用路径；
- 不应移除现有工具说明和传统 VCP 调用能力作为回退手段。

尽管如此，这项实验被视为 VCPToolBox 工具系统的一项重要开拓性研究。

如果实验能够证明其在正确率、上下文占用、工具可发现性、安全性和维护成本方面具有持续优势，它将逐步扩大能力范围，并可能逐渐替代现有依赖完整插件提示词的工具调用栈。

---

## 2. 研究背景

传统工具调用通常要求主模型理解：

- 工具名称；
- 插件职责；
- 参数名称；
- 参数类型；
- 必填字段；
- 可选字段；
- 枚举值；
- 默认值；
- 字段间约束；
- 工具间能力差异；
- 完整调用格式。

当插件数量持续增加时，工具说明会占用大量上下文。即使使用动态折叠、语义检索和渐进披露，主模型最终仍需要理解具体插件协议，并自行生成参数。

JEV 语义工具调用实验尝试把问题重新划分：

```text
主模型负责表达意图
    ↓
语义标记负责提供稳定边界
    ↓
确定性模板负责绝大多数参数装配
    ↓
Jev 只处理无法由规则确定的有限选择
    ↓
真实插件继续由既有 PluginManager 执行
```

其核心并不是“让 Jev 自由生成工具调用”，而是：

> 在人工维护的安全能力空间内，用极少量结构化决策补足确定性模板无法覆盖的语义间隙。

## 3. 核心设计原则

### 3.1 自然语言优先

JEV 调用应保持完整自然语言句法，而不是退化成参数 Token 堆叠。

推荐：

```text
请使用 {联网搜索} 中的 '谷歌学术'，在[2024年至今]的范围内搜索【大语言模型在临床诊断中的应用】。
```

不推荐：

```text
{联网搜索} '谷歌学术' 【大语言模型在临床诊断中的应用】[2024年至今]
```

两者都可能被解析，但完整句法更有利于：

- 保持模型潜空间中的语义连续性；
- 保留“使用、从、搜索、参考、修改、生成”等关系；
- 降低主次范围错配概率；
- 降低模型漏写动作关系的概率；
- 为后续语义决策保留更完整的上下文。

### 3.2 标记只作为语义锚点

当前约定：

| 标记 | 语义 |
|---|---|
| `{能力}` | 能力目录 |
| `'工具'` | 可选的显式工具选择 |
| `【主要内容】` | 主要搜索内容、视频地址、生图或修图指令 |
| `[约束]` | 次要范围、时间、地区、尺寸、画幅、截图要求或图片 URL |

标记负责提供可靠的数据边界，标记外文本仍然保留为自然语言关系上下文。

### 3.3 确定性优先

决策优先级为：

```text
显式输入
    >
确定性解析与规则
    >
Jev 有限选择
    >
安全默认值
```

以下情况不应调用 Jev：

- 用户明确指定工具；
- 能力目录存在默认工具；
- 参数可以由固定模板填写；
- 年份可以用正则提取；
- URL 可以确定性识别；
- 图片数量可以确定生成、修图或合成模式；
- 横图、竖图、方图可以由规则映射；
- VSearch 模式固定为 grounding；
- Tavily 搜索深度固定为 advanced；
- B站输入可由 URL、BV号或 av号判定为内容获取；
- AnySearch 的垂直领域可由明确关键词判定。

### 3.4 Jev 只处理有限决策

Jev 不生成自由文本参数，也不直接编写插件调用 JSON。

当前仅在以下场景中使用 Jev：

1. AnySearch 具有模糊专业范围，但无法由明确规则确定子领域；
2. 图片用途或构图要求比较模糊，无法由规则映射到目标插件支持的具体尺寸。

Jev 的输出必须属于预先定义的候选集合。

低置信度、无效响应、超时、网络失败或未配置 Jev 时，系统应回退到安全默认模板，而不是猜测危险参数。

### 3.5 能力白名单与真实插件隔离

JEV 可见能力来自独立实验配置，而不是自动镜像所有插件 manifest。

这样可以：

- 限制 Jev 可见的工具范围；
- 隐藏危险可选参数；
- 防止新插件自动进入语义调用空间；
- 保持实验能力树可审计；
- 为每个工具提供受控模板；
- 在真实插件协议变化时由适配层吸收差异。

### 3.6 不绕过现有执行链

JEV 只负责把虚拟调用展开为真实工具调用。

真实调用仍然进入现有工具执行链，因此继续保留：

- 插件存在性检查；
- 验证码校验；
- 人工审核；
- 工具调用记录；
- 工具生命周期通知；
- 结果隐私过滤；
- 本地与分布式插件桥；
- 文件 URL 透明处理；
- 插件超时与错误处理。

## 4. 当前实验范围

### 4.1 联网搜索

当前白名单包括：

| 模式 | 真实插件 | 固定策略 |
|---|---|---|
| 默认联网搜索 | VSearch | 固定 `grounding` |
| 谷歌搜索 | SerpSearch | 固定 `google_search` |
| 谷歌学术 | SerpSearch | 固定 `google_scholar_search` |
| Tavily | TavilySearch | 固定 `advanced` |
| AnySearch | AnySearch | 模板优先，必要时由 Jev 选择子领域 |
| B站搜索 | BilibiliFetch | 固定搜索模板 |
| B站获取 | BilibiliFetch | 默认获取字幕、评论、弹幕和高能进度 |

B站搜索和获取都属于联网搜索目录。

系统根据主要输入进行确定性选择：

- 视频 URL、短链接、BV号或 av号：内容获取；
- 普通关键词：B站搜索。

B站搜索类型通过 `[]` 确定性映射，不需要调用 Jev：

- `[搜视频]`、`[视频]`：映射为 `search_type=video`；
- `[搜UP主]`、`[UP主]`、`[用户]`、`[作者]`、`[博主]`：映射为 `search_type=bili_user`；
- 未指定搜索类型：默认映射为 `search_type=video`。

推荐保持完整自然语言句式：

```text
请使用 {联网搜索} 中的 'B站搜索'，在B站上[搜视频]，查找【Python入门教程】。
```

```text
请使用 {联网搜索} 中的 'B站搜索'，在B站上[搜UP主]，查找【影视飓风】。
```

截图要求同样通过 `[]` 表达，例如：

```text
请使用 {联网搜索} 中的 'B站获取'，获取视频【BV1xxxxxxxxx】的字幕、评论和弹幕，并在[截图 30,120 秒]指定的时间点截取高清画面。
```

### 4.2 图片生成与编辑

当前白名单包括：

| 模式 | 真实插件 | 定位 |
|---|---|---|
| 默认谷歌生图 | NanoBananaGen2 | 默认模式，支持生成、编辑和多图合成 |
| GPT 生图 | GPTImageGen | 独立的 OpenAI/GPT 图像模式 |
| ZImage | ZImageTurboGen | 支持生成、编辑、多图合成与负面提示词 |
| 豆包 | DoubaoGen | 支持生成、编辑、多图合成与多种分辨率 |

旧的 GeminiImageGen 不属于本次实验能力树。

图片 URL 使用统一语义输入，不要求主模型记忆插件字段：

```text
[https://example.com/image.png]
[file:///C:/images/source.png]
```

确定性模式：

- 没有图片 URL：生成；
- 一张图片 URL：编辑；
- 多张图片 URL：多图合成。

JEV 内部使用统一图片中间表示，再由适配逻辑转换为目标插件所需字段。

## 5. 调用协议

基础格式：

```text
<<<[TOOL_REQUEST]>>>
maid:「始」Nova「末」
JEV:「始」请使用 {能力} 中的 '可选工具'，围绕【主要内容】，并参考[可选约束]完成任务。「末」
<<<[END_TOOL_REQUEST]>>>
```

一个 JEV 块当前只允许一个能力目录和一个动作。

这是实验阶段的主动限制，用于避免：

- 不同目录间参数语义冲突；
- 多个主要内容之间关系不明确；
- 一个虚拟调用展开过多真实工具；
- 错误处理与结果归属复杂化；
- Jev 决策状态迅速膨胀。

显式选择多个同目录搜索工具仍然受到实验配置中的最大展开数量限制。

## 7. 当前实现结构

### 7.1 核心规划器

`modules/jevToolCallExp.js`

职责：

- 读取实验能力配置；
- 解析自然语言中的语义锚点；
- 解析显式工具选择；
- 应用默认工具；
- 应用确定性模板；
- 识别图片 URL；
- 推断生成、编辑和合成模式；
- 提取年份、地区、时间范围和截图时间；
- 在必要时请求 Jev；
- 产出一个或多个真实工具调用计划。

规划器不直接执行插件。

### 7.2 实验能力配置

`ToolConfigs/jev_tool_call_exp.json`

当前采用硬编码 JSON，原因是：

- 功能仍处于快速试验阶段；
- schema 尚未稳定；
- 能力边界可能频繁变化；
- 暂时不值得接入完整管理面板生态；
- 后续可能进行整体重写；
- 显式配置文件比自动扫描 manifest 更易审计。

该文件不是稳定公共配置协议。

### 7.3 主模型可见提示词

`TVStxt/JevToolCall.txt`

该文件面向主模型，只描述：

- 可用能力；
- 极简调用方法；
- 标记含义；
- 完整自然语言示例。

它不应重新复制插件的完整参数文档，否则会违背实验目的。

### 7.4 Jev 决策词

`TVStxt/JevToolCallDecision.txt`

该文件只保存实际传给 Jev 的简短决策指令。

当前包括：

- AnySearch 子领域选择；
- 图片尺寸选择。

决策词应保持简单、明确和有限，不应扩张成完整工具说明。

### 7.5 工具调用解析

`modules/vcpLoop/toolCallParser.js`

解析器将顶层 `JEV:` 字段识别为虚拟工具调用。

JEV 不需要真实插件 manifest。

### 7.6 工具执行展开

`modules/vcpLoop/toolExecutor.js`

执行器在真实插件存在性检查之前识别 JEV 虚拟调用，由规划器展开成真实工具调用，然后递归进入原有执行链。

## 8. Jev 失败与降级策略

Jev 不是整个调用路径的强依赖。

以下情况应安全降级：

- 未配置 API Key；
- Jev 服务不可用；
- 请求超时；
- 返回结构无效；
- 选择项不在白名单中；
- 置信度低于门槛；
- 决策过程中发生异常。

降级原则：

- AnySearch 回退通用搜索；
- 图片尺寸不注入猜测值，由插件默认值处理；
- 不因为 Jev 失败而生成任意参数；
- 不因为 Jev 失败而绕过工具安全机制；
- 不把 Jev 错误扩散为服务器级故障。

---

## 9. 安全边界

### 9.1 Jev 不拥有执行权

Jev 只能在候选集合中选择。

它不能：

- 指定任意插件；
- 生成任意插件名；
- 生成 shell 命令；
- 修改能力配置；
- 调用能力树外工具；
- 注入任意参数键；
- 绕过人工审核；
- 绕过权限验证；
- 绕过工具记录。

### 9.2 标记内容视为不可信数据

`【】` 与 `[]` 中内容可能包含提示注入文本。

规划器和 Jev 决策指令必须将其视为待分类数据，而不是系统命令。

### 9.3 配置默认拒绝

只有明确写入实验能力 JSON 的插件和参数模板才允许由 JEV 调用。

新增插件不会自动进入能力树。

### 9.4 真实执行继续受 PluginManager 保护

JEV 展开的调用必须继续经过 PluginManager 和 ToolExecutor 的既有安全流程。

---

## 10. 已知限制

当前实现存在但不限于以下限制：

1. 自然语言解析仍主要依赖人工标记；
2. 一个 JEV 块只支持一个能力目录；
3. 不支持任意工具；
4. 不支持完整 AnySearch 动态 schema；
5. 不会自动请求 AnySearch `get_sub_domains` 后进行第二阶段调用；
6. 不支持根据第一次工具结果继续自主规划；
7. 图片尺寸能力表可能随插件更新而过期；
8. 插件是否在线仍由运行时决定；
9. SerpSearch 可能来自分布式节点或外部注册；
10. 未对所有语言和标点变体进行覆盖；
11. 不保证模型始终正确输出语义标记；
12. 不保证多个工具结果的合并体验稳定；
13. 尚未接入管理面板；
14. 尚未建立正式版本迁移机制；
15. 尚未承诺配置 schema；
16. 尚未进行大规模真实会话评测；
17. 当前测试主要验证离线规划与模板映射；
18. 真实外部 API 的可用性不在单元测试保证范围内。

可能研究：

- 文件搜索；
- 文件读取；
- 网页提取；
- 视频生成；
- 音频生成；
- 开发工具；
- 知识库检索；
- 桌面自动化。

任何扩展都应先建立独立白名单和安全模板。

### 12.2 动态能力编译

未来可能从 manifest、人工覆盖配置和运行时状态编译 JEV 可见能力树，但不会简单地把完整插件注册表直接暴露给 Jev。

### 12.3 多阶段计划

可能探索：

```text
能力目录选择
    ↓
工具集合选择
    ↓
安全模板选择
    ↓
参数有限决策
    ↓
结果驱动的下一步计划
```

但首要目标仍是保持系统简单，避免过早退化成不可控的递归 Agent。

### 12.4 评测体系

未来应建立：

- 调用成功率；
- 参数合法率；
- 插件选择准确率；
- Jev 实际触发比例；
- 平均 Jev 请求次数；
- 提示词节省量；
- 端到端延迟；
- 调用成本；
- 低置信度回退率；
- 与传统工具提示词调用的对照实验。

### 12.5 逐步替代现有工具栈

如果长期评测证明该路线有效，可能采用以下迁移策略：

1. 保留传统工具栈作为回退；
2. 在少量低风险能力中默认启用 JEV；
3. 扩大模板覆盖率；
4. 减少主模型可见的完整插件说明；
5. 将传统工具调用转为高级或兼容模式；
6. 最终以语义能力入口作为主要工具调用范式。

这不是当前承诺，而是本实验希望验证的长期方向。

## 13. 非兼容性与重构政策

本实验没有稳定性承诺。

未来版本可能直接改变：

- 标记语法；
- 顶层字段名；
- JSON 文件位置；
- JSON schema；
- 能力目录名称；
- 工具别名；
- 默认工具；
- 尺寸候选；
- Jev 问题结构；
- 置信度阈值；
- 规划器导出接口；
- ToolExecutor 接入方式；
- 提示词文件结构；
- 单块多动作限制；
- 与 PluginManager 的集成边界。

实验阶段允许删除旧接口，而不提供迁移适配层。

如果功能进入稳定阶段，应另行制定：

- 版本号；
- schema 迁移；
- 兼容周期；
- 废弃策略；
- 管理面板支持；
- 可观测性规范；
- 正式安全审计。

## 14. 结论

JEV 语义工具调用实验的目标不是给现有工具调用增加另一层复杂提示词，而是从根本上减少主模型必须掌握的插件协议知识。

其基本哲学是：

```text
自然语言保持意图连续性，
语义标记提供可靠边界，
模板处理确定性工作，
Jev 处理有限模糊决策，
现有执行链负责安全执行。
```

这是一个高风险、高变化、未稳定的实验功能。

它可能失败，可能被推翻，也可能经历完全不兼容的激进重构。

但如果研究结果成立，它有潜力显著减少提示词体积、降低工具参数幻觉、提高插件生态扩展能力，并逐渐成为 VCPToolBox 下一代工具调用栈的核心基础。
