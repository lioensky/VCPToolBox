## 二、五大最终工程合龙任务

### 任务 1（最核心）：拆除过严门控，100% 复用现役「1% 变动累积代际迭代」管线！
**现状严重缺陷**：
在生产线上，RiverMemo 图资产采用 **1% Tag 变动累积触发重训**（见 `knowledge_runtime.rs:2162` 的 `memo_training_tag_count / kbm_memo_changed_tags` 与 `rivermemo_topology_v3.rs:1128` 的 `validate_artifact_with_connection`）。日常每写入 1 篇日记，SQLite 触发器会递增 `database_generation` 与 `kbm_runtime_meta['memo_tag_facts']`，但在累积变动未达 1% 前，不会重新运行 `memo_geometry` 或 `rebuild_memo_artifact`，旧 `artifact_sig` 继续合法服役！
然而当前 `warped_tag_field.rs:50-97` 的 `metadata_identity` 却写了三道**与 1% 累积管线正面冲突的过严相等门控**：
1. `source_generation != current_database_generation`（写 1 篇日记即判死刑）；
2. `kbm_runtime_meta[key] != d.dependency_version`（写 1 篇日记导致 `memo_tag_facts` +1 即判死刑）；
3. `tagmemo_artifacts.graph_generation != format!("facts:{}", current_memo_tag_facts)`（未重算几何期间 `facts` 已前移，导致连按需构建都直接报错失败！）；
4. 此外 `TagIndexDeltaTask`（`src/lib.rs:956`）每次小批量增量 Tag 写入都会调 `memo_runtime.clear()` 清空 `warped_fields`，若后续懒加载因上述门控无法重建，双曲场将永久掉线！

**施工改造铁律（与 `NativeArtifact` 100% 同生共死）**：
1. **将 `WarpedTagField` 的构建与存活契约完全绑定到目标 `artifact_sig`（复用 `validate_artifact_with_connection` 规则）**：
   - **存活校验（`WarpedTagField::current`）**：只要当前连接对应的数据库身份一致，且目标 `artifact_sig` 通过 `validate_artifact_with_connection(connection, artifact_sig)`（即 `status = 'ready'`、覆盖索引校验通过、依赖齐全且 `CAST(m.value AS INTEGER) >= CAST(d.dependency_version AS INTEGER)` 未发生回滚），该 `artifact_sig` 绑定的 `WarpedTagField` **即 100% 持续有效**！不再要求 `database_generation` 或实时 `memo_tag_facts` 与发布瞬间严格相等，查询热路径也不再每请求校验 `epa_basis_cache` 相等而误杀增量期请求（`tagRoutingCheckMs` 压至 `< 0.05 ms`）！
   - **构建取数（`WarpedTagField::build`）**：构建针对指定 `artifact_sig` 的双曲场时，读取该 `artifact_sig` 在 `kbm_artifact_dependencies` 中记录的基线依赖（或最新 `status='ready'` 的同 `model_sig` `unified_geometry` 及其对应的 `tag_intrinsic_residuals` / `ArtifactPayload.raw_residuals` 与 `epa_basis_cache.mean`），**严禁因为 `kbm_runtime_meta['memo_tag_facts']` 在 1% 累积窗口内已经前移而拒绝构建**！
   - **增量窗口期容错**：
     - 在 `TagIndexDeltaTask`（`src/lib.rs:956`）中，核实小增量行为：即使 `memo_runtime` 被清空或保留，下一次 `run_memo_pipeline` 只要传入的 `artifact_sig` 仍合法，就能从持久化双曲快照（见任务 2）在毫秒内无损恢复，绝不在 1% 累积窗口内退回余弦！
     - 在 Stage-2 精排 SQL 读取 `SELECT vector FROM tags WHERE id=?1` 时：若个别 Tag 在 1% 累积窗口内被删除（返回 `None`），仅跳过该单个候选（如同已排除节点），绝不中断整次查询；仅当返回的 BLOB 字节损坏/NaN/零向量时报错或安全拒绝。
   - **代际推进换代**：当累积变动达到 1% 触发新一轮 `rebuild_memo_artifact` 生成新 `artifact_sig'` 时，新场随新 `artifact_sig'` 构建并原子替换旧场！

### 任务 2：补齐二进制快照持久化（`VCPWF001`）与 `run_memo_pipeline` 冷启动单飞加载
**施工要求**：
1. **紧凑二进制快照格式（`VCPWF001` + Header + Payload + `CRC32`）**：
   - 为 `WarpedFieldIndex` 与 `WarpedTagField` 实现确定性二进制序列化与零信任校验反序列化（校验 Magic、长度、维度、`artifact_sig`、`preset`、CSR 边界、位平面掩码及整包 `CRC32`；~39MB 快照加载耗时 `< 50 ms`）。
   - 快照作为受控派生旁路文件存放于数据库同目录（命名规范与 `.vec` 旁路资产一致，通过 `CheckpointStaging` 临时文件 + `sync_index_file` + `publish_index_file` 原子落盘，并在旧 `artifact_sig` 被 `NativeMemoArtifactPruneTask` 清理时同步清理对应旁路 `.vcpwf` 文件，防止磁盘泄漏！）。
2. **`run_memo_pipeline` 冷命中单飞自动恢复/构建（消灭重启退回余弦！）**：
   - 当 `run_memo_pipeline` 收到 `tagRoutingMode == "warped_ags"` 且内存 `MemoRuntime::warped_fields` 尚未加载对应 `(artifact_sig, preset)` 时，通过 `warped_cold_load: Mutex<()>` 单飞锁：
     - ① 优先尝试打开并校验同 `artifact_sig` 的 `.vcpwf` 快照文件秒级恢复并注册进 `MemoRuntime`；
     - ② 若快照不存在或校验不匹配，则在当前只读事务上直接流式执行 `WarpedTagField::build`、原子落盘 `.vcpwf` 快照并注册进 `MemoRuntime`；
     - ③ 仅当数据库中连基础 `unified_geometry` / `epa_basis_cache` 尚未初始化时，才平滑回退 `"cosine"` 并在 `diagnostics.tagRouting.fallbackReason` 中明确标注原因。
