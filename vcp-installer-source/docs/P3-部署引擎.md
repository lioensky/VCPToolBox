## 一、安装流程调度器

`src/installer/mod.rs` 中的 `run_installation()` 是总调度器，按顺序执行各步骤（11步），通过 mpsc::Sender<ProgressEvent> 向 TUI 上报进度。

### install_dir 源头绝对化（v18.12 新增）

```rust
// run_installation() 函数最开头
install_dir = to_command_abs_path(config.install_path.clone());
```

**教训**：headless 传相对路径时，runtimes_dir/node_dir/npm bat 路径全相对，bat 在 cwd=组件目录 下多解析一层失败。必须在源头绝对化，防止相对路径 bug 传播到整条链路。

### 三层韧性链路

```
遇到断流 → 同站重试 2 次（每站最多 3 次尝试）
        → 失败换 [preferred_github] 备用站
        → 备用站全试过 → 切换 Tarball 模式兜底
```

**git_exhausted 状态共享**：某组件 git 全失败后，后续组件跳过 git 直接 Tarball（省 ~15 分钟）。

## 三、git clone + 看门狗 + 多镜像轮换（git_ops.rs）

### 3.1 看门狗保护

- **超时**：90 秒活动看门狗（stream_util.rs）
- **实现**：非阻塞轮询 + 90 秒无活动 taskkill /T /F 杀进程树
- **镜像拼接**：使用优选镜像站前缀替换 github.com

### 3.2 git_init_from_remote 多镜像轮换（Plan B，运行调试03 新增）

```rust
// git_ops.rs: git_init_from_remote()
// 签名：base_repo_url: &str + candidate_prefixes: &[String]
// 逻辑：按候选镜像列表顺序轮换，每站 3 次重试（含超时保护），某站成功即停止
for prefix in candidate_prefixes {
    let site_url = apply_mirror(base_repo_url, prefix);
    set_origin(site_url);          // remote set-url
    for attempt in 1..=3 {
        if fetch_depth1(site_url) { return Ok(()) }  // 成功
    }
    // 本站 3 次全失败 → 换下一站
}
bail!("所有镜像站均失败");
```

**效果**：首镜像 429/断网时，自动切换备用站，不再单点失败。

### 3.3 tarball 模式 git 分支统一（v18.10）

```rust
// git_init_from_remote() 两处修复
// 1. git init -b main（而非默认 master）
// 2. git branch --set-upstream-to=origin/main main
```

**原因**：tarball 模式 `.git` 分支名是 `master`（git init 默认），缺少 `branch.main.remote` + `branch.main.merge` 配置，`git pull` 会报 "no tracking information"。

## 四、npm install + allow-scripts 四阶段（npm_ops.rs）

- 使用 Portable Node.js
- 可选 npm 镜像（淘宝源）
- **Node.js 24+ allow-scripts 处理**：
  - Phase1: `npm approve-scripts --allow-scripts-pending`（列出挂起包）
  - Phase2: 逐个批准每个包 `npm approve-scripts <pkg>@<version>`
  - Phase3: `npm rebuild`（触发已批准包的 install scripts 执行）
  - Phase4: 验证原生模块 .node 产物是否生成

### to_command_abs_path（v18.12 新增）

```rust
// npm_ops.rs: to_command_abs_path()
// 1. 已是绝对路径 → 直接返回（GUI 场景幂等 no-op）
// 2. 相对路径 → current_dir().join(p).canonicalize()
// 3. 剥离 \\?\ 长路径前缀 (strip_windows_long_path_prefix)
// 4. canonicalize 失败 → 仅 join 保留绝对路径
```

**教训**：canonicalize 在 Windows 盘符路径返回 `\\?\D:\...`（4 字符前缀），cmd/bat 不识别该前缀 → bat 内报"找不到路径"。必须剥离。

## 五、pip install（pip_ops.rs）

- **pip 源策略**：显式指定 `-i https://pypi.org/simple/`，绕过系统 pip.ini
- **ensurepip**：优先使用内置 ensurepip（零网络依赖）

## 十、stream_util 子进程输出标准（stream_util.rs）

> 强制标准，勿再手写管道处理

### 三机制统一

```rust
// 1. 双线程并发读 + mpsc 回传 (防 4KB 管道死锁丢输出)
// 2. 字节级心跳 (每读到非空块发 Heartbeat)
// 3. 90 秒活动看门狗 (pump_child_output)
//    90 秒无任何活动 → taskkill /T /F 杀进程树 → 返回 false 触发重试
// 4. \r 规范化 normalize_cr
//    把 git 进度条压成最终态，防 TUI 假进度
```

### 看门狗策略（按工具区分）

| 工具 | 策略 | 理由 |
|------|------|------|
| git | `Always` | 全程几乎都在等网络，90 秒无字节基本断定挂死 |
| npm | `UntilMarker("added ")` | 见 `added N packages` 后解除，防误杀本地编译（2-5 分钟静默） |
| pip | `UntilMarker("Installing collected packages")` | 进入安装阶段后解除 |

### 核心函数

```rust
pub fn normalize_cr(line: &str) -> String;
pub fn spawn_pipe_reader<R>(...) -> ...;
pub fn pump_child_output(...) -> bool;
pub fn pump_child_output_with_bucket(...) -> ...;
pub fn parse_git_progress(msg: &str) -> Option<(String, u32)>;
pub fn translate_git_progress(phase: &str, pct: u32) -> String;
```

### 拔线测试验证

- 拔线 ≠ VPN 关闭（TCP 静默重传不产生错误码）
- 90 秒看门狗 taskkill /T /F 杀进程树
- 全程 9 次触发看门狗，每次 ~90 秒内 kill 后重试
- 20 分 10 秒跑完 9 阶段，零卡死

## 十一、electron-rebuild 原生模块自动重建（electron_rebuild.rs，v18.11+ 新增）

```rust
// electron_rebuild.rs
pub fn scan_rebuildable_modules(...) -> ...;
pub fn rebuild_modules(...) -> ...;
```

**触发时机**：安装流程第 09 步（Stage::Scripts，启动脚本生成后）

**扫描逻辑**：
- node_modules 下含 binding.gyp 的模块
- 排除 electron-edge-js
- 自动识别出 better-sqlite3/hnswlib-node/node-pty 三个

**重建命令**：
```
node node_modules/@electron/rebuild/lib/cli.js -f -o <模块列表>
```

**流式读取**：stream_util 双线程并发读 + 300 秒看门狗 + WatchdogPolicy::Always

**失败策略**：不阻断安装（仅警告 + 提示手动命令），与 npm install 失败哲学一致

**验证标志**：`build/Release/.forge-meta = x64--145`（与 Electron 41 ABI 匹配）

### electron-edge-js 特殊处理（勿误伤）

- .NET CoreCLR 嵌入模块，本用预编译二进制
- electron-rebuild 误对其跑 node-gyp 会导致 edge_nativeclr 编译失败（缺 MSCOREE.lib）
- edge.js 加载逻辑会自动回退到 edge_coreclr.node，不影响运行
- **结论：跳过它**

### 关键 bug 修复

- better-sqlite3 ABI 不匹配（VCPChat UI 不显示）：Electron 41 ABI 145 vs Node 24 ABI 137
- 0xC0000409 闪退：run_sync_step 在 async 上下文阻塞 → 改用 run_blocking_step_with_log（spawn_blocking）
